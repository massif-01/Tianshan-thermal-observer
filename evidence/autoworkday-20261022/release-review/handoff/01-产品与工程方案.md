# TTO自动模拟工作日：产品与工程方案

## 1. 产品安排：机器执行，人不用陪跑

原计划的24小时是软件运行上限，包含空闲、夜间、任务回落，不要求连续有人使用。2小时是同一运行会话中的健康检查点，不是两小时人工值班，更不是必须由用户再工作22小时。

用户提出的自动模拟可以作为一个新使用方式：程序通过已有模型API发起真实请求，机器产生真实功耗和热响应，observe持续记录。模拟的是请求节奏，不是伪造温度/功率，也不宣称精准复刻用户真实一天。

用户只需一次确认可用设备、观察窗口、自动请求上限及暂停方式；需要时处理已有访问认证。开始后无需不断发消息、按计时点操作、读温度或守到结束。不要求YET、录像、声学仪器或Web UI完成。

24小时仍是本轮建议上限，不是研究必须值；用户允许更短窗口时，预先生成对应短计划并标明未覆盖项目，不能拉长实测补足。长空闲可以验证观察器运行与恢复，但不能代替工作负载覆盖。

## 2. 一个明确的新建议：同一24小时内，有工作也有休息

以下比例是本轮新拟定的实验模板，不是从用户历史工作量统计得到，不是已授权现场日程。相对时间从观察进程正式开始计算，不含安装。

|相对时间|自动行为|目的|
|---|---|---|
|00:00—02:00|观察器记录背景，不主动发请求；用户可完全不操作|核对目标运行、数据、资源与存储；2小时检查由本地程序执行并保存|
|02:00—06:00|稀疏单路问答，完整结束后间隔约2—8分钟|模拟偶尔提问和长短不等的思考间隔|
|06:00—08:00|每组约4—8条串行请求，组内有短等待，组间约8—20分钟|模拟一阵连续讨论、随后停下|
|08:00—09:00|少量批处理块，例如6、9、5分钟的发起窗口，中间保留空闲|覆盖持续加热和结束回落，不长时间无间断压测|
|09:00—10:00|不发新增请求|完整保留回落|
|10:00—18:00|不发新增请求，不关闭或重载模型服务|模拟长休息/夜间，观察器持续运行；不是让主机睡眠|
|18:00—23:30|不等间隔混合前面几类节奏，不按固定一分钟机械重复|检验长时间运行后再次工作与不同热前史|
|23:30—24:00|不再发新增请求，保留回落和成熟标签，按期结束|不以最后一批请求截断所有未来标签|

首轮建议单客户端、一个已确认驻留模型；不自动加2/4并发，不切换模组、模型、功耗或风扇策略。不同并发仍是未来可选覆盖，本轮不是验证所有工况。

请求输入采用准备好的非敏感任务集合，例如问答、摘要、改写、代码解释。不调用模型生成测试脚本再执行；只消费响应内容。不同任务可自然产生不同响应长度，不能许诺固定3秒/5秒完成。沿用已接受的每请求输出上限256 token、30秒协议预算及流式结束核对；任何不兼容须在新profile中明确提出，不暗改旧合同。

新增的建议总量限制：最多600次提交，包含失败/取消的提交；单路已提交请求的累计客户端在途时间最多5小时。这是工程预算，不是GPU忙碌时长，也不是建议必须跑满。每个工作块有发起窗口与请求数上限，全局预算更严格时优先停止后续提交。剩余时间只读观察。不能补发错过的请求来追赶进度。

间隔可用固定种子的伪随机数事先生成并存为冻结计划，实际提交/结束时刻另记。计划发生变化、暂停或未执行都写明，不能把计划时刻当成真实请求时刻。不得根据模型误差或预测输赢临时调整工作量。

## 3. 工程实现：保持一个观察器，增加一个有限任务执行器

### 3.1 目前已经有什么

observe.2是只读进程，含唯一collector、quality、冻结观察器、真实预测发布与成熟评分；它不构造Requester。04线有请求事件适配、旧Requester及有界补充的准备，但现有补充计划只有约25分钟上限，并未具备22小时自动工作日能力。不能把这些材料拼接后宣称新功能已经实现。

### 3.2 本次选择的结构

优先保留observe.2已封存wheel不变。在同一设备上，由一个独立的轻量场景驱动器复用已有Requester和事件Adapter，仅发起批准的本地模型API请求。它不再采集风扇/TJ/功率，也不再创建ThermalObserver。所需当前测量/保护上下文从唯一观察器的现有只读产物取得，核对会话/身份/时间，不用新的轮询补齐。

场景驱动器的停止、资源与事件单独记录；观察器原8%/128MiB等规则不变。记录驱动器本身开销和同机总干扰，不把它挪出观察进程后就宣布所有开销不存在。

新驱动器和自动检查/监督可合并为一个小程序，不建设通用工作流平台。按已有安装方式在获准主机运行；启动后由本地时钟与进程负责，不要求Codex对话保持22小时在线，也不要求用户电脑浏览器一直开着。实际运行主机/服务生命周期要在操作卡写明，不能依赖会被关闭的交互终端。

如现有只读产物不能提供所需保护状态或进程健康证据，测试线只补必要的只读接口/心跳；确需修改候选时用新版本，不热改observe.2。不得为了实现分离而复制quality、估计器或另造第二collector。

### 3.3 与旧合同的替代关系

旧04说明将主动补充规定为先停止observe、再用带collector的execute。本方案为新批准的自动工作日profile前向替代这一条：同一observe会话持续运行，独立执行器只负责请求。旧execute本身不变；不得在observe旁直接启动旧execute，否则会重复采集/争锁。

observe的只读许可仍不允许其发请求。新请求执行器持独立、明确绑定同一设备/会话及计划的负载许可；批准可一次覆盖整窗，不要求每个请求/工作块再次询问。原只读许可不能被修改成仿佛一直包含主动负载。

### 3.4 2小时检查与主动停止

2小时自动检查复用既有资源、日志、身份、状态/覆盖、磁盘回执。软件检查通过和主动请求条件通过分别记录。模型预测误差大、未胜B0不是硬件危险；当前可验证的温度/保护、设备身份与请求结束条件才用于既定主动安全检查。不可把普通fan缺口改成有效，也不能把有限预测当作真实保护信号。

沿用已经接受的主动请求安全/暂停/恢复/停止逻辑，核对它与只读状态接口的映射。不得为让模拟跑起来静默去掉检查、放宽2.5秒TTL或5秒确认；若旧gate还错误依赖本profile没有的仪表/模型能力，明确列出最小语义调整和测试，在一次集成审阅中说明，不使用旧override。

没有足够可靠的主动条件，就不启动/暂停新请求；按已接受的有限等待规则结束自动负载，保留原因，不反复自动重试。观察器自身条件允许时可继续至本轮期限。这应报告为“观察继续、模拟未完成”，不能叫工作日负载通过。

观察器退出、失去会话关联、关键安全信息不可用、明确guard/fault或用户STOP等，执行器停止后续请求；正常结束允许在途请求有界自然收尾。超时/不完整SSE/未知结束停止后续提交，并保留服务端结束未知；客户端断开不等于GPU已经停止。仅清理自己创建的进程，不重启模型/源服务，不杀用户业务。

全局时限由本地单调时钟执行，不因暂停延长。每个阶段至少为已有单请求预算和自然收尾留足空间；最后30分钟仅回落，不在尾部塞入新请求。采集和归档都属于同一批准窗口和已设磁盘预算，不等待聊天回复才能结束。

用户要用机器时可显式暂停模拟，观察不中断；恢复必须仍在原许可和预算内。不要仅凭本执行器的“在途=0”就猜整机无人工作。首轮以预先批准的设备使用窗口避免冲突；未知其他负载如实记为未知。

## 4. 证据含义：真实热数据，人工安排的请求节奏

源类型写为“真实设备 + 自动构造工作负载”，不是自然用户使用，也不是合成传感器数据。可以验证长窗运行、这些节奏下的热响应和冻结预测；不能据此声称真实用户全天分布、跨硬件泛化或控制收益已经证明。

模型只能消费当时已有的测量，不读取驱动器未来排程、随机种子或未来请求内容。计划供执行与事后分析，不能作为G2未来输入。保持相同5秒起点、15/45/90秒与成熟评分合同，不靠夜间大量平稳点稀释错误；分别报告背景、稀疏、连续、批处理、回落及恢复的覆盖和误差，并保留总体分数。

冻结G2与原参照不重训、不热切。当前24小时是一个连续热过程，不把每条请求或每个小时冒称独立设备/独立实验。新候选校准另行安排，不回写本轮已发布预测或旧成绩。

## 5. 人与三个对话的分工

用户：一次确认范围与开始，之后无需陪跑；需要时能暂停/停止，结束后看报告。

实际安装与测试：唯一总控，负责与observe.2的只读接口、自动健康检查、进程生命周期、部署准备和汇总；不同时另发请求。

模型推理监控：负责薄的场景驱动器、请求集合、节奏/全局预算及真实事件，未来是唯一请求执行方。任务启动后本地程序计时执行，不依赖对话在线。

灰箱辨识与对照实验：不新增模型研发；确认数据角色/不可偷看未来计划，结束后评价冻结成果及具体校准需求。

## 6. 本轮完成线

交可运行离线候选、冻结计划、局部差异、必要联合验证、一页无人值守操作卡；不是只给空计划。只做有限的自建服务/虚拟时钟验证，覆盖单collector/单Requester、无人确认2小时检查、间歇与长休息、暂停/STOP、观察器退出、未知请求结束、预算/期限、归档身份及未来计划不可入模型。长虚拟时间不得改现场代码的真实时钟。

不用重新跑86400条O1实验、旧模型拟合、全部历史回归或CPU循环。若复用接口不变，不重新发行observe.2。核对新连接后即可申请一次完整现场窗口；不增设连续多轮60秒、也不要求用户先手工工作若干小时。
