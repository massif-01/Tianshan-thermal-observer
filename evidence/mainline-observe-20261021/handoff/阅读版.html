# 决策冻结与旧任务替代

## 产品经理的决定

TTO本阶段交付目标改为：**已有模型可持续使用 + 小批真实观察 + 可重复生成与校准。** CPU先导只是一次没有获得当前增量证据的探索，不再占用主线进度。冻结已有结果不等于停止模型开发；新候选单独开发，旧结果不可覆盖。

## 工程执行规则

| 旧任务／规则 | 本轮处理 |
|---|---|
| CPU 200ms旁录、60秒能力循环、6孤立+6连续12请求 | 暂停；不再申请或自动执行。保留代码和失败记录，不做删除式cleanup。 |
| INPUT-MEAN/CORE活动→高功率先验 | 不进入主线默认预测。保留负结果；不调到在旧数据上赢为止。 |
| 普通原生CPU、GPU利用率／功率字段 | 继续原样记录。暂停专用CPU旁录不等于删除原遥测CPU字段。 |
| 为延续CPU旁录单独开发的诊断分层 | 不再作为独立CPU项目推进；通用故障隔离需要的部分转入持续观察版本。已有局部实现可复用，不重复造。 |
| 持续记录必须等模型tracking、5秒控制确认或负载许可 | 仅在新observe模式解除这种耦合；原始测量资格和既有execute安全要求不改。 |
| 2.5秒fan TTL／7.5秒temp TTL与原源新鲜度 | 本阶段保留；源到期是真实到期，继续记录不等于续龄或变正常。 |
| cpu.3单线程、同PID取证、I-02、准确停止时刻、唯一采集 | 接受并继承，不重复立项。不要直接把cpu.3的CPU实验入口改名就宣称持续版本完成。 |
| 每个小修都做一轮同样的60秒现场 | 取消为默认流程。一次集成交付后，按明确设备和窗口开展2小时起步/一天级只读观察。 |
| 风扇反馈周期性长延迟 | 保留为软件可靠性问题。允许有证据的最小修复候选；不强制先根治全部历史问题才可只读记录。 |
| 当前成果比TJ好 | 精确指：某次fixed-anchors共同集合中，G2-HOLD预测平均优于保持当前TJ的B0。不是已优于整套天山OS实际控制。 |
| 原模型文件内deployable=false | 不篡改成true。另建观察发行清单，明确仅经过何种只读运行验证；控制权限始终false。 |
| 新模型开发被“不重训”全面阻断 | 旧模型不重训覆盖；**允许新目录中的有限拟合／校准候选**，数据角色必须登记。 |
| Web UI旁路任务 | 不重做PRD、不把UI合入CPU修复；观察API与UI合同对齐，UI不增加源轮询。 |

## 用户工程事实与本轮约定

当前RM-01只有一个风扇；用户确认其有效工作区间内真实转速降低时噪声降低，没有需要本阶段专门研究的反向共振区。把降低不必要的高转速与频繁变化列为体验目标，不增加声学实验室前置。不把“转速翻倍噪声翻倍”写成普适公式，也不把PWM百分比直接写成RPM或分贝。

## 已开工任务如何接续

先读现有工作目录和回执，保留已完成通用修复，停止未完成的CPU特定扩展；不要reset、清理或重做已验收工作。已有通讯专项交回的成果由测试线查收；只有实际会影响持续观察的部分纳入。不自动重新联系第四个对话安排新大修。

## 权限与退出条件

本轮只开发和准备。新包不继承任何历史密码登录、设备安装、60秒或12请求授权。不得以用户支持小批试跑为由猜设备IP或自动登录。

之后批准小批现场窗口时，一次明确：设备列表、候选/模型身份、只读权限、最长时长、归档/回退。该窗口内按计划执行，不因每个正常恢复都请求再次批准。不包含风扇控制、刷板、模型自动热替换或新增人工压力负载。

# 产品与工程总体方案

## 1. 这次要交付的两个成果

### 产品经理视角

**成果A：冻结模型观察版。** 将已取得收益的G2保留下来，作为能在真实机器日常运行的观察能力。用户可以看到当前TJ、模型快慢状态、未来15/45/90秒条件预测及成熟后的误差；某一来源有缺口时不再整套退出。

**成果B：模型生成与校准工具。** 同一软件面对一份新的有效记录，可以生成该设备的候选、和旧版比较、说明是否适合替换。初版允许离线或周期执行与人工确认；后续再允许持续候选生成和受控自动启用，不能把状态更新冒称参数学习。

成果A无需等待成果B优化成功。成果B无需等待CPU先导、Web UI、外部探头或所有通讯缺口消失。

### 工程师视角

沿用G2拓扑、原生数据质量与已接受估计器。冻结原primary/spec/实现；构建新发行封套、新observe入口和可重复的工具接口。收集、估计、预测评分、训练候选、执行负载、控制风扇各自分工，不靠单一qualified字段决定全部生命周期。

## 2. 冻结的结果与没有证明的事

唯一fixed-anchors过程为 `5d5e5a4a-6081-49d8-a9be-5156d9ca2ab3`，field和modeling是同一个过程。45秒共同2649起点中：G2-HOLD MAE1.544°C，B0保持TJ为2.230°C，平均误差约低30.8%；但G2绝对误差P95=10.264°C、最大低估12.712°C，比B0对应9.600/11.782°C更差。A-roll MAE0.334°C使用未来真实输入；A-long MAE0.888°C也不是可提前知道负载的证明。[S1,S2]

**接受的产品定位：有实际研究依据的条件热观察/预测候选。** 不是已认证安全预测器、真实Ts测温、跨设备通用参数，也不是已经降低风扇转速或噪声。历史Y短问答有不胜B0的结果，一并保留。[S1,S6]

cpu.3在N305本次真实进程两个数值池均1线程，接收CPU在旁录前/中/后均值约2.98/3.93/3.14%，峰值5.89%，RSS峰值74.47MiB，支持继承该运行修复。周期性fan缺口仍存在，不能从此推断所有通讯已修复。[S3]

## 3. 软件职责整理：最小改动，不重写平台

建议模块边界：

```text
原生只读采集 → 原始日志与原始质量
                  ├→ 冻结G2状态估计 → 条件预测 → 成熟标签评分
                  ├→ 事件/健康/运行摘要 → Web UI或只读导出
                  └→ 显式选定的训练数据 → 新候选 → 比较/人工启用

独立实验执行器 ← 现场授权 + 真实设备保护/控制条件
天山OS原控制与保护 ← 保持原样；不接本阶段TTO写指令
```

- 原始日志先保存；估计器错误、晚到或暂不可用不能让其他原始数据自动丢失。
- 不新建第二个质量引擎或第二套HTTP/WS轮询。估计消费缓慢时使用有界队列/已落盘序列及明确落后标记；绝不能无界堆内存、静默跳样或通过更改源采样止损。
- 如为保留已验收状态语义需要维持串行调用，可用最小异常隔离及有界处理；是否另worker由实测必要性决定，不强制微服务/多进程。
- 普通fan过期只撤销该来源资格，按原估计器的短缺口/长缺口规则降级或停模型输出，原始TJ等仍记录。明确guard/fault也保留真实事件，可停止模型建议，但只读记录不因此变成控制动作。
- 原运行环境单线程规范与同PID回执作为每次实际run身份；不增加全机环境修改，不影响推理服务的线程设置。
- 新observe不创建Requester，不调用模型列表/推理API，不要求YET/CPU sidecar/实验actor ID。原execute入口及设备保护不因该拆分放宽。

## 4. 小批试跑建议（不是已经确定的设备数量）

建议首批**最多3台：当前参考机 + 两台同散热结构/同模组优先**。设备不足就先现有一台持续运行，不等待凑齐。型号不同的机器只在字段语义核对后加入单独配置组；原模型直接迁移仅作探索，不称已适配。

建议每台观察上限24小时。首台前2小时为运行健康检查点，通过后在同一已批准窗口内继续；再加入批准清单里的其他机器。一天仅是首轮观察预算，不是自动足够校准的数据量。默认业务照常、TTO不主动发负载。

这是**先安装成熟的观察能力，后以新数据推动校准**，不是把未验证模型交给风扇。真正落地时由用户确认设备与时段；本轮软件开发不等待这些信息补齐。

## 5. 模型开发为什么现在应重新启动

### 产品经理视角

冻结现有收益，解决“已经有一个有用模型却一直无法交付”；生成/校准解决“以后换硬件怎么办”。两者并行，而不是等所有场景完全准确才给用户用。

### 工程师视角

- 冻结θ的状态更新继续按原先验和E估计工作；E不是室温，不复制M24°C。
- 新生成候选可调整θ，但生成新model_id，不改primary原件。
- 初版复用既有G2辨识代码/损失/边界，封装流程，不另做模型族搜索。完整生成和以当前模型为起点的校准共用同一有限求解器。
- 新硬件可能需要新参数或新结构，但结构扩展必须由“输入已知仍有可重复动态残差”的证据触发，不现在一律加阶数。
- 学习优先后台或离线周期执行，不在1秒估计路径中做优化；不会因为训练失败停止观察。

## 6. 之后才做的两件事

**受控在线校准：** 有合格数据时自动生成候选、先用后续数据比较，再允许观察模型替换并可回退。是否递归逐点更新以后按数据价值/资源决定，初版不承诺每秒自学。

**实际风扇收益：** 明确有合法PWM映射和独立试验方案后，才在单台做实际控制对照。当前接受用户确认的转速—噪声方向，先以真实RPM/经核实PWM的相对趋势与听感评价；精确dB收益需要对应声学测量，不能拿影子建议代替已实现降噪。该阶段不要求先证明CPU先导或所有跨机型泛化。

# 给「灰箱辨识与对照实验」的执行指令

**本任务完整执行，不是只再看一次CPU背景片段。** 先读共同文件00、01、05、06。独立工作树，现场与Web UI生产文件不由本线改。

## 产品经理视角：交付什么

一份能直接交测试线的冻结观察模型包，以及一套实际可运行的生成／校准／比较工具。模型线不再等待CPU先导测试；也不要求每个新候选都胜出才算工具完成。

## 工程师视角：A1先封存可用基线（优先交给测试线）

1. 从当前已接受原件核对 `reference/frozen_model/` 的primary、observer-spec、observer实现SHA；保持字节。标签可称 `G2-FROZEN-RM01-v1`，这是本轮管理名，不冒充旧文件已含该版本。
2. 输出 `frozen-model-manifest.json`、简短model-card和运行接口说明：拟合数据L/M/S、适用输入/单位、先验、E与θ区别、15/45/90秒HOLD的条件假设、允许状态/失效原因、旧评分和不适用范围。
3. 不把primary/spec里的deployable=false改true；用另一个发行清单登记“只读试跑候选，控制写入false”。旧科学报告不能因发行而改标签。
4. 固定θ和原状态估计；B预测用同一当时TJ锚点、当时两rail、已知或声明的条件PWM、当时Ts/E。不得看将来的任务计划或A类未来真实功率。提供纯计算调用给测试线；方法名可适配现有工程，但不能复制另一套数学。
5. 优先实现生产形态的轻量预测封装（如果既有函数已具备就复用）：输入状态+观测截止+发布时刻，返回每个horizon数值或明确不可用原因。旧历史回放与新实时发布分开标注；不事后补发冒充实时。
6. 给出少量真实记录形成的跨端golden fixture与容差，覆盖正常、短缺口、长期失效、恢复、同run热历史与无未来泄漏。不要重算所有旧排名/42次拟合。
7. A1一旦完成即交测试线，不等待下面生成器全部完成；数据字段有变化以05为共同语义，不两边各写一个转换器。

## A2：实现模型生成与校准最小产品闭环

从现有第二轮辨识代码中复用真实fitting/data_views/scoring流程。交付逻辑功能（CLI命名沿项目常规即可）：

- `generate`：读取明确的设备配置和显式train/validation数据角色，运行已接受的G2有界拟合，保存新模型、输入范围、过程/求解状态和未验证项。
- `calibrate`：以指定旧模型为起点、只使用新增已批准的校准数据运行**同一套**有界求解流程，产生独立candidate。不是改E后称已完成θ自学习，也不是重训覆盖旧模型。
- `compare`：当前模型、候选、B0/B1和现成简单参照，在相同输入/状态初始化信息预算、共同起点及未来标签上比较；A与B分表，覆盖和拒绝原因单列。
- `register/activate/rollback`：实现模型包校验和版本选择的本地管理能力；首版默认只登记候选，启用要显式确认。此命令不触达任何风扇。运行中替换先按安全边界暂不热切：在观察会话边界切换，保留旧版本，保证可以回退。

### 有界算法要求

1. 初版只用当前G2，不扩G1/Ridge新搜索、Transformer或高阶结构；已有B0/B1/LP基线只复用。
2. 沿用已有物理可行参数边界与损失。完整生成最多既有六初值；校准最多六个预登记初值，其中一个为当前θ，余者来自既有固定种子。不要在看到验证分数后重选初值、损失或窗。

# 共用接口与评价合同（精简语义，不强制重写已有schema）

## 产品经理视角

同一份事实应当同时服务于观察、建模和UI，不因一个模块失败而消失。每个数字需回答：这是测量、估计还是预测？对应哪台设备和哪个时刻？现在能否信任？未来答案到了吗？

## 工程师视角：五类对象

### 1. 设备与会话

`device_id`、`thermal_config_id`、`observer_host_id`、`session_id/run_id`、`boot/clock_domain`、软件/模型/spec身份、来源适配器及单位。thermal_config包括模组SKU/SoC、散热结构/材料版本、单风扇身份、原功耗与控制配置已知部分；未知留null，不把T234和T4000/T5000当同类字段。

不同设备不得共享运行中的Ts/E、状态缓存或标定值；换模型/重启/硬件配置变化明确建新会话或事件。首批可先采用每观察主机一个目标的已有拓扑，不扩多租户。

### 2. 观测与质量

每字段保留原值、单位、原ref/seq、观测/接收时刻、原始有效性、到期/明确失效、未知原因。成功PWM≠目标PWM≠RPM，零RPM没有可靠源证明时不可当真实停转。各rail不任意求和为整机热功率；现有CPU/GPU值来自Jetson而非N305。

继续记录与当前有效是两个概念；明确失效不回找旧valid。字段失效可使特定模型不可用，但不停止不相关字段原样写出。保留原质量输出，不用新interface改旧数据合同。

### 3. 状态和条件预测

状态：Tf、Ts、E、phase、内部不确定性/假设、状态所观察到的原ref和时刻。Ts是潜在慢态、E是等效边界，不作为实测结构/室温；不确定性不是已校准95%概率。

预测每项至少包括：
- 唯一prediction_id与device/config/run/model/spec；
- 原TJ起点ref/measurement_time、状态observed_through、真实`issued_at`及同一可关联时钟域；
- `horizon_s`=15/45/90，明确目标时刻的anchor；
- value或null+reason，方法G2-HOLD/B0/B1、条件功率/PWM假设、起点状态分层；
- `publication_mode=live|replay`，是否晚发，不能追填为live。

**新实时语义建议：以原TJ决策起点的接收时刻为anchor，target=anchor+h；issued_at只标真实生成/发布时刻，并报告有效剩余提前量。** 超过目标后生成的记录不算实时预测。复用旧评价时间轴时必须有单独标签，不与新时间口径混合排行。模型线/测试线冻结一次映射，不逐run换定义。

所有方法同一发布时点、同一已到达信息预算。B0保持当时真实TJ；原天山OS45秒参考如已有可用只作独立条件参照，不自动叫B0或和不同horizon凑对照。

### 4. 成熟标签与评分

使用目标时刻之后最早的合格TJ，容差沿旧冻结规则2秒；保持真实arrival与原ref，无插值、不向前偷答案、不跨run/时钟域/硬件变化。原算法如不同，以旧spec复现结果单列；新live映射需明确版本。

到期才评分；提前结束或中间丢标签为缺失，不是零误差。误差定义为prediction−actual，低估=max(actual−prediction,0)。至少分时距报告MAE、bias、P95绝对误差、P95/最大低估、预测覆盖、标签覆盖和分母；同集合比较之外也报全量有效TJ分母，保留每设备/每run结果，不能用长背景遮盖转折。阶段标记只能事后分层，不能变成模型未来特征。

相邻秒、重叠45秒答案、同run多个阶段不是独立实验。缺事件时不猜工况；不以平均变好自动宣称真实控制改进。

### 5. 模型候选包

需有：新model_id；parent_model_id；θ与结构；数据角色与train/validation/future评估界线；设备配置/输入域；E/状态初始化策略；拟合尝试/时间/资源；比较结果；可用范围；已知限制；启用/拒绝/待确认理由；回退对象。

一次生成完成≠候选优于旧版≠已启用≠可控制。模板状态默认not_run，不允许填假通过。

## 生成／校准评价

旧数据全属已查看开发集合。完整新过程优先作为未来确认；不能把同一机器相邻秒随机拆成训练验证。可以在一个长观察窗内预先划出按时间先后的完整业务会话，前段校准后段确认；跨边界去掉最长horizon标签交叉。数据不足照实，软件仍应能交出候选/不充分原因，不要求先补所有工况。

# 集成验收、小批试跑与下一阶段

## 产品经理视角：不是“所有功能完美”，是“能稳定使用已有价值”

本阶段一次集成交付，不再反复将每项小修当新项目。小批试跑目的是验证可运行性、已冻结模型在真实使用中的价值和校准需求；不承诺一天就证明跨材料通用性。

|---|---|---|---|

| M1 可持续观察候选 | observe、实时B预测/成熟评分、保真日志/有限资源/回退 | 测试线整合模型接口 | M0；不等校准工具最终结果 |

## M1交付验收：四类真正的阻断

1. **事实错误：** 串设备/时间；把过期数变新；伪造PWM/RPM/先发预测；未来信息泄漏。
2. **越权或干扰：** observe发推理或写风扇；重复轮询造成额外负担；停其他业务；篡改原保护。
3. **不可运行：** 无真实入口/无法安装；模型错误让原始记录崩溃；内存/队列无界；磁盘无明确上限；STOP无法回收自己。
4. **交付不一致：** 实际安装不是审过的候选，模型/输入语义不匹配。

非阻断示例：一个设备暂未够校准数据；某horizon不胜B0；已知fan缺口且如实降级；无YET/RPM/jtop/业务事件；某张UI图尚未完成。非阻断不等于删除，进入问题清单并明确影响。

## 现场前唯一必要的用户信息

准备期不必提问；正式现场前一次性确认：具体设备列表/热配置、可用观察主机/源端点、允许的最长窗口、数据保管目录、是否只日常业务、谁可停止。密码/令牌不进包，凭据仍留安全本地方式；不自动发现机器或复制旧授权。

## 建议首批安排（须批准，不是事实）

- 默认最多3台，优先相同模组/散热版本；不同配置分组。只一台也可先开始。
- 每台最多24小时。第一台在原有日常运行中先看前2小时技术健康，若没有阻断就在同一授权内继续；同一批已批准的其余机器可接着部署，不逐台等待主审再批一次。
- 每设备保持自己的run/config/model身份。不同主机不能共享单调时钟或热状态；多台数据不池化成“一个更大实验”。
- 默认0个TTO Requester，用户日常业务不受TTO预测状态指挥。TTO自己的状态失效不暂停/终止用户现有工作。
- 不额外做CPU60秒，不要求YET/jtop或全部热平衡；正常恢复保留原样，不因为出现一次缺口重开run凑满。
- 24小时没有工作负载就报告观测内容不足；由推理线提出一个后续有界场景，不能自动延长、增压或补跑。

## 现场结果怎样决定后续

| 结果 | 下一步 |
|---|---|
| 软件稳定、模型有条件预测，部分工况平均有增益 | 保留已冻结版为观察稳定基线；用新数据推进候选校准 |
| 记录完整、但新设备模型有偏差 | 不停止全部观察；该配置标待校准，生成本机candidate，不称通用模型已有效 |
| 反馈反复失效，预测大部不可用但raw可信 | 保留日志；准确说模型验证不足，针对通讯问题处理；其余机器不自动一起判失败 |
| 软件越权、串机、记录不保真或资源不可控 | 停自己的候选并回退；问题解决前不扩机器 |
| 没有活动信号足够变化 | 不“学习”出假系数；保留旧模型或无模型，只建议最小有信息量的新过程 |

## 防止再次钻支线

每个新假设必须写清：解决哪个产品问题、现有最简单基线、什么结果值得继续、最多一次怎样的实验。如果没显示足以覆盖成本的增量，归档待新证据；不能改名后成为新的主线前置。

本阶段CPU逐核为paused，不是证明永久无效；无需为暂停再做完12请求。通信修复最多围绕已明确长延迟做有证据工作，不要求无缺口才能观察。Web UI不阻断观察版，模型生成不阻断冻结版试跑。

每个交付只汇报五项：用户获得什么；实际做到什么；证据；限制；下一步。少量已知非阻断问题随版本维护，不为“全绿”无限返修。

## 二、关于转速与噪声：不再泛化质疑用户的本机经验

### 产品经理判断

接受当前RM-01“减少不必要的高转速与调节，能降低本机风扇噪声/扰动”的设计方向。不要把购买声级计或排查未知共振作为当前只读试跑、生成校准甚至下一步控制方案设计的前提。

### 工程师表述

实际RPM下降与PWM建议下降不是同一个事实；首阶段风扇仍由天山OS控制，观察模型上线本身不会降低实际转速。此阶段报告预测/状态收益，不报告已实现降噪。未来控制试验在可比温度/性能下报告真实转速及停留时间、变动和听感；需要精确dB变化时再加相应测量。

不将“转速翻倍、噪声翻倍”当通用公式；声功率、声压、dB和主观响度不是同一个量。这里不开展声学新支线。

### 本轮外部查阅（与项目数据分开）

- Apple官方《Mac Studio (2023) - Tech Specs》，Acoustic Performance：ECMA-109条件下给指定M2 Ultra配置的idle/wireless web声功率级与操作位声压级；表内1.5 B、6 dB。https://support.apple.com/en-us/111835
- Apple官方《Mac Studio (2025) - Tech Specs》，同节给指定M3 Ultra配置对应1.6 B、7 dB。https://support.apple.com/en-us/122211

2026-10-21查阅。这两页没有给RPM→噪声的函数/倍数关系；这些不同产品的规定条件数字不能用于拟合RM-01，也不能拿跨年数值推断风扇速度规律。未找到足以支持“Apple发布了转速翻倍噪声翻倍定律”的官方材料。这个未找到不影响接受用户对自己机器的工程判断。

reference中旧文档可能含设备路径、旧命令、旧模式或“继续CPU测试”的历史段落。它们只作证据，优先级低于00和本轮专项指令。只读新试跑必须由测试线按明确清单取得当次授权，不根据历史批准自行访问。
