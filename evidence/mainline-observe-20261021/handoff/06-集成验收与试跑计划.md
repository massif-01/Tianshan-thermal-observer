# 集成验收、小批试跑与下一阶段

## 产品经理视角：不是“所有功能完美”，是“能稳定使用已有价值”

本阶段一次集成交付，不再反复将每项小修当新项目。小批试跑目的是验证可运行性、已冻结模型在真实使用中的价值和校准需求；不承诺一天就证明跨材料通用性。

## 里程碑与负责人

| 节点 | 实际交付 | 负责人 | 前置 |
|---|---|---|---|
| M0 结果固定/支线暂停 | model-card、原件SHA、限制、CPU归档状态 | 模型线；测试线同步 | 现有资料即可 |
| M1 可持续观察候选 | observe、实时B预测/成熟评分、保真日志/有限资源/回退 | 测试线整合模型接口 | M0；不等校准工具最终结果 |
| M2 一批真实机器观察 | 明确清单、1→最多3台、24h预算、每设备报告 | 测试线；推理线仅提供现有事件 | M1核验+用户批准设备/窗口 |
| M3 生成与校准工具 | generate/calibrate/compare/register及真实离线示例 | 模型线 | 现有数据可并行做，不等M2 |
| M4 真实新过程校准比较 | 新数据按时间划分、固定旧版/新候选比较、接受/拒绝 | 模型线与测试线 | M2有信息量的数据+M3 |
| M5 受控更新/后续控制 | 先观察模型候选管理；实际PWM收益另批准 | 后续独立任务 | 不要求CPU或所有材料研究通过 |

## M1交付验收：四类真正的阻断

1. **事实错误：** 串设备/时间；把过期数变新；伪造PWM/RPM/先发预测；未来信息泄漏。
2. **越权或干扰：** observe发推理或写风扇；重复轮询造成额外负担；停其他业务；篡改原保护。
3. **不可运行：** 无真实入口/无法安装；模型错误让原始记录崩溃；内存/队列无界；磁盘无明确上限；STOP无法回收自己。
4. **交付不一致：** 实际安装不是审过的候选，模型/输入语义不匹配。

非阻断示例：一个设备暂未够校准数据；某horizon不胜B0；已知fan缺口且如实降级；无YET/RPM/jtop/业务事件；某张UI图尚未完成。非阻断不等于删除，进入问题清单并明确影响。

## 现场前唯一必要的用户信息

准备期不必提问；正式现场前一次性确认：具体设备列表/热配置、可用观察主机/源端点、允许的最长窗口、数据保管目录、是否只日常业务、谁可停止。密码/令牌不进包，凭据仍留安全本地方式；不自动发现机器或复制旧授权。

## 建议首批安排（须批准，不是事实）

- 默认最多3台，优先相同模组/散热版本；不同配置分组。只一台也可先开始。
- 每台最多24小时。第一台在原有日常运行中先看前2小时技术健康，若没有阻断就在同一授权内继续；同一批已批准的其余机器可接着部署，不逐台等待主审再批一次。
- 每设备保持自己的run/config/model身份。不同主机不能共享单调时钟或热状态；多台数据不池化成“一个更大实验”。
- 默认0个TTO Requester，用户日常业务不受TTO预测状态指挥。TTO自己的状态失效不暂停/终止用户现有工作。
- 不额外做CPU60秒，不要求YET/jtop或全部热平衡；正常恢复保留原样，不因为出现一次缺口重开run凑满。
- 24小时没有工作负载就报告观测内容不足；由推理线提出一个后续有界场景，不能自动延长、增压或补跑。

## 现场结果怎样决定后续

| 结果 | 下一步 |
|---|---|
| 软件稳定、模型有条件预测，部分工况平均有增益 | 保留已冻结版为观察稳定基线；用新数据推进候选校准 |
| 记录完整、但新设备模型有偏差 | 不停止全部观察；该配置标待校准，生成本机candidate，不称通用模型已有效 |
| 反馈反复失效，预测大部不可用但raw可信 | 保留日志；准确说模型验证不足，针对通讯问题处理；其余机器不自动一起判失败 |
| 软件越权、串机、记录不保真或资源不可控 | 停自己的候选并回退；问题解决前不扩机器 |
| 没有活动信号足够变化 | 不“学习”出假系数；保留旧模型或无模型，只建议最小有信息量的新过程 |

## 防止再次钻支线

每个新假设必须写清：解决哪个产品问题、现有最简单基线、什么结果值得继续、最多一次怎样的实验。如果没显示足以覆盖成本的增量，归档待新证据；不能改名后成为新的主线前置。

本阶段CPU逐核为paused，不是证明永久无效；无需为暂停再做完12请求。通信修复最多围绕已明确长延迟做有证据工作，不要求无缺口才能观察。Web UI不阻断观察版，模型生成不阻断冻结版试跑。

每个交付只汇报五项：用户获得什么；实际做到什么；证据；限制；下一步。少量已知非阻断问题随版本维护，不为“全绿”无限返修。
