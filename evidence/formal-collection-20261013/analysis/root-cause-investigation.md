# 本轮采集异常定位（只读调查）

调查对象：正式采集 c1a1bd6a 和续采 f43af598。以下时刻均为北京时间，异常时刻是请求返回/超时报错时刻，并非异常实际起始时刻。原始数据、既有归档和产品代码均未修改。

## 结论与证据边界

1. 六次风扇请求是 TTO 等待主板 HTTP 响应超过 2 秒，不是风扇停止，也不等于温度订阅过期。六次均与主板发起的 Thor SSH 查询重叠。结合主板 SSH API 在 httpd 内同步连接/执行的实现，最有证据的原因是主板 HTTP 服务被 SSH 操作占用，风扇查询排队后超过 TTO 的 2 秒总超时。历史日志没有每条 HTTP 请求开始/结束记录或 TCP 抓包，因此不能把具体阻塞时长、丢包排除结果说成已完整证明。
2. 四次 stale 是主板自己报告并实际进入 25% PWM 兜底。主板在异常之前最近的有效温度更新，到异常时只有约 2.0–5.9 秒，低于固件的 10 秒过期阈值；TTO 的 Thor 温度流同时正常。因此不能把这四次直接解释成订阅连续停更超过 10 秒。源码中存在明确机制：控制定时器以零等待读取变量锁，取锁失败和真正数据过期都变成同一个 invalid/stale 状态；变量锁争用是最符合这些观测的根因。历史日志没有记录取锁失败原因，无法逐次直接证明是哪把锁、哪个持有者。应区分“机制已经定位”和“每次触发已直接捕获”。
3. 6 分 28.545 秒缺口来自首段采集到 30 分钟后正常自动退出、续采没有及时接上，与上述 HTTP 超时、主板 stale 无关。

## 四次主板 stale

| 主板返回时刻 | 工况 | HTTP RTT | 最近已知有效主板变量更新距异常约值 |
|---|---|---:|---:|
| 10:34:15.202 | 4 单发推理 | 1033.17 ms | 5.94 s |
| 10:34:22.145 | 4 单发推理 | 12.15 ms | 2.02 s |
| 10:49:36.606 | 5 并发推理 | 12.38 ms | 3.49 s |
| 10:51:24.192 | 5 并发推理 | 11.12 ms | 5.89 s |

这四次 fan.status 都成功返回 code=0，auto_state=stale、temp_stale=true、temp_valid=false、duty/target_duty=25，没有 fault/guard。相邻 temp.status 在 10:34:15.641 和 10:51:24.335 也返回 active_source=default、valid=false、timestamp_ms=0；这证明主板内部温度源实际降级，并非 TTO 解析出来的假标记。后续恢复 variable/有效温度。

约值由主板 uptime 与观察机时间只读校准推算，校准 RTT 33 ms；不是任务精确打点，不用于主张毫秒级同步。即使保留时钟与采样误差，这些距离仍明显低于10秒阈值。

根因机制沿以下源码路径成立：
- ts_fan.c 控制定时器调用 ts_temp_get_effective_nonblocking。
- ts_temp_source.c 非阻塞读取时以0等待取温度锁和变量锁；read_fresh_variable_float 对取锁失败、变量不存在、数据龄超过10000 ms等情况统一返回false。
- evaluate_active_source_with_lock_mode 将读取失败的快照写为无效，活动源退到 default；并未区分锁忙和实际过期。
- ts_fan.c apply_adaptive_auto 把所有不可用输入统一标为 stale，并立刻 update_pwm(25)。

因此 stale 标签当前包含“读取暂时失败”，并不只代表订阅数据超过10秒没有更新。最符合历史观测的是锁争用触发错误降级。不能凭现有记录确认锁持有者，也不能用监控服务没有断连日志证明每条主板订阅消息必定收到。Thor tegrastats-api journal 本窗口只有 TTO 两次连接/断开，没有主板断连或服务重启记录。

设备报告固件为 0.6.2+88dd9807d.10130219。本机源码 HEAD 为88dd98079ce14d2180afef8efc41d742735568da，上述关键文件没有本地修改；版本对应同一短提交前缀，但固件版本包含构建标记，未做闪存二进制逐字节来源验证。

## 后续定位所需的最小证据（本轮没有执行修改）

若要把高置信机制进一步落实到每次触发，需要 HTTP 请求排队/handler 耗时或被动抓包，以及主板温度读取失败的原因和最后有效样本龄。仅增加TTO超时只能降低报错数量，不能解决主板HTTP阻塞；仅将stale解释成网络掉线会掩盖读取锁忙导致的控制降级。本轮未调整任何超时、订阅、日志级别、风扇控制或服务配置。

只读证据位于 diagnostics/：原始异常上下文、SSH关联、主板日志、设备身份/时钟校准与 Thor ssh journal。既有原始采集/归档保持原样。
