## 4. 四项实质问题

### R1｜P2：复用非连续过程名称，会把测试之后的记录放进训练区

**位置：**`src/tto/dataset.py:95–117`、`:139–177`。

`freeze_split`先按run开始时间排序，再按episode名称的第一次出现去重，随后把所有同名episode的行分到同一区。`check_split`的时间支持检查只比较同一run内的区间；跨run的检查又使用已经去重的episode列表，漏掉同名episode在更晚run再次出现的情况。

独立输入为六段按时间排列的合成run，名称依次A、B、C、D、E、A。调用真实`freeze_split`与`check_split`，两者均接受：

| 时间顺序 | 过程名称 | 实际分区 |
|---|---|---|
| 第1段 | A | train |
| 第2段 | B | train |
| 第3段 | C | validation |
| 第4段 | D | test |
| 第5段 | E | test |
| 第6段 | A | **train** |

**用户影响：**用户再次使用相同的过程名时，后采集的记录可以加入训练，报告仍把第4/5段称作按时间留出的测试。不能据此证明所有当前正常切分都错误，但这条允许通过的真实入口会破坏“只用过去训练、检验后续过程”的含义。

**最小修正：**分区前与分区验证时，都检查完整run/episode时间支持与分组顺序。发现非连续交错的同名过程，明确拒绝并说明哪些过程需要确认分组；不能静默把后段划回训练。相邻、确属同一连续过程的多次采集仍可分到同一组；不能自动改名制造独立实验。保留现有单run purge、原始引用/哈希验证，不另建通用跨设备时间平台。

**回归：**A-B-C-D-E-A必须拒绝或经明确分组后形成真实顺序；相邻A-A-B-C-D-E不应因相同名字被无故拒绝；正常唯一episode和单长过程探索模式保持原行为。

证据：`results/model-probes.json::chronological_split`及`scripts/check_model_paths.py`。日期、名称和内容均为审查合成夹具，不是用户已采集的数据。

### R2｜P2：多输入模型缺项，连TJ小模型的有效比较也被挡住

**位置：**`src/tto/evaluation.py:41–60、94–118`；`src/tto/report.py:83–95`。

当前先要求四种方法在同一起点都可用，才计算主共同评分表与进入价值判断。于是，“M0有用但M1暂时不可用”这条路线，也要先满足M1有结果。JSON另有各方法全量指标，并非数值完全没有计算；缺口在公平比较与最终结论的入口。

独立验证：用包内生产演示生成器产生五段720秒合成过程并训练，然后只在测试区移除M1选中的`vdd_gpu_soc`及其汇总特征。训练/验证未改，同一审查环境下重训的模型methods完全一致。结果：

- M1三时距均没有可用输出，四方法共同评分数均为0。
- M0在45秒仍有198个可评分起点，分布于两个测试过程，每个99个。
- 在B0/B1/M0三者共同的同一198个起点上，episode等权MAE分别为1.7294、0.8745、0.2930°C。
- 在明确的决策函数单元测试标志下，当前函数仍返回“证据不足：缺少足够未使用的独立测试过程或共同可评分起点”。

**以上误差只证明决策逻辑的反例，不代表任何真实模型的精度。** 为进入非模拟结论分支，复现脚本只在传入决策函数的副本里设置了明确标注的单元测试状态；没有把合成dataset当真实部署数据保存或发布。

**用户影响：**以后某个可选功耗域缺失，程序正确降级到M0，却可能无法告诉你“M0本身是否比简单趋势更有帮助”，主报告出现零共同样本/空成绩。你可能误以为整个建模都必须等待该字段恢复。

**最小修正：**预先固定分层比较集合：B0/B1；B0/B1/M0；B0/B1/M0/M1。每一组内部仍只比较相同起点与相同标签，并单列覆盖率、过程与阶段。不用不匹配样本相互比较。M1不可用应影响“M1增量价值”的结论，不能自动抹掉M0对基线的证据。全四方法表可以保留，但不能是所有判断唯一入口。基线-only评估也应有可读结果。

这项修正是在落实“简单模型可单独有用、辅助缺项不应拖死整体”的产品目标，也补清原方案对共同交集层次写得不够细的地方；不是为了让M1赢而放宽评分。无须新增插补、换模型、增加超参数搜索或改温度真值。

证据：`results/model-probes.json::missing_full_model`。

### R3｜P2：旁路预测已经存下，报告却完全没有读取它们

**位置：**`src/tto/report.py:21–49`；辅助路径`dataset.py:10–23`、正确落盘路径`collector.py:160–173`。

`summarize`调用不带模型的`replay(run)`；`run_report`固定写“预测效果：待真实时间隔离评估”。这条路径没有读取本run的`predictions.jsonl`与`scores.jsonl`，也没有按固定旁路模型汇总误差和覆盖。

独立验证使用真实`Engine`、`Journal`、`summarize`和`run_report`，以合成观测生成一个400秒的模拟旁路过程：已经保存44个包含M1的预测起点及102条M1时距评分。102条是不同起点/时距的评分记录，不是102个独立使用场景。报告仍不展示模型成绩。再把这两个日志文件在自己的合成目录中移开，前后`summarize`结果完全相同。

**用户影响：**以后你真实运行旁路半小时，预测与评分虽然保存了，但按正式report命令生成的页面依然只告诉你“以后再评估”，不能完成“模型实际预测得怎样”的使用闭环。此问题不是“尚无真实训练数据”能够解释的；对应报告功能已经在模拟路径上漏接。

**最小修正：**区分collect记录报告、离线留出评估报告与shadow实际运行报告。shadow从已保存、带模型身份与起点身份的预测和追加评分汇总；保留fallback、未评分、跨段及缺项。不能用事后新加载的模型回算，冒充当时已经发出的预测。原始预测不可覆盖。

报告应给出模型身份、实际方法、各时距数量/误差/覆盖与原始引用；有缺失证据就明确提示。模拟仍明显标模拟；真实旁路的在线表现也不能被包装成新的独立留出验证。下一步随状态变化，不再所有报告固定要求重新doctor。

回归同时覆盖有模型/无模型、有评分/无评分、降级、缺失日志、模拟标识，以及过去保存的预测不受后来模型文件变化影响。无需为此建设在线仪表盘。

证据：`results/model-probes.json::shadow_reporting`。本轮没有绕过“模拟模型禁止连接真实端点”的保护，测试全程离线。

### R4｜P2：默认WebSocket握手没有继承HTTP的重定向限制

**位置：**`src/tto/collector.py:120–132`。

HTTP `_request`设置`allow_redirects=False`并拒绝3xx；但`ws_connect`仅校验初始地址，直接调用底层session的WebSocket连接。底层握手自己的HTTP请求不会经过TTO外层的`_request`校验。

使用安装候选和aiohttp 3.13.3，在两个临时127.0.0.1端口建立真实本地服务：授权的`/socket.io/`返回302，指向另一端口的`/not-authorized`。生产WebSocket路径跟随跳转，第二服务收到请求和测试自定义header。相同设置下ESP32状态GET正确拒绝跳转。

该header值仅为`nonsecret-fixture`，没有使用真实密码或Token。**不据此声称标准Authorization一定会跨源泄漏，也不声称用户现场发生过跳转。** 已证明的是既定“只接指定目标/路径、不跟随重定向”的边界漏在默认WS握手上。

依赖证据分层：真实执行用本审查环境aiohttp3.13.3；另外核对候选锁定aiohttp3.11.18官方`client.py`，其`_ws_connect`也委托`self.request`，未覆盖默认重定向行为。不是仅凭另一版本推测；但锁定版本的端到端Socket.IO复跑仍应由依赖完整的执行端完成。

**最小修正：**在实际握手及重定向跟随发生之前落实原origin/path和不跳转策略，使HTTP与WS走一致边界。不能等第二目标已经连接后再报错。不要简单给不支持该参数的`ws_connect`塞`allow_redirects=False`并声称修好；采用与锁定版本兼容的接口/钩子，实际证明第二目标零请求。保留必要Engine.IO GET/POST、heartbeat与显式polling；不重写Socket.IO，不禁用TLS验证，不另建权限平台。

回归：正常WS、正常显式polling、跨源跳转、同源未授权路径跳转、ESP GET原限制，以及失败后的有界关闭。该项完成后再开始用户的真实只读采集。

证据：`results/ws-redirect.json`、`scripts/check_ws_redirect.py`。

官方源码参考（只用于依赖行为核对）：
`https://raw.githubusercontent.com/aio-libs/aiohttp/v3.11.18/aiohttp/client.py`
