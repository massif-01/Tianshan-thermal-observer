### 3.2 参考源码链

固定参考：[ts_fan.c@88dd9807](https://github.com/RMinte-AI/TianshanOS/blob/88dd98079ce14d2180afef8efc41d742735568da/components/ts_drivers/src/ts_fan.c)。AUTO由timer callback推进，温度事件只服务旧CURVE路径。普通AUTO链为：

```text
可信控制/guard温度 → 历史 → 30秒斜率（至少10秒跨度）
                         → 到期的响应学习更新gain
基础曲线整数插值 → 风险/正趋势追加 × gain → 未限速需求
                  → 退档许可 → 差额式下降限速 → PWM HAL
                  → HAL成功才更新current_duty/duty_valid
```

在非硬保护分支，基础值B加额外量，额外量包含：95°C保护温度剩余余量不足25°C的追加、45秒预测超过85°C的追加，以及`2×max(30秒斜率,0)`，额外量乘gain。高预测可能请求max_duty，实际guard达到95°C则独立锁100%，到90°C以下连续有效30秒才释放。这些风险路径与本次低温拖尾应分开。

退档条件是`guard≤90°C && (斜率无效或≤0)`。未限速需求低于当前成功PWM、条件不满足时，继续保持当前PWM。因此没有必要假定控制器知道“请求已完成”；此函数没有请求结束、GPU利用率或功率输入。

获准后才进入下降限速：`fall_rate=max((当前PWM−需求)/30秒,0.30个百分点/秒)`，累计小数额度，够整数步才降低，接近需求时进入慢尾；升档仍按12个百分点/秒。30秒在趋势窗口、响应学习和差额分母中分别出现，并不是每题结束后启动一个固定保温计时器。API的`target_duty`已经过许可与限速，不是链中的“未限速需求”。

### 3.3 为什么一个快照可以算出37%，却记录42%

S01首峰原始引用为`d2a7593a…/observation:1075`。48.5°C、斜率6.6°C/min、gain1.77525985，在低温分支没有额外高温余量项：

| 曲线假设 | 整数基础值 | 趋势追加 | 四舍五入前/后需求 |
|---|---:|---:|---:|
| 用户JSON | 14% | 13.2×1.77525985 | 37.433 → 37% |
| 当前回读曲线 | 19% | 相同 | 42.433 → 42% |

用户已纠正此前JSON的归属，文件算出的37%不能再作为这台Thor现场需求的预期。当前回读曲线给出的42%解释了这个**即时计算差异**；仍没有据此证明实验时完整曲线就是当前这一份。没有反调gain、系数或曲线来凑42%。

更不能用它解释所有峰值：S05首个38%快照温度45.2°C、斜率2.4、gain1.445960，用户曲线即时需求约19%，当前曲线也只有约24%。输出可能来自此前周期的需求并被正趋势保留，原API没有保存每个控制周期的未限速需求和学习观察状态。准确分摊仍缺历史配置、控制周期与构建身份。

## 4. 唯一推荐方案：增加额外输出的退出许可

### 4.1 最小改动与输入

建议只在TianshanOS **ts_fan.c**内修改：在现有`allow_down`旁加入一个额外许可helper，在每个fan的状态中保存许可/新报告确认信息，并在已有AUTO重置、失温和硬保护入口清理该许可。沿用现有温度历史、有效性、源身份/报告时间、当前成功PWM、当前未限速需求、guard温度及45秒预测。

不需要TTO或WS新增任务结束输入、GPU负载输入或控制接口；不修改需求公式、基础曲线、普通min/max、上下升降速率、保护或失温输出。本轮只在独立分析目录实现原型。

### 4.2 退出条件与状态生命周期

保留原有退档许可。额外许可只负责回收“当前成功PWM高于此刻未限速需求”的部分，目标仍是原公式的动态需求，不能直接压到基础曲线，更不能强制最低档。

工程初值如下，**没有按42%或逐题收益搜索参数**：

| 条件 | 初值及依据 |
|---|---|
| 风险隔离 | guard<70°C、45秒预测<85°C；避开原公式高温余量及预测追加开始的区域 |
| 降温证据 | 现有历史中约5秒跨度，容许一个1秒timer周期偏差，即4～6秒；净下降至少0.3°C |
| 新报告确认 | 同一有效温度来源/身份至少3份递增时间戳报告；重复缓存不增加确认数 |
| 待回收量 | 当前PWM>未限速需求，且>当前基础需求；保留原动态需求作为下降终点 |
| 重新升温 | 单份新报告或约2秒历史累计上升≥0.2°C，立即取消额外许可并重新积累降温证据 |
| 失效 | 输入失效/失温/partial-stale、身份变更、报告倒退、间隔超过两个timer周期、故障、硬保护、AUTO重置或没有待回收量时清除 |

0.3/0.2°C分别对应参考控制温度0.1°C量化的3/2格，用于避开单格抖动；4～6秒容差来自现有1秒推进周期。它们是待验证工程初值，不是实测最优或对铝体温度的估计。

降温证据建立后，允许在近期趋稳时继续退出历史额外量；重新升温、风险升高或有效性丢失立即撤销。原趋势/预测需求一旦上升，仍走原升档路径。新请求不需要等“回落完成”才响应。本方案减少的是长窗口残留趋势对**退出许可**的阻挡，没有统一加快下降速度。

状态应归属于每个fan，不能以全局变量串扰其他风扇；本离线harness仅有一个fan。实现时同步接入已有模式重置路径，不改字段合同。候选实施边界为这一源文件及其必要窄测试，实施前另行复审。

## 8. 低阶灰箱：具体辨识设计

### 8.1 候选结构与真实输入

先辨识一个快/慢两状态的**等效温度偏差模型**，不是直接给芯片/铝体贴上物理热容。快状态x_f近似TJ相对启动基准的偏差，慢状态x_s是未测热体的等效偏差；唯一必需观测为reported TJ，CPU/GPU/SOC温区用于独立残差检查，不能替代不存在的TTP/环境温度。

每个连续段以预测开始前已获得的背景样本确定T_ref、各P_ref及u_ref，禁止用全段或未来平均值作基准。u为成功逻辑PWM/100，三路ΔP分别保留原名与W单位。候选方程：

```text
dx_f/dt = −a(x_f−x_s) + b_gpu ΔP_vdd_gpu
                       + b_cpu ΔP_vdd_cpu_soc_mss + b_5v ΔP_vin_sys_5v0
dx_s/dt =  c(x_f−x_s) − (d0+d1·u)x_s − d2·(u−u_ref)
TJ_hat  =  T_ref + x_f
```

约束a,c,d0>0，d1,d2≥0，b各自≥0；a/c/d0/d1单位1/s，b单位°C/(W·s)，d2单位°C/s。d2表示在背景附近改变风量的等效降温项，不能被命名为测得的环境温差。gain不另外作“热输入”：其影响已体现于成功PWM；没有必要把gain与PWM重复当两个冷却执行量。

环境测量缺失：只对每个连续段近似环境稳定作明确假设，把背景偏置放入参考值和慢初态，不同时自由拟合环境温度、额外常数热源及传感器偏置，以免等价参数无限互换。假设不满足则该段残差会暴露漂移，须报告未知；不会填入假环境温度。未知参数最多8个动态系数，加每段慢初态；它们是等效系数，不倒算kg/J·K或宣布真实热容。

### 8.2 数据段、初态、拟合与可辨识性

1. 输入使用本轮保存的**2529+1610条accepted完整原时间序列**及原fan as-of证据，不降成每5秒预测表。每份样本保留来源引用与资格；缺成功PWM或资格边界不跨越插值，不把不同小段拼成一段连续热过程。失温输出若有成功证据照实保留为事件材料，正常参数拟合按原资格隔离。
2. 每段开始留出至少60秒因果初始化背景。x_f(初始)从当时TJ−T_ref取得；x_s(初始)未知，只用该段已经发生的前60秒观测、固定动态系数估计。训练段可以联合拟合其慢初态；验证/预测时不以未来温度重新拟合初态。段过短就报告无初始化覆盖。
3. 在训练窗口完整约1秒序列上，用实际不规则Δt、零阶保持各当前输入，矩阵指数或等价稳定状态传播；一次约束非线性最小二乘，残差用固定Huber尺度0.3°C的初始设计，参数正性/稳定性作为约束。不增加候选模型或网格。单一数值初值为a=0.1、c=0.005、d0=0.001、d1=0.003、d2=0.05、b_gpu=0.03、b_cpu=0.01、b_5v=0，随后检查残差和Jacobian；这些只用于数值初始化，不是已辨识热参数。不多起点搜索到“必须胜出”。本轮交设计，不报告这些系数已拟合。
4. 当前rail之间高度相关：七工况CPU/SOC/MSS与5V的Pearson约0.9988，短问答约0.9942；标准化三rail+PWM矩阵条件数约57/33。代数满秩也不意味着可辨别各路发热或风量贡献。若Jacobian秩差/系数不稳定，先固定b_5v=0作为不增加自由度的嵌套结构，仍保留5V原数据作残差诊断；不将三rail相加。单一快状态是必须保留的更简单参照，两状态不得预先被认定正确。
5. 检查块敏感性、初态敏感性、参数相关和残差自相关。AUTO使PWM受温度驱动，负载/PWM并非独立激励；本数据不足以把“多风量贡献”与“任务结束”完全分开，也可能无法独立辨识慢状态。识别失败要返回具体秩/残差/覆盖，不用正则化参数冒充物理真值。

### 8.3 验证与未知未来输入

沿用当前原工具可支持的purged时间开发窗口；参数、缩放、参考状态估计方式先固定，再评估15/45/90秒。灰箱评价与B0/B1/Ridge必须报共同起点、额外覆盖、欠预测风险及脉冲前后误差，按连续段/时间块汇总，不把18条题当18个独立热过程。两轮都已用过，正式确认必须依赖未来未使用过程；本轮没有为此启动新实验。

预测时仅使用起点之前的观测来估计状态。未来负载/PWM未知时，默认分别保持起点最后有效三rail和PWM，输出明确的“保持输入情景”；输入未知或过龄就降级到B0或报告无覆盖。若以后有事先已知的操作计划，可另报已知输入情景，保留它的来源；不得把未来实测功率、未来PWM或真实任务完成时刻倒填进主预测。历史重建使用过去实际输入与预测使用未知未来输入，是不同用途。

不依据Ridge输赢决定灰箱是否值得研究。当前完成结构、输入、可用段、初态、拟合/验证及未来输入规则的设计；没有识别真实热容、没有启用在线模型或修改控制。
