## 2．R4：先封住WebSocket实际握手的跳转缺口

**原位置：`src/tto/collector.py:120–132`。**

### 要修的行为

ESP32普通HTTP请求已经拒绝重定向，但默认WebSocket握手只检查初始地址，底层握手能够跟随302进入另一个端口或未授权路径。本轮只补齐已经约定的连接范围，不建设新的安全平台。

### 实施要求

1. 在底层真正发送跳转后的请求之前，落实原有origin/path与不跟随重定向策略。正常HTTP与WebSocket握手须一致受约束，不能连接到第二目标以后才报错。
2. 使用与锁定依赖兼容的局部接口或钩子。先确认实际调用链，不能给不接受该参数的 `ws_connect` 直接塞入 `allow_redirects=False` 就宣称完成，也不能仅在外层校验一次URL。
3. 保留正常Socket.IO、心跳、断开重连与显式polling；必要Engine.IO GET/POST是传输协议，不是风扇业务写入。不要取消polling所需的两个传输HTTP槽，也不要新增第二条业务会话。
4. 不关闭TLS验证、不重写Socket.IO、不全局猴子补丁其他进程或第三方安装文件。优先保持当前锁定版本；确实需要依赖变化时，说明必要性和范围，更新锁并完整重跑相关协议测试，不泛化升级。
5. 失败后正常释放自己的连接、任务和会话，保持原有重试上限；日志不输出真实凭据。

### 验收

在候选锁定的Python 3.10兼容隔离环境中，使用生产客户端和真实loopback服务验证：正常WebSocket、正常显式polling、跨源跳转、同源未授权路径跳转、ESP32 GET已有拒绝行为，以及失败后的有界关闭。

**决定性断言：跳转目标的实际请求计数为0。** 使用非敏感测试header，证明不是“header被删了但请求仍发出”。上一轮实测为aiohttp 3.13.3；本轮必须覆盖候选锁定的aiohttp 3.11.18及对应Socket.IO/Engine.IO，不能只重复另一依赖版本的结果。

## 3．R1：分区建立与验证都必须保证真实时间顺序

**原位置：`src/tto/dataset.py:95–117、139–177`。**

### 要修的行为

按时间排列的六段run，过程名称为 `A → B → C → D → E → A`，原实现会接受 `train → train → validation → test → test → train`。同名过程最后一次出现的位置没有进入完整的时间顺序验证。

### 实施要求

1. `freeze_split` 与 `check_split` 使用一致的时间/分组规则；检查全部run与episode的实际时间范围，不能只依据过程名首次出现后的去重列表。
2. 非连续、交错的同名过程不得静默分回早期训练区。明确报出冲突的过程、run与时间范围，要求确认分组；不要自动改名、拆组或删除后段来制造更多独立实验。
3. 相邻且确属同一过程的多次采集允许合组，不能把“名称重复”一概视作错误。
4. 保留原单run的purge/支持区间隔离、原始引用和哈希校验。跨run排序使用已有可核对的时间信息；不同run的本地单调时钟不可直接相减。时间证据不足时明确说明，不假装已经形成严格时间留出。
5. 训练和评估实际消费split时也须经过有效校验，不能仅创建新split时正确，却仍接受手工改坏或旧的无效清单。
6. 不覆盖已有冻结split、模型或test-used记录。需要重新生成派生产物时用新路径与新身份，标注旧产物不再用于正式结论；已经看过的真实测试数据不能被重新称作未使用留出。合成夹具可重复用于软件回归。

### 验收

必须覆盖 `A-B-C-D-E-A` 的原反例、相邻同组 `A-A-B-C-D-E`、正常唯一过程，以及原单长过程探索路径。分别从创建和直接验证入口检查，保留原支持区间与未来数据扰动回归。

**关闭条件：**晚于测试的数据不能因复用名称进入训练并通过时间留出校验；同时正常连续分组仍可用。

## 4．R2：分层公平比较，M1缺项不能抹掉M0证据

**原位置：`src/tto/evaluation.py:41–60、94–118`，及 `src/tto/report.py:83–95`。**

### 要修的行为

M1因已选功耗字段缺失而停止输出时，M0与简单基线仍有可评分结果，原判断却因四方法交集为0而阻挡M0的独立价值判断。

### 本轮明确的比较合同

在下一次真实评估前登记以下固定层次：

| 比较层 | 共同评分集合 | 能得出的结论 |
|---|---|---|
| 基线层 | B0与B1均可评分的相同起点、相同标签 | 两种简单办法在这批过程中的表现。 |
| M0层 | B0、B1、M0均可评分的相同起点、相同标签 | 仅TJ历史的小模型是否比简单办法有帮助。 |
| M1层 | B0、B1、M0、M1均可评分的相同起点、相同标签 | 多输入模型是否进一步增加价值。 |

1. 每层独立汇总样本数、覆盖率、episode与升温/回落等已有阶段；15/45/90秒都保留，45秒仍是主时距。
2. M1层没有足够数据，只影响M1增量价值判断；M0层有足够证据时正常判断。只有基线也应有可读报告，不显示为整套评估故障。
3. 不能拿M0层MAE与M1层MAE直接比较模型优劣，因为样本可能不同；M1的增量比较须使用M1层内的同一批起点。
4. 保留各方法全量覆盖、缺项与fallback记录。M1降级为M0不能算作M1成功，缺项不得填0、续旧功耗或靠新插补恢复资格。
5. JSON、Markdown、HTML和最终价值判断使用同一分层结果。全四方法表可以保留，但不再是所有结论的共同前置条件。
6. 保留原部署身份、真实/模拟标识、独立测试过程、困难阶段覆盖与欠预测风险要求。修复后“能够评价M0”不等于强制宣布M0有效。

### 验收

复用原反例：训练/验证保持不变，仅在测试阶段移除M1已选字段。应看到M1不可用及明确原因，同时M0在自己的共同集合上正常比较；原夹具的198个45秒可评分起点用于复现核对，不作为生产硬编码或必须达到的数量。

另覆盖四方法齐全、M1局部缺项、只有基线、证据不足与没有稳定收益。不能通过换测试集、放宽新鲜度、调整温度真值、增加超参数或取消模拟标识让结论“变绿”。

## 5．R3：旁路报告读取当时实际落盘的预测与评分

**原位置：`src/tto/report.py:21–49`；相关路径 `dataset.py:10–23`、`collector.py:160–173`。**

### 要修的行为

当前旁路已保存模型预测和评分，报告却走不带模型的回放并固定显示“待真实时间隔离评估”。本轮补齐报告消费路径，不改写过去预测。

### 实施要求

1. 明确区分三类报告：普通collect的数据质量报告、离线时间留出评估报告、shadow实际运行报告。优先复用现有命令/manifest/记录，必要时局部补充明确类型；不建立常驻仪表盘。
2. shadow的事实来源是本run已经保存的 `predictions.jsonl`、`scores.jsonl` 及对应身份信息。按现有记录中的预测身份、时距、方法与模型身份关联，不凭行号或到达次序硬拼。
3. 输出各时距实际预测数、可评分数、误差与欠/过预测指标、覆盖、fallback、未评分/跨段/缺项原因，以及可定位到原记录的引用。保留原已有指标口径，不新设效果门槛。
4. 不得加载一个后来变化的模型重新算出预测并冒充当时输出；不得覆盖、修饰或重写原始预测和评分。观测回放可继续辅助质量诊断，但不能替代shadow历史事实。
5. 有预测无评分时，显示已发出但尚未能评分；缺少应有日志时，显示具体证据缺失，不填0、不假装运行过模型、不偷偷退回无模型回放后宣布完整。
6. 模拟数据仍明显标模拟；真实旁路记录仅描述该次在线观察表现，不能冒充新的独立留出测试或允许降低PWM的证明。
7. 三种输出格式内容一致；图按预测目标时刻对齐，保留模型身份与实际方法。下一步提示随状态变化，不再所有情况固定要求重新doctor。中文先说发生了什么、缺什么、下一步是什么，技术字段放详情。

### 验收

用生产Engine/Journal生成离线模拟shadow记录，再走正式 `tto report` 入口。报告须能读到实际保存的模型、预测与评分，汇总与原日志一致。

同时覆盖无模型的collect、有模型但无评分、部分降级、缺失日志、模拟标识。记录完成后更换或移开当前模型文件，已有旁路统计不得改变；移走预测/评分日志时，报告必须明确改变为缺证据，不能仍给出相同的完整结论。测试只操作新生成夹具副本。
