## 0．先读这一页

### 0.1 项目和目标

项目名称 **Tianshan Thermal Observer（TTO，天山热观察器）**，建议新仓库目录 `tianshan-thermal-observer`。

> 在不改变现有单风扇控制的前提下，自动记录温度、负载、功耗与成功下发的风扇档位，建立一个轻量的短期TJ预测模型，再用未参与训练的数据检查它是否比简单趋势方法更有价值。

**TTO是观察器，不是新的风扇控制器。** 现有TianshanOS智能模式继续负责风扇；TTO退出、断网、预测错误或没有模型时，不向现有系统发送任何补救调速。

## 1．事实基线与本次设计分开

### 1.1 已确认的产品事实

- 一个共享散热结构、一个风扇；有Jetson与x86计算机。用户描述整体铝散热结构热容较大，但没有提供可辨识的热容/热阻参数或独立铝体温度测量。
- 当前主要测温是Jetson `tj-thermal`。它是指定片上温区的最高值，不是均热板温度，也不覆盖整机所有外部热源。[E1]
- 用户希望正常温度与性能条件下尽量安静；本轮不改变已经满意的控制来追求新名称或新模型。
- 新观察器在N305/16GB/Ubuntu22.04运行。当前不需要串口、不需要恒功耗任务、不需要用户手抄或录屏取数。

**现有TianshanOS参考实现确实包含响应学习和增益参与输出。** `apply_adaptive_auto`调用`update_response_learning`，增益影响基础曲线以上的补偿，差额式回落也在实际路径中。[S3] 不能混入早期未集成的TTI候选、“已删除旧学习”的叙述或专用`@TTI1`遥测能力。本轮不重新审计整个风扇控制器。

### 1.3 从“热模型”落实为首版的选择

前期讨论提出小型热响应/灰箱建模方向。本次把**可验收的首版**定为：有温度与负载历史的、带正则化的动态回归；不先拟合不可观测的物理热容。

这是本次实施设计的具体化，不是声称旧代码已有该模型。它保留快/慢变化的信息，学习在当前控制继续工作时温度的统计响应；**不是RC物理网络，不把拟合系数命名成真实热阻或铝体热容量**。RC灰箱模型是有依据的后续对照路线，但本轮不并行建设它，不扩展成神经网络/MPC/RL。[E2]

理由：目前没有独立铝体温度与环境温度的可靠测量，现有风扇还在随温度闭环调节；先证明可观测数据对预测有帮助，比给隐藏状态贴物理名称更容易验证。

## 3．架构：两路输入，无控制输出

```text
Orin已有rm01OrinStatus ─ Socket.IO tegrastats_update ─┐
                                                   ├─ N305：TTO
ESP32已有TianshanOS ─ 已确认的只读状态GET ────────────┘    │
                                                        ├ 原始接收记录/质量报告
                                                        ├ 历史回放/离线拟合/留出评估
                                                        └ 固定模型实时预测/事后核对

现有ESP32→风扇的控制链不变。TTO没有→风扇/温度源/服务重启的业务写路径。
```

**Orin数值直接从Orin服务取得，不绕ESP32转发一遍再当“同一原始测量”。** 这样避免内置旧客户端对CPU/内存/功耗字段的历史结构差异影响新模型。[S1]

### 3.1 实现组件

建议少量模块：配置与只读策略、Orin适配器、ESP32适配器、接收记录、时间/质量处理、统一特征器、模型、评估与报告、CLI。可以按现有工程风格合并；不要求为了目录树制造空模块。

优先Python3.10兼容代码。采集采用一套 `asyncio` 调度、`python-socketio` 5.x兼容客户端与`aiohttp`，实际依赖须在目标兼容隔离环境安装并冻结。**不把“最新”当兼容版本号**。numpy/scipy/scikit-learn用于离线训练，预测只需冻结后的数值系数与预处理；不要让只采集命令强制加载重型训练库。

采集CPU、内存和自身写入速率可用psutil；测试pytest。没有MATLAB授权需求，没有CUDA/torch/TensorFlow/LLM下载，没有云端日志、数据库服务、消息中间件或常驻Web后端。

### 3.2 真正的只读边界

- Orin只连接指定Socket.IO namespace/event；不调用其模型日志接口，不保存模型输入、输出或任务文本。
- Socket.IO/Engine.IO握手、心跳、连接管理可能包含HTTP POST或协议帧；**允许必要传输协议，不把“所有网络只能GET”写成错误限制**。业务层禁止自定义控制emit/call。[E3]
- ESP32业务请求仅准入已核对的GET路径，默认禁止重定向、不扫描API。不能做一个允许任意method/path的管理客户端，再只靠注释要求只读。
- 鉴权使用用户本机提供的既有凭据；不自动登录试口令、不生成管理员账户、不修改认证。确需既有登录交换时，先按实际合同单列授权，不绕开安全机制。
- 不更改WS源采集频率，不重启tegrastats，不重复启动采集服务。一个TTO采集/旁路进程共用一条Orin连接和一组ESP32轮询；本机锁防止误开两个实例。
- 只读请求仍有开销，不承诺零影响。失败时暂停/退出TTO、保留原因，不能“自愈”到风扇控制或源服务。

## 4．输入合同与字段使用

### 4.1 Orin：Socket.IO，不是裸WebSocket

配置为用户提供的 `orin.base_url`，协议参考端口58090、path `socket.io`、namespace `/`、事件 `tegrastats_update`。不要把仓库内默认内网IP当作当前授权目标。默认只选WebSocket transport，握手细节由兼容库处理；确需polling时显式配置、记录，不自写`42`字符串客户端。[E3]

保留完整接收到的该事件JSON对象及本地接收信息。JSON对象重序列化叫“收到的对象记录”，不冒称原始WS字节抓包。`model_status_update`可被库接收，但首版不存其中日志/内容；也不能把“模型服务运行中”当作实时推理中。

#### 元数据：输入schema 1

| 路径 | 使用规则 |
|---|---|
| `telemetry_meta.schema_version` | 已支持版本必须显式识别；未知版保留诊断，不按v1偷偷读取。 |
| `stream_id` | 源采集生命周期身份，不是物理主机ID、Socket.IO sid或风扇控制会话。 |
| `sample_seq` | stream内接受输入行的序号；0表示无首帧。完整样本键为`source_id + stream_id + sample_seq`。 |
| `received_at` | Orin采集线程读入行的UTC时间；不是硬件精确采样时间。 |
| `sample_age_ms` | 发送快照时在源主机计算的接收年龄；不含未测得的网络延迟。 |
| `fresh` / `collector_state` | fresh需为true且state为running才能用于新预测；不保证每个字段齐全。 |
| `freshness_timeout_ms` | 按该帧提供的正数界限读取；不得固定假设永远5000。 |
| `time_basis` | 预期`collector_receive`；其他定义不静默当作相同时间。 |
| 顶层`timestamp` | 保留发送时刻语义，**不能用它创造新样本或重置测量年龄**。 |

已审合同的默认过期界限是 `max(5000ms,3×实际采集间隔ms)`，达到界限即不新鲜。TTO只消费它，不修改Orin或ESP32的有效期。[S1]

#### 数值字段

| 输入 | TTO含义与处理 |
|---|---|
| `temperature.tj` | 唯一首版预测目标，摄氏度。缺失/非有限时该帧不能成为TJ训练或预测样本；不以CPU/GPU替代。 |
| `temperature.cpu/gpu/soc0/soc1/soc2` | 有则记录独立测点；不能称均热板温度。上游可能不提供GPU温度。 |
| `cpu.cores[].usage` | Jetson被解析核心的使用率%，不是N305/ESP32 CPU。首版仅聚合有效已报告核心，并保留报告核数，不依赖历史有缺陷的物理核编号。 |
| `cpu.cores[].freq` | MHz；保留有效核心的聚合，不以频率充当功耗。 |
| `gpu.gr3d_freq` | 在本项目实际为GPU忙碌百分比0–100，名称虽带freq，**不能当MHz**。 |
| `power.<完整小写rail>.current` | mW，转W只在标准化层除1000且保留原值与单位。0有效，缺失不补0。 |
| `power.<rail>.average` | 上游平均值，定义窗口未证明；记录作诊断，首版模型不把它当固定30秒均值。 |

首版可选功耗域为 `vdd_gpu_soc`、`vdd_cpu_cv`、`vin_sys_5v0`。它们不是独立纯GPU功耗、纯CPU功耗和可随意相加的整机功耗。**不生成总功耗**，未知rail只记录、不自动进入特征。正常字段未到不阻止做TJ基线。

### 4.2 TianshanOS：成功输出和控制状态

固定参考已有GET `/api/v1/fan/status`、`/api/v1/temp/status`；执行方须核对实际路由、鉴权、成功外壳和当前部署合同，不能猜路径。主机只读快照工具可作参考，不直接盲跑其中的默认地址。[S3][S4]

`fan.status`可能返回单风扇对象或`data.fans`数组。按明确`fan_id=0`选择；本机只有一个风扇，**不平均全部卡片、不发现第二风扇后自动扩大任务**。HTTP状态与API `code`都检查；错误对象不能转换成数值。

| 字段 | 含义 |
|---|---|
| `duty` + `duty_valid` | 最后成功下发的逻辑PWM百分比；0为有效输出，null/false/缺字段是不可确认。不是机械RPM。 |
| `target_duty` | 当前请求值，AUTO中已受许可和限速约束；不是原始散热需求，也不能代替duty。 |
| `mode/enabled/fault` | 保留实际模式、使能与故障；用于分段/质量，不能由TTO修改。 |
| `control_temperature/guard_temperature` | 控制读数与保护读数；并非天然与Orin事件同一时刻，不当训练真值替代TJ。 |
| `predicted_temperature/slope_c_per_min` | 当前固件趋势参考；保留作45秒诊断对照，不当未来真值。 |
| `controller_gain/cooling_response` | 记录现有自适应状态；不能解释成热阻或已证明风扇因果效果。 |
| `guard_active/temp_stale/auto_state` | 当前状态；标记异常、保护、基线/活动等阶段。 |
| `rpm` | 没有确认测速线与有效性前，不用于模型也不把0当风扇停转。 |

`temp.status`至少核对 `current_temp_c/current_temp_01c`、`current_valid`、`current_timestamp_ms`、绑定/源、测试输入状态。`current_timestamp_ms`属于ESP32时钟域/变量更新语义，不能与N305 UTC直接相减，也不能代替Orin的样本身份。[S5]

默认fan状态每1秒一次、温度绑定状态每5秒一次；同ESP32最多一个请求在途，fan到期优先且temp不能长期饿死。请求结束后跳过错过的周期，不并发补发“追赶”。读配置只在开始/结束或用户已知变更时做有限快照；不为此引入更多高频接口。

**接口目前没有未限速需求、回落余额、完整HAL逐次事件或真实控制耗时。不能补造；HTTP往返时间不是固件控制耗时。** 同一JSON只证明同次接口返回，也不据此保证所有内部字段来自同一个原子控制周期。

## 5．时间、重连和样本质量：必须先实现

### 5.1 两种时间与一个因果约束

记录每个事件的N305 `observer_run_id`、UTC和本地单调接收时刻；ESP32请求另记发送、接收、往返时长。Orin原时间字段全部保留。

首版建模采用 **`observer_receive` 时间轴**：预测起点是N305当时已经可用的数据，未来标签是同一观察时间轴上收到的有效新TJ。产品报告需注明“接收时间近似，不是硬件采样时刻”。不未经验证跨主机对钟，不把网络延迟算成物理热滞后。

对已收到的帧，后续本地年龄可计算下界：

```text
age_lower_bound = 源报告sample_age_ms + 自该次本地接收起经过的单调时间
```

它仍缺少网络在途时间，不叫精确端到端年龄。同一身份反复收到时，不能让缓存重新年轻：保留首次接收锚点，保守使用既有年龄推进与新报告年龄中的较大者。遇到源fresh=false或不可用状态，立即拒用；**重复帧不能恢复预测资格，恢复需新的有效样本身份**。

最重要的不变量：某次预测使用的每条信息，其 `available_at` 必须不晚于该次预测起点。形成预测时保存不可变的特征快照和原始引用，后来到达的数据不能修改它。例：10:00:00收到Orin帧，10:00:01才收到fan状态，不能事后把后者放进10:00:00的输入。标签可以在未来寻找，特征不可以。

### 5.2 序号与生命周期

- 相同sample key的重发只记接收事件/质量状态，不增加训练行或预测次数；真正相同行但seq增加则是新样本。
- 同key的测量值发生冲突，记录冲突并隔离该段，不静默取最后一份。年龄/发送时间变化不属于数值冲突。
- 同stream内seq倒退按乱序拒用，不把旧行插回实时历史；明显重置但不换stream记协议异常。
- seq跳跃记录漏帧数。1秒采集但1秒推送是两个线程，跳号不必然是网络故障；仍不得补造缺帧。
- WS断开、stream切换、N305进程重启、长接收空白、配置/模型版本切换，断开可用特征历史，重新预热。WS重连不改Orinstream，但本地连接epoch要变。
- 断开前发出的预测，标签窗口若跨越输入断段/stream变化，标记不可评分，不从新stream拼回“答案”。保留所有不可评分预测。

### 5.3 缺失和新鲜度

原始记录保留null/缺字段和原因，绝不填0。TJ、成功输出、服务状态各自有可用性，不能一个`connected=true`代替全部。

默认历史最长180秒；长间断判据初值 `max(5秒, 3×实际源采集周期)`。该值是TTO的建模分段规则，不延长源fresh/控制TTL。源周期未知时先只记录并让doctor提示，不凭端口推断1Hz。

模型输入要求：当前TJ来自新样本且fresh；本地年龄下界未达到该帧界限。full模型的fan快照还需不超过2.5秒、`duty_valid=true`、`fault=false`。这些是本轮工程默认值，实际调整须在留出评估前登记新配置，不能为了成绩随时放宽。

保护、测试温度、手动/关闭、输出不可确认、控制模式/绑定变更的记录全部保存。首轮学习与主成绩限定**正常AUTO、源身份一致、没有故障/失温/测试输入**的范围；异常段另列数量和原始片段，不包装成系统能处理所有故障。

Orin与fan一时温度不同不能立刻判错误：它们异步、量化和绑定路径不同。报告差异与时间范围；持续明显差异时核查绑定，禁止自动改绑或用平均值掩盖。

## 6．记录、目录、隐私和资源边界

### 6.1 保留可重放证据，不保存无关内容

每次采集创建新的run目录，建议结构：

```text
run-<UTC>-<random>/
  manifest.json                  # 版本、环境、配置快照、单位、实际源周期/来源
  observations-0001.jsonl         # 收到的tegrastats对象、fan/temp API结果及时间
  events.jsonl                   # 连接、丢弃、分段、操作标记、错误、停止原因

  scores.jsonl                   # 未来到达后追加标签引用与误差
  summary.json                   # 数量、完整性、最终状态
```

`manifest`至少包含：TTO源码identity/dirty状态、配置schema和SHA、输入/特征/模型版本、两个源身份、部署核对状态、温度和功耗单位、fan_id、operator/unknown环境说明、起止时间、超时/资源限制、网络授权范围。没有装机固件SHA就写未验证或用户说明，不凭README版本伪造。

数据目录默认在仓库外（建议用户家目录 `.local/share/tianshan-thermal-observer`），权限仅当前用户。仓库提交模板、测试固定样例和文档，不纳入真实凭据、生产数据、模型服务日志、完整环境变量或个人任务内容。`.env`不自动加载；只读取明确列出的TTO环境变量。可选手动标签只允许短的场景词，不收推理内容。

传给复审的证据默认使用固定/合成测试样例；用户实测数据仅在用户授权分享后放入包。静态HTML对所有标签/文本转义，不加载外部CDN，不把本地报告变成脚本注入入口。

### 6.2 有界运行

默认：单条业务对象64KiB；队列同时限制256条和8MiB；原始数据单文件64MiB；单run上限2GiB；磁盘保留至少1GiB；一轮采集最多4小时，首轮普通采集默认30分钟。达到任一上限，正常停止本程序，**不循环覆盖用于训练/审查的旧文件**。

回调只做轻量检查、打时间与入队；写盘和报告不能在Socket.IO接收回调里长时间执行。队列满时显式丢弃并计数，标记历史断段；不无限等网络、不无界增内存，不悄悄采样后仍声称连续原始记录。

JSON解析、transport接收缓冲和应用队列的限制要分别检查；库已经分配的缓冲不能被描述为应用层64KiB检查已经预防。固定输入压力测试要覆盖大对象、断线风暴、慢盘、满盘和停止。

训练单独进程/显式命令运行，BLAS/求解器线程限制为1；不每秒重训，不默认在采集中并行训练。采集与预测不应因模型文件损坏停止保留有效观测，但必须撤下模型结果。

初始资源目标（工程预算，不是已测结果）：采集＋实时预测RSS≤256MiB，稳态CPU≤单核5%，一次三时距预测P99≤20ms。训练RSS≤2GiB、单次候选比较最多10分钟，禁止无限搜索。目标机测得不符时先检查实现与必要数据规模，再报告；不能借此改用GPU或直接吞下16GB。

CPU百分比口径明确为进程CPU时间/墙钟时间（100%=一个逻辑核）；另外报告峰值、P95、消息速率、轮询漏期、队列峰值、丢弃量。主机替身测试不冒充N305实测。TTO退出只关闭自己的任务、连接、文件和子进程，不用广泛pkill。

## 7．模型与基线：一次定义，不让执行端自由扩赛道

### 7.1 预测问题

固定时距H={15,45,90}秒，45秒为主。当前信息记作x(t)，目标为：

```text
ΔT_h(t) = T_J(t+h) - T_J(t)
预测 = 当前真实TJ + 模型预测的ΔT_h
```

这里的t/h使用上述观察接收时间轴。预测的是**现有控制仍运行、未来负载尚未知时的可观察TJ结果**。不能把后来实际出现的功耗、PWM、gain或模型服务状态送回该预测。

第一次拟合前冻结时距、特征版本和评估规则；不使用未来PWM路径递归模拟、teacher forcing或已有视频OCR帧充当训练遥测。屏幕记录仅用于历史问题解释，不是这次热系统的训练集。

### 7.2 四个必做比较

| ID | 方法 | 回答的问题 |
|---|---|---|
| B0 `persist` | 未来TJ保持当前值 | 有没有超过最简单的办法？ |
| B1 `trend30` | 近期真实TJ变化速度作线性延伸 | 有没有超过简单趋势？ |
| M0 `ridge_tj` | 仅TJ历史的同类动态回归 | 学习本身是否增加信息？ |
| M1 `ridge_full` | 同样TJ历史＋成功PWM/增益＋可用负载、测点及rail历史 | 更多观测是否进一步有用？ |

B1定义：同一连续段30秒内最早与当前的有效新样本，跨度至少10秒，以真实时间差求°C/s，`T+h*slope`；不把这一算法声称为精确复刻固件。默认不clip异常预测以美化误差，保存原始数值。

固件 `predicted_temperature` 可作为另外一列**45秒趋势参考的诊断**，只在该字段及AUTO状态可确认时保留。它承担风险控制语义，不能因为事后预测误差较大就宣布控制算法无用，更不能据此替换它。

### 7.3 统一、因果的特征器

离线回放和实时运行使用**同一个**有界特征实现；历史最长180秒，不用无限历史的隐式EMA造成切分泄漏。

M0特征：当前TJ；相对当前TJ的5/15/30/60/120/180秒滞后差；过去10/30/120秒TJ均值相对当前差；过去10/30/120秒的简单时间斜率。过去样本用因果as-of查找，只选当时已收到、位于目标滞后时刻之前的样本。

滞后允许误差初值 `min(5秒,max(2秒,2×实际采集周期))`；均值按接收时间作左侧持有的时间加权近似，绝不跨超过许可的数据空白，且始终保留该近似的定义。预热180秒只影响模型，B0/B1满足各自条件可先运行。

M1另加：成功PWM当前值、30/120秒均值、30秒变化；当前 `controller_gain`；以下**候选可选字段**的当前值或与TJ差、30/120秒历史均值：
- CPU/GPU/SOC0/SOC1/SOC2温度相对TJ的差；
- 已报告CPU核平均usage%、平均freq MHz与报告核数；GPU忙碌%；
- 三个已确认rail的current W及30/120秒均值。

总特征列数不超过64；确有超限先减少本次定义的冗余汇总并登记，不增加神经网络来消化数据。

可选字段仅依据**训练区**的可用率与实际合同选择：默认可用率≥95%、非全常量才纳入；固定原始字段名、单位和变换。不用测试区决定留哪些特征。缺少真实GPU温度或某个rail不是开工阻断，也不伪造该字段。

首版不做复杂插补：某个已选字段在当前/必需窗口缺失，则M1该次不可用，明确转为已验证可用的M0或基线，记录实际method和理由。**不能用M0的结果充当M1成功**。M0也不能获得完整历史时，退到B0/B1或不预测；当前TJ无效时不出新预测。

### 7.4 拟合与持久化

用标准化＋Ridge，不使用默认随机交叉验证。每个h独立直接预测ΔT，截距不惩罚。对每个方法固定小网格λ={0.001,0.01,0.1,1.0}，目标函数为：

```text
[Σ_i w_i (ΔT_i - b - x_i·β)^2] / Σ_i w_i  + λ ||β||²
```

实现映射到scikit-learn Ridge时，`alpha=λ×Σw`，避免把与样本量有关的两个正则定义混用。[E4] 可使用数值稳定的SVD求解；不自己求矩阵逆。每个训练episode总权重相等，episode内按有效时间分配；标准化均值/方差也仅从训练区计算并记录采用的权重方式。

M0/M1正式公平比较使用**同一组可训练起点**，另附M0在更多可用样本上的覆盖表现。标准化、特征选择、系数都禁止在val/test重新fit。

每个方法用验证集45秒的episode等权MAE选择一个λ，其他时距用同一个λ减少挑选空间；近似持平（≤0.01°C差）选择更强正则。最终测试前冻结模型文件与哈希，首轮不在测试前临时合并验证集重训。

持久化为可校验的JSON（数值系数、截距、缩放参数、列顺序、合同、来源、训练/验证哈希），不加载不可信pickle/joblib。模型≤5MiB，验证维度/有限数/版本/输入列表；实时加载失败不执行任意代码、不产生风扇写操作。固定模型不在线改权重，不自动切换新模型。

## 8．样本、标签与数据切分

### 8.1 起点不是每条WS消息

每次有效新Orin样本进入统一特征器；预测最多每5秒一次，选自真实新样本，不人为插出每秒“测量”。同一sample key只允许一个预测起点；原始记录仍保留每次接收和所有有效新样本。

5秒是首次实验起点节奏，不是源采样周期。各方法在同一个起点、同一个当前TJ、同一个可用输入截止时刻比较；不能先等未来HTTP返回再给旧起点补数据。

### 8.2 标签

h秒后的标签选同段内**第一份在t+h或之后到达**的有效新TJ，容差初值 `max(2秒, 实际采集周期)`，最多5秒。记录实际到达偏移，不用最近邻从t+h之前找旧缓存凑答案。

窗口内没有标签、跨断线/stream/控制配置边界或期间质量无法确认，标未能评分。不前向填充标签、不平滑真值、不跨缺段插值。15/45/90秒分别计可评分率；多次预测窗口重叠不是独立实验。

### 8.3 不把文件拆分当独立场景

`run`是一次采集进程运行，`segment`是连续可用段，`episode`是一次完整的使用/热过程分组。文件轮转、WS重连或手工把同一负载拆成几段，不制造独立episode。

优先以不同正常使用过程、不同时间窗的完整热周期分组；保留待机→任务启动→任务运行→任务结束→回落、再次启动等过渡。相同持续热状态跨相邻文件需保持同组。无法判定独立性就报告，不声称拥有大量独立样本。

### 8.4 时间隔离

采用从早到晚的训练/验证/测试episode，不随机打散行。至少要有三段可分配的真实过程才能给出第一版探索性报告；不足时仍可完成程序和模拟验证，成绩写“待真实数据”。

更可靠的初轮安排是有训练、验证后，留下至少两段没有参与调参的测试过程。**这是证据要求，不是要求用户先按固定次数做一套专门实验**；先正常使用，程序告知已积累什么、还缺哪类过程。

任何原始输入的支持区间 `[t-180秒, t+90秒+标签容差]`不得同时用于两个分区。按原始时间区间验证purge/embargo，不能仅给`TimeSeriesSplit`一个行数gap就忽略实际时间。[E5]

若只有一段长录制，可以前后分块留隔离带作为探索，但标“同一热过程的时间外推”，不能用它证明跨过程泛化或升级长期旁路候选。

切分清单需含源文件哈希、时间范围、episode/segment、丢弃理由和每个样本原始引用。冻结后不重洗牌、不挑好看的测试段；看过测试成绩又改模型/特征，旧测试就成为已使用资料，新的确认需新留出过程。

## 9．怎样判断价值，而不是只交“训练成功”

### 9.1 先把覆盖率摊开

每个方法/时距都报告：总计划预测起点、输入可用、预热中、方法输出、fallback、没有未来标签、跨断段、可评分数量；提供按时间与按episode的汇总。

比较准确性使用相同起点/相同标签的交集，覆盖率另外单列。不能因为复杂模型只在最平稳的时刻出结果，就宣布它比基线更好。

### 9.2 必报指标

- MAE、RMSE、绝对误差P95；偏差均值；欠预测 `max(T真实−T预测,0)` 的P95和最大值；过预测对应指标。
- 每episode一行及等权宏平均，同时保留全时间加权汇总。不用一段长待机压过短负载的失败。
- 以历史温度方向或用户任务标记划分稳定、升温、回落、重新升温；另列较高温度区间（仅诊断，不修改控制阈值）。没有该类数据写未覆盖。
- 45秒主对照；15/90秒不得因为差就删掉。正常过程与数据/设备异常分开。
- 至少输出几段成功与最差片段的原始引用，图中预测按目标时刻对齐，不能把“发出预测时刻”和“所预测未来时刻”混画。

不使用“准确率80%”、自造模型置信百分比或套用其他项目预算。相邻时间行高度相关，没有适当分组分析不输出貌似精确的总体置信区间。

### 9.3 决策与停止

软件完成、数据可用、模型有价值、允许实际控制，四种状态独立。

第一轮可以给出：
1. **有初步新增价值**：M1在相同留出起点比简单基线和M0更好，且改善不只来自长待机；较差场景与覆盖代价已列明。
2. **只证明小模型有用，未证明更多输入有用**：M0有效，M1没增加稳定收益。保留M0，不为了用齐数据而保留M1。
3. **暂未证明新增价值**：没有稳定胜出，或欠预测/覆盖代价明显。保留采集和基线，不继续自动换模型/增加搜索。
4. **证据不足**：热过程/数据/部署身份不足，准确说清缺什么；不冒充算法失败。

不要预设必须赢，也不凭首轮没有赢永久否定热建模。本轮不制定未经实测支持的“必须降噪X%”目标。

提出实时旁路候选前，至少需要软件回归通过、真实数据质量合格、冻结模型、未使用的过程对照、资源测量及欠预测风险说明。**它仍只有观察权限**。模型是否长期使用由产品负责人看报告决定，不自动部署或激活。

## 10．实时旁路的行为

- `collect`和`shadow`使用同一采集器，不能同时启动两条重复连接。没有模型的collect仍能正常工作。
- shadow每次先持久化预测记录（含起点、模型哈希、输入样本键与截止时刻、预测值、方法、质量/降级原因），之后才能看到未来标签；追加评分记录，不覆盖预测。
- 已有预测的评分有最大等待 `90秒+标签容差`；到期无数据就失效，等待队列有界。
- 只读连接断开、fresh失效、schema不支持时停止新模型预测；恢复后按身份和预热条件重建。UI显示“数据暂不可用，预测已暂停”，不是继续显示旧值却标实时。
- 超出训练输入范围可标“超出已验证范围”；不裁成范围内后隐瞒。不是校准的概率，不用“可信度97%”。
- 模型切换只接受明确的本地命令，在run/segment边界进行；每个预测带身份。不可悄悄在线训练或热替换。
- 正常关闭TTO只停观察。现场确认应停止/启动TTO本身，不是停止供温服务来检验它是否独立。

预测准不等于可以降低PWM：当前PWM40%时温度正常，不能推导PWM30%也正常。闭环数据里的PWM系数可能同时包含温度升高引发调速的相关性；**不把回归系数解读为调风扇的因果效果**。

## 11．CLI与用户交付体验

以下命令是**需要实现的接口合同**，不是现在已经存在的软件。配置示例见`config/tto.example.json`。

| 命令 | 行为 |
|---|---|
| `tto doctor --config ...` | 默认离线检查配置、路径、模型/合同版本，不连接设备。 |
| `tto doctor --config ... --live --duration 180` | 用户运行或授权后，只读检查明确端点，限时形成数据入口报告。 |
| `tto collect --config ... --duration 1800` | 用户运行即授权这轮指定端点只读采集，默认30分钟；不中断任何源服务。 |
| `tto summarize --run ...` | 离线给出质量、缺项、过程数量、采集开销和下一步。 |
| `tto split --runs ... --output ...` | 离线生成时间/episode切分清单；完成后冻结。 |
| `tto train --dataset ... --split ... --output ...` | 训练区拟合、验证区选择，生成冻结模型；不偷读测试区调参。 |
| `tto evaluate --dataset ... --split ... --models ... --output ...` | 对冻结测试区一次评估，保存完整结果与已使用记录。 |
| `tto shadow --config ... --model ... --duration 1800` | 用户确认后固定模型只读旁路，与collect共用实现。 |
| `tto report --run ... --output ...` | 生成JSON＋Markdown＋可直接打开的自包含HTML，无云端/CDN。 |
| `tto demo --output ...` | 完全离线固定模拟数据贯通，所有页面明显标“模拟演示”。 |

`security.default_live_access=false`表示导入、离线命令和不带`--live`的doctor不得外联；`collect`/`shadow`是明确的联网命令，只有用户自己运行或已经记录用户对应授权时才执行，不把该默认值理解成它们永远不能工作。

配置优先级：显式CLI > 明确TTO环境变量 > JSON配置文件 > 内置默认。先选生效值再校验，非法被选值不静默回退；未知配置键报错。环境变量只接受文档列出的键，不读取WS项目`TEGRASTATS_*`来暗改TTO行为。

端点默认空；不自动发现扫描内网。输入base URL不能带user:password；凭据通过本机保护文件或明确环境名引用，不写入日志/manifest/HTML。TLS验证默认开启，自签证书使用显式CA，不默认关闭验证。

常用中文反馈：
- “已连接，正在等待第一份有效温度数据。”
- “收到的是重复缓存，本次没有新增测量。”
- “风扇状态暂不可确认；本次只记录温度，不使用多输入模型。”
- “正在积累最近3分钟的温度历史。”
- “程序已经可用，真实数据还不足以判断预测效果。”
- “记录达到本轮上限，已停止TTO；现有风扇控制未被修改。”

不把schema、epoch、identity superseded等内部术语直接丢给普通用户；技术详情保留在可展开项和JSON中。

报告第一页回答：连接是否可靠、数据够不够、模型比简单办法好在哪里/差在哪里、下一步只需做什么。细节附后，保留原始数字与反例。**第一轮不建设复杂仪表盘、账号系统或手机App。**

## 12．实施顺序与交付里程碑

### A：建立新项目与合同（不用设备）

检查用户指定目录/Git状态，保护文件；创建README、必要.gitignore、配置模板、依赖与输入合同。登记两个参考项目和WS最终部署尚待确认项。不得从旧main生成缺少修复的假服务替代部署候选。

### B：记录与数据质量（可先全部模拟）

完成Orin/ESP32适配器、只读策略、时间/身份、去重、缺失、生命周期、有界存储、doctor/summarize、离线demo与测试。**到此先交一个真正能用的采集版本，不要等模型训练才给用户用。**

### C：模型与评估工具（没有实测也能编码）

完成共用特征器、样本/标签、切分泄漏检查、四个方法、冻结模型文件、报告与模拟全链路。合成结果只用于正确性测试，不能写真实性能结论。

### D：真实数据检查与离线比较

用户部署WS并运行/授权只读采集后，先确认真实输入合同、配置与质量。利用正常使用产生的数据；执行方按已经批准的本轮范围完成训练与评估，不每段数据都再问。确实缺资料时只交清晰的单一缺口，继续其他可独立工作。

### E：候选实时旁路

D有可解释的价值或需要观察的明确问题后，向用户交固定模型和只读启动命令。用户确认运行窗口后验证资源与连续预测；没有长期常驻授权就不安装systemd服务、不加开机项。

以上是一次TTO v1任务的阶段，不是五个需要重新设计的项目。执行端必须维护 `PROGRESS.md`，记录已实现/已测试/待真实数据/待用户授权/失败与原因，避免对话变长后重新从头设计。

## 13．最低验收矩阵

每项标：未做／通过离线／通过真实只读／不通过／缺证据。测试名称可自定，不能把测试数量当成产品效果。

| ID | 场景 | 必须证据 |
|---|---|---|
| A01 | 导入、help、doctor默认 | 零设备连接、零服务启动、零Git写入。 |
| A02 | 实际Socket.IO本地服务→生产客户端 | 正确event/namespace/heartbeat/reconnect；不是仅调用回调函数。只监听loopback。 |
| A03 | 业务只读限制 | ESP32写接口/任意路径/重定向/错误目标被阻止；Orin无业务emit。允许必要协议握手。 |
| A04 | auth/配置错误 | 不泄露凭据、不回退生产默认IP、不反复猜口令；CLI优先级贯通。 |
| D01 | 同sample多次重发 | 一份测量、最多一个预测起点；年龄不被续期。 |
| D02 | 同数值但seq增加 | 多份真实输入，正确记录，不按内容hash去掉。 |
| D03 | seq倒退/跳号/同身份冲突 | 有明确拒用/缺段事件，不静默覆盖。 |
| D04 | 源stream变更、断线重连、旧回调迟到 | 旧数据不污染新段，断段窗口不评分。 |
| D05 | fresh=false、state停止、无首帧/未知schema | 无新模型预测；旧值显示为旧/未知。 |
| D06 | UTC跳变、local monotonic epoch变化 | 不靠UTC判年龄；不跨run拼单调时间。 |
| D07 | 缺GPU温度、缺rail、0功耗 | 缺失与0分开，TJ正常时采集继续，M1降级明确。 |
| D08 | duty未知/请求70但成功37 | 使用37或未知，不用70冒充成功，不把rpm0当停转。 |
| D09 | Orin/ESP32返回相位错开 | 输入available_at不晚于预测；没有未来fan数据回填。 |
| D10 | 慢接口、超时、断网风暴 | 请求数/连接数/重试频率有界，不追赶补发，无进程堆积。 |
| R01 | 队列满、慢盘、满盘、文件上限 | 显式丢弃/断段/停止，旧证据不被覆盖，现有控制零写入。 |
| R02 | SIGINT/SIGTERM、重复停止/启动 | 只清理TTO资源；无锁重入卡死、无测试子进程遗留。 |
| M01 | 离线/实时输入同一序列 | 特征、方法、预测数值同合同；冻结浮点容差，身份/时间/资格必须一致。 |
| M02 | 篡改预测起点之后全部数据 | 起点特征和已发预测不变；仅未来评分可能改变。 |
| M03 | 切分/缩放/字段选择泄漏 | 训练输出不依赖测试值；原始支持区间无分区重叠。 |
| M04 | 无标签/超容差/跨段 | 明确不可评分，不能填0、复用旧TJ或跨stream补答案。 |
| M05 | 长待机＋短负载 | episode等权与全时间统计均正确，困难场景不被淹没。 |
| M06 | 模型文件被篡改/NaN/错维度/错合同 | 拒绝模型、继续允许采集，不加载任意可执行对象。 |
| M07 | 缺数据/无稳定收益 | 正确输出待数据/未证明收益，不产生虚假通过或自动换赛道。 |
| M08 | 固件趋势参考比较 | 只作观察诊断，不用它当训练标签或证明可减少PWM。 |
| P01 | 干净目录安装wheel后运行demo/测试 | 正式入口引用交付源，不依赖作者缓存、绝对路径或装机状态。 |
| P02 | N305资源与网络负担 | 实际RSS/CPU/P99/消息率/漏期结果，主机模拟与目标机分列。 |
| L01 | 用户部署后180秒只读doctor | 新包身份/合同/TJ/seq/age/功耗与正常连接结果，待执行不预报通过。 |
| L02 | 用户普通使用与关闭TTO | 可采集完整正常过程，停止TTO不发任何控制/源服务操作；现场效果不从mock推定。 |

离线测试默认阻止外网/生产IP、真实tegrastats、SSH、systemctl/journalctl。Socket.IO集成使用明确的本机服务替身，不启动原项目ModelMonitor。解析/拟合单元测试可用fake clock；至少一次真实本地网络/文件/信号贯通，清楚记录边界。

**B．`TTO-v1-实施证据包.zip`**：最小完整源码、配置模板、CLI使用卡、wheel/依赖锁、固定模拟数据、可复现测试、模型/切分合同、日志、文件SHA-256与一条离线重跑入口。无.git/venv/cache、无原始私密任务、不塞入旧的大风扇包。

取得真实数据并训练后再追加：冻结模型JSON与SHA、训练/验证/测试manifest哈希、每个预测原始引用、完整方法成绩及坏例。未经用户授权不把完整实测原始数据打进可分享包；可另给本机可重跑清单，明确外部复审缺少原始数据时的边界。

保留增量变化与版本，不使用一个不断覆盖的`latest`结果冒充所有历史；缺依赖、未跑实机、失败后修正分别记录。
