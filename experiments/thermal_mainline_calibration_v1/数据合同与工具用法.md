本版使用 `TTO-G2-MODELING-DATA-v1`，不直接猜测现场厂商日志字段。完整例子在 `inputs/dataset.json`；由原质量引擎的 accepted 证据经字节不变的 R2 `data_views.py` 派生。重建脚本已用旧封存归档实际验证，输出 SHA 完全一致。

每个 `runs` 对象保存实际 run UUID、device/config、角色及时间范围；每个 `segments` 对象保存真实质量断点形成的严格段、成功 PWM 与独立两 rail 的有资格输入时间线。TJ 单位 °C，rail 单位 W，rows.duty 是百分数，timeline.inputs 的第三项是 0—1 分数。输入两 rail 不相加；5V/gain 不作为额外热功率或物理冷却输入。

`examples` 保留全量约一秒 TJ 起点，含 source_valid、ready、原引用、过去趋势、逐时距标签/拒绝原因、质量/控制上下文。A 必须有完整未来输入路径；B 可以有合法 TJ 答案而未来输入不完整，按原 R2 分离规则评价，不将未知控制状态标成正常。阶段只用于事后分层。标签是目标以后最早合格 TJ，容差 2 秒，各时距独立，不插值、不跨真实身份边界。

当前例子 L 2529、M 2504、S 1610 个 TJ 起点，共 6643；58 个质量严格段不等于 58 个独立热过程。M 的三个工作块仍是同一 run，不因工作块切换重置。L/M/S 都已分析；Y/fixed-anchors 同属已查看资料，本轮未重新训练或重算其排名。行政配置标识中的 `unverified-revision` 明示物理版本未知，不是已核实硬件身份。

真实执行过的三个命令如下，重跑时必须改为新输出目录：

```sh
python -m tool generate --job config/generate.json --parent baseline/frozen-model-manifest.json --output runs/generate
python -m tool calibrate --job config/calibrate.json --parent runs/generate/model-bundle/model-manifest.json --output runs/calibrate
python -m tool compare --plan config/compare.json --output runs/compare
```

generate 用原 G2 结构、约束、加权 Huber 和 N1—N6；calibrate 将 N1 替换成父模型 θ，另用 N2—N6。校准仅拟合 M，L 只通过父 θ 初值参与，没有增加保留 L 的惩罚项，也不冒称联合 L+M 训练。M 是相对该父版本新增的历史开发资料，绝不是本轮新盲测。未来的校准需显式批准新资料、冻结新 job 的 SHA；不能把 parent 已拟合的同一 run 换名字后再称新增。校验比较真实 UUID；新生成包同时写实际训练/验证 UUID。两个本轮先行示例保持原字节，只按其精确训练数据 SHA 绑定的旧角色表解析；不能用调用者新给的别名表猜旧来源。

两个操作都在独立工作进程中有界执行，600 秒/2048 MiB/最多六初值；每初值最多 300 nfev/1500 次真实残差调用。没有质量合格段或只有平稳输入时返回明确 insufficient，不制造新系数。未收敛的输出只保留诊断身份，不允许登记后选择为观察版本。

候选包复制同一纯计算运行时；新 primary、observer-spec 和 manifest 独立保存。只改候选 spec 的动态参数与身份，原 observer 数学和因果先验不变。调用候选时显式传 `Predictor(候选/model-manifest.json)`；命令行用 `python -m g2_runtime --manifest 候选/model-manifest.json --input 请求.json --output 新文件.json`，模块来源需是该候选包。输入状态也必须来自该候选 spec、相同设备/run/时钟及原 TJ 截止，不能复用另一模型的运行中状态。

登记和版本选择示例（均只读本地模型文件，不触达观察进程/风扇）：

```sh
python -m tool register --registry 新目录/registry --manifest baseline/frozen-model-manifest.json --device-id RM01-reference-LSM --thermal-config-id RM01-original-development-config-unverified-revision
python -m tool register --registry 新目录/registry --manifest runs/generate/model-bundle/model-manifest.json
python -m tool register --registry 新目录/registry --manifest runs/calibrate/model-bundle/model-manifest.json
python -m tool session-open --registry 新目录/registry --session-id session-before
python -m tool activate --registry 新目录/registry --model-id G2-GEN-L-20261021-v1 --confirm --reason 离线演示
python -m tool session-open --registry 新目录/registry --session-id session-new
python -m tool rollback --registry 新目录/registry --model-id G2-FROZEN-RM01-v1 --confirm --reason 离线回退核验
```

同一 model_id 不允许登记不同字节，校验所有包文件 SHA，保留父版/冻结参照才允许选择。每个 registry 绑定一个 device/config，不共享热状态。activate/rollback 必须有显式确认和理由；只影响未来新建会话，已经打开的 session pin 不变。演示最后已回到冻结版；没有运行中模型热切。新进程应按 pin 的 manifest 新建该模型观察器，本工具本轮未集成到生产模型加载或现场准入。

`config/future-data-policy.json` 在新观察资料到达前固定规则：按设备/完整实际 run 分组，时间在前的完整过程校准，后续完整过程确认，最长 90 秒标签不越界。v1 明确支持完整 run 的不相交划分；同一长 run 的业务会话切分不自动执行。若以后采用，须先登记真实会话边界、过去状态预算和 90 秒保护，不能用相邻秒随机切分，不能把 field/modeling 当两轮。只有一个新过程时仍可生成候选，但确认结论为证据不足，不自行补测。

评分采用 `LEGACY-R2-PAST60-REPLAY-v1`：各模型一致用过去 60 秒初始化；首个有资格前缀估计该 run 的 E，随后固定；滚动起点只用过去窗口估计 Ts，以当时实测 TJ 为 Tf 锚点。A-long 前缀以后不再吸收 TJ。M 的 24°C 没有被拿来固定 E；Ts/E 仍是潜变量/等效量。

HOLD 保持起点两 rail/PWM；RELAX30 保持 PWM、两 rail 向 min(当时值, 对应训练 P10) 以 30 秒时间常数指数回落。各模型的 P10 只来自各自拟合侧，是原策略的一部分，全部写在包内；不读未来真实输入/任务结束。两种情景整表分开，不能逐点挑赢家。

历史 compare 的过去窗口状态初始化不是新实时观察器 KF。新实时 API 使用 `TTO-RECEIVE-ANCHOR-v1`，target=原 TJ 接收+h，实际发布时刻只减少剩余提前量。两种时间/状态合同分别存证，不能混排。测试线发布器负责最终真实写入时间和 late 撤销；纯计算接口不把计算开始时刻伪称最终写盘时刻。
