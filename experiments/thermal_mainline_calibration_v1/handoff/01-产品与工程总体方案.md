# 产品与工程总体方案

## 1. 这次要交付的两个成果

### 产品经理视角

**成果A：冻结模型观察版。** 将已取得收益的G2保留下来，作为能在真实机器日常运行的观察能力。用户可以看到当前TJ、模型快慢状态、未来15/45/90秒条件预测及成熟后的误差；某一来源有缺口时不再整套退出。

**成果B：模型生成与校准工具。** 同一软件面对一份新的有效记录，可以生成该设备的候选、和旧版比较、说明是否适合替换。初版允许离线或周期执行与人工确认；后续再允许持续候选生成和受控自动启用，不能把状态更新冒称参数学习。

成果A无需等待成果B优化成功。成果B无需等待CPU先导、Web UI、外部探头或所有通讯缺口消失。

### 工程师视角

沿用G2拓扑、原生数据质量与已接受估计器。冻结原primary/spec/实现；构建新发行封套、新observe入口和可重复的工具接口。收集、估计、预测评分、训练候选、执行负载、控制风扇各自分工，不靠单一qualified字段决定全部生命周期。

## 3. 软件职责整理：最小改动，不重写平台

建议模块边界：

```text
原生只读采集 → 原始日志与原始质量
                  ├→ 冻结G2状态估计 → 条件预测 → 成熟标签评分
                  ├→ 事件/健康/运行摘要 → Web UI或只读导出
                  └→ 显式选定的训练数据 → 新候选 → 比较/人工启用

独立实验执行器 ← 现场授权 + 真实设备保护/控制条件
天山OS原控制与保护 ← 保持原样；不接本阶段TTO写指令
```

- 原始日志先保存；估计器错误、晚到或暂不可用不能让其他原始数据自动丢失。
- 不新建第二个质量引擎或第二套HTTP/WS轮询。估计消费缓慢时使用有界队列/已落盘序列及明确落后标记；绝不能无界堆内存、静默跳样或通过更改源采样止损。
- 如为保留已验收状态语义需要维持串行调用，可用最小异常隔离及有界处理；是否另worker由实测必要性决定，不强制微服务/多进程。
- 普通fan过期只撤销该来源资格，按原估计器的短缺口/长缺口规则降级或停模型输出，原始TJ等仍记录。明确guard/fault也保留真实事件，可停止模型建议，但只读记录不因此变成控制动作。
- 原运行环境单线程规范与同PID回执作为每次实际run身份；不增加全机环境修改，不影响推理服务的线程设置。
- 新observe不创建Requester，不调用模型列表/推理API，不要求YET/CPU sidecar/实验actor ID。原execute入口及设备保护不因该拆分放宽。

## 4. 小批试跑建议（不是已经确定的设备数量）

建议首批**最多3台：当前参考机 + 两台同散热结构/同模组优先**。设备不足就先现有一台持续运行，不等待凑齐。型号不同的机器只在字段语义核对后加入单独配置组；原模型直接迁移仅作探索，不称已适配。

建议每台观察上限24小时。首台前2小时为运行健康检查点，通过后在同一已批准窗口内继续；再加入批准清单里的其他机器。一天仅是首轮观察预算，不是自动足够校准的数据量。默认业务照常、TTO不主动发负载。

这是**先安装成熟的观察能力，后以新数据推动校准**，不是把未验证模型交给风扇。真正落地时由用户确认设备与时段；本轮软件开发不等待这些信息补齐。

## 5. 模型开发为什么现在应重新启动

### 产品经理视角

冻结现有收益，解决“已经有一个有用模型却一直无法交付”；生成/校准解决“以后换硬件怎么办”。两者并行，而不是等所有场景完全准确才给用户用。

### 工程师视角

- 冻结θ的状态更新继续按原先验和E估计工作；E不是室温，不复制M24°C。
- 新生成候选可调整θ，但生成新model_id，不改primary原件。
- 初版复用既有G2辨识代码/损失/边界，封装流程，不另做模型族搜索。完整生成和以当前模型为起点的校准共用同一有限求解器。
- 新硬件可能需要新参数或新结构，但结构扩展必须由“输入已知仍有可重复动态残差”的证据触发，不现在一律加阶数。
- 学习优先后台或离线周期执行，不在1秒估计路径中做优化；不会因为训练失败停止观察。

## 6. 之后才做的两件事

**受控在线校准：** 有合格数据时自动生成候选、先用后续数据比较，再允许观察模型替换并可回退。是否递归逐点更新以后按数据价值/资源决定，初版不承诺每秒自学。

**实际风扇收益：** 明确有合法PWM映射和独立试验方案后，才在单台做实际控制对照。当前接受用户确认的转速—噪声方向，先以真实RPM/经核实PWM的相对趋势与听感评价；精确dB收益需要对应声学测量，不能拿影子建议代替已实现降噪。该阶段不要求先证明CPU先导或所有跨机型泛化。
