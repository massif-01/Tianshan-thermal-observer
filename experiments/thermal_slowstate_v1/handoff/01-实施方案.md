# TTO：快慢热状态核对与平稳散热需求——离线实施方案

**编号：TTO-SLOWSTATE-v1.0｜日期：2026-10-14｜执行方：灰箱辨识／对照实验Codex对话。**

## 0. 本轮的产品决定

本轮不是继续42次参数拟合，也不是固件返修。复用第二轮已冻结G2，真正导出快／慢状态，检验慢状态是否比简单滤波提供额外信息，并做一个**不连接设备、不输出实际PWM的慢热需求信号原型**。

用户明确的产品目标：在温度安全、性能可维持的条件下，日常散热尽量安静、平稳；不要把每一个短TJ尖峰复制成风扇的一次明显升降。频繁短任务可以形成适度稳定的平台；任务结束后允许有依据的继续散热，但不追求无限冷却或无限保持高档。

优先级相对上一轮建议作如下调整：

- 从“先改善所有45秒未来输入预测”调整为**先确认已有模型中的慢热状态能否支撑上述产品目标**。
- HOLD／RELAX30及旧TJ误差原样保留；未来输入策略研究暂缓一轮，不取消、不包装成已经完成。
- 旧短任务“提前退档许可”只作为历史独立原型，本轮不实施；不能把“越快返回最低PWM”设为当前唯一目标。
- 本轮不证明真实降噪、低PWM仍然安全、物理热容、TTP温度或跨硬件通用性。只是把下一步的模型信号和控制接口依据做实。

这不是否认已有短峰误差，而是明确：**TJ预测、慢热状态、风扇输出必须分别定义、分别评价。**

### 1.2 四种曲线不可混同

| 名称 | 真正含义 | 本轮允许怎样评价 |
|---|---|---|
| 实测TJ | 芯片最高结温相关的观测目标 | 保留原始尖峰、源身份、质量与时间 |
| `Tf_hat`／旧图中的G2 A-long | 原G2输出方程的TJ估计：`y_hat = Tf` | 继续对照TJ；欠峰/迟降仍是这个输出的误差 |

用户关于“大热容把短时热脉冲在结构中展开”的判断是模型研究动机，不是现有`Tf_hat`已经测准铝体温度的证据。**不得把原图里偏矮的Tf曲线改名成Ts，就宣称解释成功。**

“延后撤掉额外风量”是一种可选择的控制策略；“模型误报TJ还没降下来”是另一件事。好的系统可以同时报告TJ已降、慢状态仍高，并选择适度继续散热。

### 1.3 CPU/GPU共同工作与有效输入

正常推理里主机调度、设备计算可以共同活动。这里的`VDD_CPU_SOC_MSS`不是纯CPU功率，必须保留全名。功率高度相关不等于数据错误或温度模型不可用；它限制的是分开归因与超出已见功率比例的迁移。

本轮继续保留两rail，不强制安排CPU-only/GPU-only实测，不擅自合并为整机总功耗。可导出冻结模型的

`q_equiv = b_g * P_g + b_c * P_c`

它是模型快状态方程里的**等效驱动项，单位°C/s**，不是实测W，不是总热量，也不能由b_g贴零推出GPU不发热。5V与其他温区继续留诊断。

## 3. 第一步：固定含义，先把真正的Ts画出来

### 3.1 主模型与诊断副本

主候选固定为第二轮 `runs/main/fits/D-LSM-G2/model.json`（Efree）。它使用过L/S/M，因此结果标为开发/拟合内状态研究。

状态稳健性只增加两个**已有冻结**参照：旧LS-fit G2，以及D-LSM-G2-A24。它们只用于比较潜在状态在可比信息预算下是否稳定，不挑一个Ts曲线更漂亮的替换主候选。

已封存的旧LS-fit在M未用M拟合动态参数的事实继续保留；前缀校准仍须披露。

### 3.2 两套状态轨迹分开输出

1. **A-long同源状态**：按原记录的过去前缀初始化及原输入传播，导出两维状态；之后不读TJ反馈。应复现旧A-long的Tf，补出同次传播的Ts。不能把训练全段拟合初态拿来冒充因果前缀。
2. **因果在线可用状态**：优先读取原`states.jsonl`，其每个起点只用过去60秒；`state[0]`已锚到当前TJ，必须注明“观测锚定”，不能把它对当前TJ的零误差算成预测本领。`state[1]`才是该估计器的慢态。缺失处按固定原方法重放到该起点，不看未来。

这两套状态不能拼接成一条最优线。原证据`plots.py`取的是`A['G2']`作为Tf输出，`vendor/v1/initialize.py`保留了慢态估计与证据范围；沿实际字段核对。

每点记录：run/ref/segment/UTC与本机单调时钟、Tf来源、Ts、E、当前输入、有效截止、初始化窗口、原始引用、模型SHA、估计方法。不要跨run相减单调时间。

### 3.3 先查可使用性，不靠“平滑看着对”判断

检查原60秒状态估计中Ts是否在滑窗重估时出现跳变、贴边或异常漂移。源缺口前后断开，不能补一条平滑线。M的三个工作块不得新建慢初态。

旧LS、现D-LSM、A24之间分别比较：绝对Ts差异，以及相对于各自合法前缀参考的增量差异。后者有助于看形状，但不能用每段自由平移、全段归一化把不一致藏掉。参照若初始很热，也必须保留“非冷机、非平衡”的身份。

不增加新的卡尔曼滤波器、第三状态或观测校正模型。若现有估计器产生不可用跳变，明确给出证据和最小后续方向；本轮仍完成其他能够完成的对照，不对着旧数据无限调估计器。

## 4. 第二步：检验慢态的信息价值，而不只比谁更平滑

### 4.1 预登记的四种慢态来源

保持**同一个D-LSM G2的θ、run E、当前实测Tf和未来输入情景**，只替换起点的慢态。这是诊断性消融，不是重训练四个模型。

设 `d(u)=d0+d1*u`，则固定当前Tf时，使慢方程导数为零的代数状态为：

`Ts_qs(t) = [c * TJ(t) + d(u(t)) * E] / [c + d(u(t))]`。

四条分支：

- `STATE-G2`：原过去60秒得到的Ts。
- `STATE-QS`：使用当前`Ts_qs`，不保留慢历史。这不是测量，只是去掉慢记忆的对照。
- `STATE-LP30`：对Ts_qs做仅使用过去的30秒指数低通。
- `STATE-LP120`：相同的120秒指数低通。

低通使用真实Δt，按左持有输入精确递推；起点初始化为本严格段首个合法Ts_qs。不得用居中平均、filtfilt或未来数据。run E只能在其首次前缀完成后固定；在第一个可评价起点可因果回放该已发生前缀，但不能对前缀内早期时刻宣称已知最终E。

前60秒均视为起点准备，不称120秒滤波已到稳态。段内过滤历史可持续累积；原G2使用固定60秒窗口。这种记忆差异明确报告，不为了齐分数改窗口。所有方法只用已发生信息。

### 4.2 分别做两种温度检查

- **A-roll诊断**：四种起始慢态各自传播15/45/90秒，给定记录中的真实未来两rail与PWM，禁止未来TJ反馈。检验慢态差异是否影响可观测的温度响应。
- **B-HOLD诊断**：同起点、同四种慢态，未来输入均为原HOLD；不知道下一次任务这一限制对四者相同。旧RELAX30继续作为历史诊断，不在本轮创建新请求状态选择器。

冻结参数不变、初始化信息预算和标签规则按现有合同记录。A需要完整未来输入；B的未来辅助缺口按TTO-EVAL-AVAIL-v2.0分层，不删除本来合法的温度答案，不补当时不存在的预测。B0及既有Ridge成绩保留参考，不必重训。

主比较用共同起点/同一标签并列覆盖，逐run与负载/回落/背景分别报告MAE、偏差、P95与最大欠预测。误差保留未裁剪原值。补缺口后的离线回放必须标新派生结果，不假称现场已经发出。

**这能提供慢态是否有用的证据，不是Ts真实温度的直接验证；QS/LP也不是经过最优化的所有简单控制器。** 若简单滤波表现相当或更好，如实报告，不能因为项目强调模型就删掉它。

### 4.3 时序、风险和实际目标并列

重点窗口：S全部稀疏/连续短问答，L负载开始/结束，M三块与0–5/5–15/15–45/45–90/90–300秒回落。

沿用原事件窗；被后题影响、缺峰、辅助缺口与异常恢复分别标记。保留“原输出Tf对TJ的短峰误差”；另说明其对当前无控制权的产品阶段的实际影响，不要求每根低风险尖峰都完美才允许研究慢控制。

不将原未来45秒MAE唯一化为整个TTO成败指标，也不因本轮强调平稳控制便取消它。快风险、慢状态、控制平稳是不同栏目。

## 5. 第三步：做一个离线的平稳需求信号原型，不直接计算可部署PWM

### 5.1 为什么本轮只到需求信号

潜在Ts尚无实测体温标定，也没有确认新风量下的热响应。直接把Ts喂原TJ—PWM曲线，等于把两种不同量当同一个量，可能制造虚假的低档收益。

本轮实际实现一个**增量型、无量纲、只用于对比形状的需求信号**。它只是下一步控制接口的原型，不是“最佳风扇档位”。它为0不意味着风扇可以停，也不意味着当前机器没有热负担。

### 5.2 一个固定、可重跑的原型，不做网格搜索

在每个严格连续段第一次具备合法因果状态的时刻t0，分别固定各慢态分支的参考值 `s_ref=s(t0)`。它是该段的增量参考，不是环境温度/冷机状态。若段首已经热，增量信号不能表示绝对冷却需求；图上明确标记。

为每种慢态来源（G2/QS/LP30/LP120）使用同一映射和后处理：

```
z_raw(t) = (s(t) - s_ref) / 10.0
z_target(t) = clip(z_raw(t), 0, 1)
if abs(z_target - z_previous) <= 0.02:
    z_output = z_previous
else:
    z_output = z_previous + clip(z_target - z_previous, -dt/120, dt/30)
```

10°C只作为同单位增量的展示尺度；0.02死区、30秒全幅升量、120秒全幅降量都是**本轮预先固定的信号塑形参数，不是物理热常数、声学最优参数或固件值**。不输出0–100%标签，不作PWM换算。raw、clip前后、触发原因均保留，饱和时间单列；不能靠削峰截断隐藏状态继续上升。

所有分支用相同后处理，不能G2加平滑、对照不加。Ts下降后保留适度尾部是允许的信号行为，但更长不自动更优。

实际PWM只作另一坐标的现场参考。**不把新信号代入状态传播后仍沿用实测TJ声称闭环安全；也不将本模型同时当控制器和唯一验证对象，宣布自己证明自己。**

### 5.3 快风险通道与边界接口

输出分两部分：

- `normal_extra_demand_index`：上述普通慢热需求原型。
- `fast_status`：从原记录读到的测量、保护/故障/失温/当前输入资格等。保持原始TJ，不能用Ts或平滑TJ掩盖。

明确保护/异常、当前资格不足或源身份变化时，普通原型输出null并记录“不可用/应由既有控制负责”。恢复后按原历史资格建立状态；不能拿上一条信号续龄。检测这些已提供标记不需要等慢滤波、死区或下降时间常数。

本轮不构造适用于所有Jetson的温度保护阈值，也不把现有固件每个普通高PWM都当硬保护。原保护行为保持原系统执行；研究工具无硬件写入口。

### 5.4 该报告哪些行为

每个分支原始/塑形后信号的总变差、峰谷幅度、≥0.02的有效方向反转数、饱和与不可用时间；稀疏任务之间的残留、连续短任务的平台程度、持续负载时需求是否增加、结束后何时回到本段参考附近（仅描述）。

同时报各段信号幅度，不把“永远输出0”当最平稳的优胜者。没有温控后果与声学证据，不能给出真实风量/噪音收益排名。

## 6. 一份有限的数据诊断，不再要求把CPU与GPU强行分开运行

从冻结系数导出q_equiv，对三个已有G2参照比较其组合驱动与状态输出在已观测功率比例范围内是否稳定。b_g/b_c分别变化大，但组合输出一致时，结论是“当前工作负载域下的等效模型可能仍可用”，不是“参数全都坏了”。

功率比例跨域提示须标明当前采样支持范围；不改变rail名、不添加臆测热量，不把r接近1当源错误。除非本轮诊断明确说明必须，否则不得为分离两个系数追加CPU-only、GPU-only等现场前置测试。

本轮不重拟合q的系数；未来若转为组合驱动、降维或联合热源模型，需要另登记，不默改当前物理解释。

## 7. 真正需要的验证与交付

### 7.1 有限测试

只跑新增研究测试与直接复用函数检查，不重跑全产品/固件回归，不重算42次优化。

至少覆盖：

1. 曲线字段：旧A-long G2取的是Tf；导出的Ts不是Tf重命名，状态锚定当前TJ不当预测精度。

5. 滤波：真实不规则Δt、左保持、断段/恢复/预热，未来平均不得进入；M块切换不重置。
