# 04：只读任务事件与唯一执行链交付

合同 TTO-WORKLOAD-EVENTS-v1；本轮仅离线候选，无现场授权。

## 读取方式与语义

`events.Adapter.feed(row, received_mono_s=..., received_at_utc=...)` 接受已有 Requester 的追加式 `protocol.jsonl` 行，返回一个字典或 None。由测试线在自己的进程中读取已存在文件或本地有界队列并调用；适配器不启动线程、文件追踪器、Requester、collector，不访问模型或遥测接口。模型线只能消费测试线截至当前已收到的输出。`events.py INPUT --session-id ... --source-clock-domain ...` 只用于离线回放，publication_mode=replay；不是现场启动命令。

输入：event、native_run_id、request_id、mono_s、at_utc；终结行按原记录保留 status、done、finish_reason、usage、error_class、server_request_id。只消费 request_submit、first_content、request_cancel、request_end。忽略 scheduler 的未来阶段计划和 native collector 内部事件。源必须保证 session 内 request_id 唯一；boot/进程重启、新run须创建新适配器并重新绑定。

输出：contract、event、sequence、session_id、request_id；source_event_utc/source_event_mono_s/source_clock_domain；received_at_utc/received_mono_s/observer_clock_domain；publication_mode；client_inflight；terminal、done、finish_reason、usage、server_request_id、content_semantics；gpu_kernel_start/end 永远 null。时刻缺失保持 null，不用读文件的本机时刻冒充源时刻。sequence是去重后的发布顺序，不是原始行号。

首内容沿用已接受 Requester：非空 content/reasoning/reasoning_content 的第一个 SSE 增量均算；不是首个可见正文，也不是 GPU 开始。first_network_line 只是客户端首行，不等于网络首包。完成必须记录 completed + DONE + finish_reason，usage 可缺失但不能伪造。finish_reason=length 是达到上限，stop 是协议自然结束。两者均不证明 GPU 内核结束。

request_cancel 表示取消意图，暂不减在途；request_end 才关闭本地请求。取消/超时/断流/没有充分完成标志均输出 server_end_unknown，禁止当作成功或触发自动重试。客户端在途归零仍可有服务器未知尾部；它不能推出服务闲置。客户端在途只覆盖该 Requester session，不代表整机总请求数。GPU利用率是独立遥测；既不能反推请求数，也不能补齐内核起止。

## 缺失、重复与乱序

只有从 session 开始完整接入且无缺口时，测试线才可显式 complete_from_session_start=True；否则 client_inflight=null，不能显示0。从中途接入或只有最终 requests.jsonl 的历史记录，不反向发布“当时已知”的提交或首内容。没有业务事件源时，测试线直接保持 unknown，用户业务照常运行。

完全相同行去重；源单调时刻回退、身份不符、缺提交终结或队列丢失使计数未知，不按源时间排序偷偷回填。单调时刻只在同一个 source_clock_domain 内比较，不与 observer 的单调时钟相减。测试线看到文件截断/轮换无法接续、读入丢行、队列满、来源失联时必须调用 unavailable(reason)，保持未知直到可证明完整的新 session；重读旧缓存不能复活当前有效状态。

活动请求状态上限256，去重摘要最近4096条，超限输出unknown。文件追踪/队列容量与读延迟归测试线共享事件读取层管理；不得另起全局代理或再次轮询模型/设备。输出只描述事件发生/收到时状态，不声称可无限期充当当前快照；来源健康由测试线共享质量层标记。回放的 received_* 为 null，禁止把它混入当前业务。

## 唯一采集、唯一请求的接续

1. 日常 observe：测试线独占一个原生 collector，默认零 Requester；事件可缺失，业务可继续，不以新模型 tracking 决定用户业务能否运行。
2. 整个已批准自然窗口结束后，测试线汇总 coverage.json 的实际缺口；若缺持续工作/回落，仅提出本包一个补充场景。不自动延长、不默认重跑长短矩阵，不恢复 CPU6+6。
3. 获得具体设备/模型/窗口/请求上限的用户批准后，测试线停止 observe，归档 native UUID、最后源序列、实际停止时间与进程/任务关闭证据，释放唯一采集所有权。未证实关闭不得启动 execute。
4. 只由本推理对话接续唯一统一 execute，execute 自带唯一 collector 与 Requester；不在仍运行的 observe 旁起另一套采集。新run建立新身份和时钟锚，与前一run通过交接记录关联，不能冒充连续单调时钟。
5. 终止/未知尾部不静默重启；保留请求、SSE、取消、退出证据，停止发新请求并等待处置。归档后若再进入自然观察需新run和明确所有权转移。

旧 execute 的 formal、真实设备新鲜度、仪表/当前授权、安装身份、容量及模型驻留安全检查全部保留。不得设formal=false绕过。本轮没有改执行合同。长期将模型 tracking 从实验资格解耦的最小方案：测试线共用同一真实设备状态/当前许可对象，分别发布 collection/model/field_safety/authorization 四层；开始和持续发请求使用真实设备安全+许可，模型输出资格单独标记。须共同验证、复审后实施，当前候选不启用。

## 一个补充场景的候选边界

`supplement.py` 的默认 CLI **只打印计划**；run() 是未来统一 execute 的待接入 helper，无网络入口、不构造 Requester。复用 reference/requester.py 原样内容（来源SHA见reference/requester-provenance.json），不另造推理客户端。单路、最多24请求；原消息模板/stream/include_usage/max_tokens256、超时30秒及采样默认全部沿用；背景300秒、工作360秒、回落480秒，名义19分钟；包括准备最多300、末尾排空最多30、清理最多30的总上限1500秒（25分钟）。达到请求上限后不补发，剩余工作段只等候；请求开始前必须留足原30秒请求预算。未知结束立即停止后续请求，无重试；取消客户端不宣称服务器已停止。

调用方必须先核对身份、使用原 execute gate，创建并最终关闭已有Requester，保留旧检查，并在包含准备/清理的外层1500秒截止前停止。helper只负责阶段/请求预算，不能替代原运行器的身份、资源及退出审计。任一安全gate失效/用户STOP时停止等待或取消在途。helper已用虚拟时钟和替身请求验证，没有接到真实入口：旧runtime.profile()硬编码fixed-anchors且probe_profile只允许loopback。测试线须评审新profile登记和统一调度接入，不能把helper单独直连设备。当前尚不可宣称“新场景已现场就绪”。

新设备/模型/容量不同先登记新profile，本包历史RM-01参数不是当前驻留证据。若另行选择原fixed-anchors，则仍是原44.5分钟名义/60分钟上限；它不是本包默认补充项，也不与本项叠加。本轮未改旧入口。
