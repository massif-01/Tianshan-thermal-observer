# 决策冻结与旧任务替代

## 产品经理的决定

TTO本阶段交付目标改为：**已有模型可持续使用 + 小批真实观察 + 可重复生成与校准。** CPU先导只是一次没有获得当前增量证据的探索，不再占用主线进度。冻结已有结果不等于停止模型开发；新候选单独开发，旧结果不可覆盖。

## 工程执行规则

| 旧任务／规则 | 本轮处理 |
|---|---|
| CPU 200ms旁录、60秒能力循环、6孤立+6连续12请求 | 暂停；不再申请或自动执行。保留代码和失败记录，不做删除式cleanup。 |
| INPUT-MEAN/CORE活动→高功率先验 | 不进入主线默认预测。保留负结果；不调到在旧数据上赢为止。 |
| 普通原生CPU、GPU利用率／功率字段 | 继续原样记录。暂停专用CPU旁录不等于删除原遥测CPU字段。 |
| 为延续CPU旁录单独开发的诊断分层 | 不再作为独立CPU项目推进；通用故障隔离需要的部分转入持续观察版本。已有局部实现可复用，不重复造。 |
| 持续记录必须等模型tracking、5秒控制确认或负载许可 | 仅在新observe模式解除这种耦合；原始测量资格和既有execute安全要求不改。 |
| 2.5秒fan TTL／7.5秒temp TTL与原源新鲜度 | 本阶段保留；源到期是真实到期，继续记录不等于续龄或变正常。 |
| cpu.3单线程、同PID取证、I-02、准确停止时刻、唯一采集 | 接受并继承，不重复立项。不要直接把cpu.3的CPU实验入口改名就宣称持续版本完成。 |
| 每个小修都做一轮同样的60秒现场 | 取消为默认流程。一次集成交付后，按明确设备和窗口开展2小时起步/一天级只读观察。 |
| 风扇反馈周期性长延迟 | 保留为软件可靠性问题。允许有证据的最小修复候选；不强制先根治全部历史问题才可只读记录。 |
| 当前成果比TJ好 | 精确指：某次fixed-anchors共同集合中，G2-HOLD预测平均优于保持当前TJ的B0。不是已优于整套天山OS实际控制。 |
| 原模型文件内deployable=false | 不篡改成true。另建观察发行清单，明确仅经过何种只读运行验证；控制权限始终false。 |
| 新模型开发被“不重训”全面阻断 | 旧模型不重训覆盖；**允许新目录中的有限拟合／校准候选**，数据角色必须登记。 |
| Web UI旁路任务 | 不重做PRD、不把UI合入CPU修复；观察API与UI合同对齐，UI不增加源轮询。 |

## 用户工程事实与本轮约定

当前RM-01只有一个风扇；用户确认其有效工作区间内真实转速降低时噪声降低，没有需要本阶段专门研究的反向共振区。把降低不必要的高转速与频繁变化列为体验目标，不增加声学实验室前置。不把“转速翻倍噪声翻倍”写成普适公式，也不把PWM百分比直接写成RPM或分贝。

## 已开工任务如何接续

先读现有工作目录和回执，保留已完成通用修复，停止未完成的CPU特定扩展；不要reset、清理或重做已验收工作。已有通讯专项交回的成果由测试线查收；只有实际会影响持续观察的部分纳入。不自动重新联系第四个对话安排新大修。

## 权限与退出条件

本轮只开发和准备。新包不继承任何历史密码登录、设备安装、60秒或12请求授权。不得以用户支持小批试跑为由猜设备IP或自动登录。

之后批准小批现场窗口时，一次明确：设备列表、候选/模型身份、只读权限、最长时长、归档/回退。该窗口内按计划执行，不因每个正常恢复都请求再次批准。不包含风扇控制、刷板、模型自动热替换或新增人工压力负载。
