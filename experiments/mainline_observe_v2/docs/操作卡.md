# observe.10 常驻只读观察

observe.10 / Web rc11 是新的软件身份。冻结模型、源采样、轮询、TTL、15/45/90 秒预测与评分算法不变。只运行一个原生采集器和一个有状态模型，Web 使用 follow；没有设备写入、负载请求或另一套观察器。

本轮只进行本地修复、回放、安装验证和 PR；不连接或部署到 N305。

## 常驻与限时测试

`preview` 和 `observe` 省略 `--duration` 表示常驻。明确传入 `--duration SECONDS` 才是原来的限时测试（最多 86400 秒）；普通非 observe 命令仍保留原有运行边界。

先使用新候选的独立环境核验身份，然后预览已有的端点配置和设备登记：

```sh
"$TTO_PREFIX/bin/tto-observe" verify-install --target
"$TTO_PREFIX/bin/tto-observe" preview --config "$TTO_CONFIG" --registration "$TTO_REGISTRATION" > "$TTO_PREVIEW"
```

预览不连接设备。沿用已有的只读启动登记：将 grant_template 另存为 grant，确认设备、配置、主机、软件/模型清单一致，按实际批准填写 `explicit_user_start=true`、`evidence`。常驻需明确 `continuous=true`；不使用到期时间、单轮时长和累计字节预算，不需要每天重新登记。软件或配置变更后重新生成登记。此文件不是网页登录口令，网页仍直接打开。

```sh
"$TTO_PREFIX/bin/tto-observe" observe --config "$TTO_CONFIG" --registration "$TTO_REGISTRATION" --grant "$TTO_GRANT" --output "$TTO_HISTORY" --publication-descriptor "$TTO_PUBLICATION/active.json" --allow-network
```

常驻每次进程启动自动生成新 session_id，在固定历史根目录下创建对应子目录；同一配置可以在停止后再次启动。boot_id、原生 run_id、单调时钟域均来自真实运行。跨天仅切记录文件，不重启进程、不更新运行身份、不重新预热模型。真实重启或源缺口仍按原有规则重新建立资格，不伪装连续。

`--local-loopback` 和 `self_owned_loopback` 仅用于自己创建的本地模拟源，不能用于现场。端点没有默认设备地址。发布目录须独立、私有、短路径。

## 历史与评分

- 常驻流直接写 `days/YYYY-MM-DD/` 下的 gzip level 1 JSONL。原始输入、温度与有效性、来源引用、预测和评分保留；不重新落盘完整内部状态。
- 沿用 UTC 日期，保留当天加之前 29 天。按最早日期删除整天数据和索引；同设备/主机的记录置于同一历史根目录。独立归档和无滚动标记的旧资料不自动删除。旧限时会话仍按原来的开始日整套清理。
- 小幅校时回拨不会重新打开已封存日期；当前进程的记录日期不倒退，记录本身保留实际 UTC 时间。预测时距和标签成熟继续依据单调时间。
- 跨午夜预测和评分按预测发出日归组。该日预测按原有规则结算后封存 `scoring.json` 和文件 SHA 索引；无新源数据时也会结算超期缺标签。哈希/封存在现有异步线程池执行，当前采集和模型使用新日期的文件。
- 每天评分保留原来的精确 P95 算法，只在内存保留未封存日期的误差。日 P95 不取平均冒充全程 P95。累计计数仍真实累计，不构成运行次数上限。
- 常驻没有累计写入额度停机；保留分片界限和磁盘不足/写入失败的明确错误。资源仍记录，但限时测试的 CPU/RSS 预算不作为常驻自停条件。
- 常驻历史是滚动保留片段，支持查询和停止后校验归档；不能作为从第 1 条开始的完整运行回放。未引入模型快照、状态恢复或自动重建。原限时明文/压缩会话的查询、回放和归档保持兼容。

## 状态、停止与归档

`TTO_SESSION` 指具体启动后生成的会话子目录，而非历史根目录：

```sh
"$TTO_PREFIX/bin/tto-observe" status --session "$TTO_SESSION"
"$TTO_PREFIX/bin/tto-observe" history --session "$TTO_SESSION" --stream scores --last 20
"$TTO_PREFIX/bin/tto-observe" stop --session "$TTO_SESSION"
"$TTO_PREFIX/bin/tto-observe" archive --session "$TTO_SESSION" --output "$TTO_ARCHIVE"
```

评分查询按实际结算单调时间合并保留日期，避免跨日迟到评分被漏掉；读取可扫描保留的评分文件，内存只保留请求的尾部。常驻日布局使用 `TTO-OBSERVE-DAYS-v2`：根 `files.json` 登记应保留的每个日索引及其 SHA，归档按清单核对，整天目录或索引缺失也会失败。正常淘汰先更新日期清单；已关闭会话原子更新根索引后，再删除过期目录；删除中断留下的过期文件不进入归档。关闭后的历史查询也按清单读取。程序退出只封存尚未完成的日期，额外校验小型日索引，不重新计算过去 30 天原始文件的哈希。

此前本地候选的 `TTO-OBSERVE-DAYS-v1` 没有完整日期清单，仍可查询，但不能宣称归档完整；归档入口明确拒绝，需保留原始目录。旧限时会话格式的归档保持兼容。

STOP 只处理核对 PID/创建时刻/主机/用户后的本观察进程。硬件身份冲突、原始数据丢失、写盘失败仍明确报错；模型或发布故障保持原有处理边界。限时测试仍保留窗口和资源预算及收尾记录。

## 服务与安装

`install_observe.py --unit-output ... --config ... --registration ... --grant ... --session-output ... --publication-descriptor ...` 仅生成用户服务文本，不启用服务。省略 duration 的单元无 RuntimeMaxSec，使用固定历史根目录并自动生成每次启动的身份；可随 default.target 开机启动。服务崩溃使用 systemd 的 Restart=on-failure（60 秒内最多启动 3 次，避免错误配置反复重启），不按天重启；手动停止不会重启。限时单元保持 Restart=no 和窗口+10 秒上限。

部署需另行授权，采用新 prefix 和独立环境，保留旧版本、配置、失败记录和历史归档；本轮不执行 enable/start、现场采集或升级。
