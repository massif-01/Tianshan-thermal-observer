# observe.9 本机发布接口

observe.9 的默认入口为常驻只读运行，按日存档而不重启采集或模型；限时测试需显式传 duration。详见[操作卡](操作卡.md)。发布协议和预测读视图沿用现有接口。

observe.8 在 observe.2 唯一采集、质量判断、投影和模型消费链上增加可选发布通道。冻结模型、规格、采样/轮询/TTL、预测账本算法不变；原生采集器增加取得唯一锁后的初始化回调，用于先清理过期记录再写新会话；新增账本评分结算时刻/实测 UTC 字段；软件版本和候选文件清单改变，不能称为“整轮软件未变”。PR #16/#20 的原后端验收限本地回放/loopback；rc8 整合与安装短测、后续本地清理范围见 docs/reports/observe-publication.md，不把早期结论当作现场结果。

## 接入位置与依赖

`Consumer.on_record` 仍先记录 observations，再将已处理 frame 交给原有模型队列。仅启用发布时，为这份队列快照附上独立复制的 raw 和原生 quality；其余 processed 字段不复制；不把 engine 交给发布器。`Consumer._work` 使用原有 observer 计算，先将本轮预测/评分压缩写入原账本，再提交该帧、模型状态和原记录的 consumable deadline；完整内部状态不再落盘。

发布线程使用 `WebEncoder` 编码，然后写 Unix socket。编码器的字段白名单沿用 `work/webui-v1/src/tto_web/adapter.py` 的 `Adapter.encode`，构造器不创建或调用 engine、projection、CommunicationBridge、ThermalObserver，不修改 owner。后端没有依赖或安装 `tto-web-ui`；避免其 vendor 的同名 `tto`/`tto_field` 覆盖生产者。单独保留纯编码器是为了让后端包能独立安装；回放验证逐包对比既有 Web 编码，防止两份协议实现漂移。

本机发布不是 HTTP 接口。实时出口是私有目录里的 `publication.sock`，Web 用 follow 订阅。另有同目录 `predictions.sock`，按修订游标只读补取已提交的预测和评分。Web 自行 observe 不属于这条接入链路。

## 未来授权窗口中的配置

默认不发布。`tto-observe observe` 可显式追加：

```text
--publication-descriptor /run/user/UID/tto-pub/active.json
```

实际路径由部署时确定；目录只允许当前用户访问（0700），socket 为 0600，路径须足够短，且目录要独立于原始记录目录。描述文件不能与 publication.sock、predictions.sock、predictions-final.json 或 publisher.lock 同名。发布器持有独立的 `publisher.lock`，不会替代或抢占原生采集锁。

启动写 `TTO-WEB-ACTIVE-v1`、`socket:publication.sock`、真实 boot_id、publisher_id、`ended:false`；正常关闭先完成最后的后台评分，原子写 predictions-final.json 终态读视图，再写带 publisher_id/prediction_final 的 `ended:true` 并移除两个 socket。进程崩溃可能来不及更新描述文件，follow 会因 EOF/超时断开，已收值按原期限失效。发布启动失败不阻止采集，summary 记录错误；修复配置后在新运行中重新启动发布，不自动重启采集。

Web 配置需 `source.mode=follow` 且 `source.active_descriptor` 指向同一描述文件。两者必须同主机、同 boot；当前目录权限要求同用户。Web 必须独立 venv、全新 prefix，使用 `--service none --access local`。统一安装入口见 docs/统一候选安装与短测.md；是否实际执行以本次报告为准。

## 帧、时钟和故障语义

公共包沿用 `TTO-WEB-PUBLICATION-v1`。run_id 和 source_ref 保持 Web 既有短哈希表示，可从对应原生身份计算核对；source_epoch 来自真实 frame。新生产者使用新 run_id，epoch 从其真实初值开始，不伪造跨进程连续编号。

`clock_domain_id=host-monotonic:<boot_id>` 使 follow 可比较本机单调时间；附加 `process_clock_domain` 是 observe 的真实 Clock.domain，`frozen_state_clock_literal` 单独保留冻结模型自身的字面标签，两者不能混用。model_id/spec_id 来自未修改的冻结模型与规格；software_version 如实标记实际候选版本。生产发布与预测读视图共同使用 session_origin_mono_s；不能各自重设 elapsed 原点。

`input_mono_s` 不重写，`generated_mono_s` 仅表示编码时间。consumable deadline 不得晚于已落盘 state 的截止时间，重连重发 latest 也不续期。模型异常时仅在公共编码中补 `Tf_C/Ts_C/E_C:null`，保持原状态记录不变。

生产者待编码队列最多 8 份快照；每客户端最多 9 份编码数据（允许首次 latest 加一批 8 帧），最多 4 个客户端，每包小于 512 KiB，socket drain 等待最多 0.2 秒。编码和 JSON/socket I/O 都在发布线程，不持有生产者队列锁。慢客户端被断开；发布队列满时清空积压并保留新数据。

模型队列丢帧/超时、发布队列丢帧、编码或序列化失败会撤销发布缓存，并通过 `TTO-WEB-DISPLAY-GAP-v1` 或合格包的缺口标记撤销连续性；恢复包带 `publication_gap:true`。清理显示缓存防止遗漏 fan/temp 撤销事件后旧值重新被标有效。GPU 独立样本的身份、最早失效时间和撤销状态另存一份固定大小记录，普通发布缺口及模型重置保留它；同一旧样本不能续期或复活。只使用原生 quality 已确认的身份；error/unavailable 空状态或不可信时间戳仅撤销旧样本，不替换其记录。新可信样本/来源 epoch 则可恢复。source_reset 由编码器统一清理显示缓存，发布器只标缺口。线程启动异常直接交给 run_observe 的初始化边界处理，不返回失败的发布器，不再入队或二次关闭；启动、入队、编码、传输和退出异常均与采集 stop 分开；错误只保留类型，不发送异常正文、原始 payload、配置 URL 或凭据。summary 给出 published/dropped/errors/slow_clients、worker_stopped 及 lifecycle/callback 错误；收尾时遗留待编码项记为 dropped，不伪称全部送达。

发布仍会增加快照复制、编码 CPU、内存和线程竞争成本；不能宣称零开销或保证 N305 的原预算。已测 rc8 低负载短测总开销，未测同机关闭发布的增量对照或长期预算。

## 后台统一预测

`Consumer.emit` 在 predictions/scores 写入并 flush 后才更新 `PredictionView`；保留60分钟紧凑G2记录，不扫描磁盘或重新预测。投影失败只禁用本轮读视图，原账本继续；后台规则、正式阶段和页面字段见 [前后端契约](../../../docs/后台统一预测-前后端接口约定.md)。

`predictions.sock` 接受单次JSON请求 `{ "cursor": 0 }`，按revision排序分页交付，最多128行/512KiB；cursor只推进至本页实际交付位置，后续评分修订覆盖同一ID。最多共8个实时/查询处理任务。编码和等待不持有账本锁或生产者队列锁，Web补取任务不阻塞实时接收。

终态先完成ledger.finish、保存最终文件，再登记正常结束。生成/写入/登记失败尝试一次publication_failed登记，不伪造完整结果。正常终态的history_identity独立指向最后一组正式历史；实时身份不回写，当前参考撤回，时间轴停止。Web生命周期和历史恢复规则统一由上述契约说明。
