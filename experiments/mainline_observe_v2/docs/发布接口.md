# observe.5 本机发布接口

observe.5 在 observe.2 唯一采集、质量判断、投影和模型消费链上增加可选发布通道。冻结模型、规格、原生采集器、采样/轮询/TTL、预测账本算法不变；新增账本评分结算时刻/实测 UTC 字段；软件版本和候选文件清单改变，不能称为“整轮软件未变”。PR #16/#20 的原后端验收限本地回放/loopback；后续 rc7 整合与安装短测单独记录于 evidence/unified-web-rc7-20261023，不把早期结论当作现场结果。

## 接入位置与依赖

`Consumer.on_record` 仍先记录 observations，再将已处理 frame 交给原有模型队列。仅启用发布时，为这份队列快照附上独立复制的 raw 和原生 quality；其余 processed 字段不复制；不把 engine 交给发布器。`Consumer._work` 使用原有 observer 计算，先落盘 states，再提交该帧、模型状态和原记录的 consumable deadline。

发布线程使用 `WebEncoder` 编码，然后写 Unix socket。编码器的字段白名单沿用 `work/webui-v1/src/tto_web/adapter.py` 的 `Adapter.encode`，构造器不创建或调用 engine、projection、CommunicationBridge、ThermalObserver，不修改 owner。后端没有依赖或安装 `tto-web-ui`；避免其 vendor 的同名 `tto`/`tto_field` 覆盖生产者。单独保留纯编码器是为了让后端包能独立安装；回放验证逐包对比既有 Web 编码，防止两份协议实现漂移。

本机发布不是 HTTP 接口。实时出口是私有目录里的 `publication.sock`，Web 用 follow 订阅。另有同目录 `predictions.sock`，按修订游标只读补取已提交的预测和评分。Web 自行 observe 不属于这条接入链路。

## 未来授权窗口中的配置

默认不发布。`tto-observe observe` 可显式追加：

```text
--publication-descriptor /run/user/UID/tto-pub/active.json
```

实际路径由部署时确定；目录只允许当前用户访问（0700），socket 为 0600，路径须足够短，且目录要独立于原始记录目录。描述文件不能与 publication.sock、predictions.sock、predictions-final.json 或 publisher.lock 同名。发布器持有独立的 `publisher.lock`，不会替代或抢占原生采集锁。

启动写 `TTO-WEB-ACTIVE-v1`、`socket:publication.sock`、真实 boot_id、publisher_id、`ended:false`；正常关闭先完成最后的后台评分，原子写 predictions-final.json 终态读视图，再写带 publisher_id/prediction_final 的 `ended:true` 并移除两个 socket。进程崩溃可能来不及更新描述文件，follow 会因 EOF/超时断开，已收值按原期限失效。发布启动失败不阻止采集，summary 记录错误；修复配置后在新运行中重新启动发布，不自动重启采集。

Web 配置需 `source.mode=follow` 且 `source.active_descriptor` 指向同一描述文件。两者必须同主机、同 boot；当前目录权限要求同用户。Web 必须独立 venv、全新 prefix，使用 `--service none --access local`。统一安装入口见 docs/统一候选安装与短测.md；是否实际执行以本次报告为准。

## 帧、时钟和故障语义

公共包沿用 `TTO-WEB-PUBLICATION-v1`。run_id 和 source_ref 保持 Web 既有短哈希表示，可从对应原生身份计算核对；source_epoch 来自真实 frame。新生产者使用新 run_id，epoch 从其真实初值开始，不伪造跨进程连续编号。

`clock_domain_id=host-monotonic:<boot_id>` 使 follow 可比较本机单调时间；附加 `process_clock_domain` 是 observe 的真实 Clock.domain，`frozen_state_clock_literal` 单独保留冻结模型自身的字面标签，两者不能混用。model_id/spec_id 来自未修改的冻结模型与规格；software_version 如实标记 observe.5。生产发布与预测读视图共同使用 session_origin_mono_s；不能各自重设 elapsed 原点。

`input_mono_s` 不重写，`generated_mono_s` 仅表示编码时间。consumable deadline 不得晚于已落盘 state 的截止时间，重连重发 latest 也不续期。模型异常时仅在公共编码中补 `Tf_C/Ts_C/E_C:null`，保持原状态记录不变。

生产者待编码队列最多 8 份快照；每客户端最多 9 份编码数据（允许首次 latest 加一批 8 帧），最多 4 个客户端，每包小于 512 KiB，socket drain 等待最多 0.2 秒。编码和 JSON/socket I/O 都在发布线程，不持有生产者队列锁。慢客户端被断开；发布队列满时清空积压并保留新数据。

模型队列丢帧/超时、发布队列丢帧、编码或序列化失败会撤销发布缓存，并通过 `TTO-WEB-DISPLAY-GAP-v1` 或合格包的缺口标记撤销连续性；恢复包带 `publication_gap:true`。清理显示缓存防止遗漏 fan/temp 撤销事件后旧值重新被标有效。GPU 独立样本的身份、最早失效时间和撤销状态另存一份固定大小记录，普通发布缺口及模型重置保留它；同一旧样本不能续期或复活。只使用原生 quality 已确认的身份；error/unavailable 空状态或不可信时间戳仅撤销旧样本，不替换其记录。新可信样本/来源 epoch 则可恢复。source_reset 由编码器统一清理显示缓存，发布器只标缺口。线程启动异常直接交给 run_observe 的初始化边界处理，不返回失败的发布器，不再入队或二次关闭；启动、入队、编码、传输和退出异常均与采集 stop 分开；错误只保留类型，不发送异常正文、原始 payload、配置 URL 或凭据。summary 给出 published/dropped/errors/slow_clients、worker_stopped 及 lifecycle/callback 错误；收尾时遗留待编码项记为 dropped，不伪称全部送达。

发布仍会增加快照复制、编码 CPU、内存和线程竞争成本；不能宣称零开销或保证 N305 的原预算。真实机器预算未验证。

## 本地验收及复现

详细结果见仓库 `evidence/observe-publication-20261023/`。

1. 30 分钟、5572 条录制输入，通过真实 `Consumer.on_record/_work` 生成记录；无第二观察器。逐条比较公共编码和原 Web encode、公共模型和落盘 states；Web State 直接消费 JSON 包，不启动 HTTP。回放使用明确的虚拟接收时钟，保持原始时间，不能称现场运行。整个回放无强制丢帧，另用实际 socket 故障测试覆盖有损路径。
2. 实际 Unix socket 的 loopback 采集用例，比较接收端 JSON 与对应落盘 states 的值、身份、进程域和期限。测试设备服务完全由本地 fixture 生成，没有访问真实设备。
3. 实际 follow/State 订阅断开及重启、生产者新 run 重启、过期、非读 socket、编码/序列化/超大包错误、启动冲突及退出错误验证。无需安装或启动 Web。
4. 独立进程顺序运行发布关闭、开启无人订阅、开启但订阅者不读数据的 CPU/RSS/回调耗时对比，包含自建源服务的成本，只能作为 Mac 本地影响估计。

示例命令（使用已有锁定后端依赖，不安装 Web）：

```sh
PYTHONPATH=experiments/mainline_observe_v2/src python -m pytest experiments/mainline_observe_v2/tests -q
python experiments/mainline_observe_v2/scripts/validate_publication_replay.py --run evidence/formal-collection-20261013/run-2026-10-13T022246.369032_0000-c1a1bd6a --output /tmp/tto-pub-replay-NEW
python experiments/mainline_observe_v2/scripts/measure_publication_cost.py --output /tmp/tto-pub-cost-NEW.json
```

不要同时运行不同采集测试/性能实验：原生独占锁仍按同一用户共享。上述示例从仓库根目录运行，回放输出目录必须全新。

## 预测验收边界

公共数据保真和页面预测口径仍分开验收。早期 PR #16 仅接通状态，曾有共同起点 984 个 horizon 预测一致，但两侧起点数 355/1635 的差异；这是旧方案记录，已由 PR #20 的后台统一账本替代。当前 Web 不再计算预测或匹配实测，正式展示使用后台 tracking/degraded G2-HOLD 记录；5572 条回放产生的 1065 条 G2 预测/评分按 ID 一致，两侧均 355 个起点。provisional 留档，B0/B1 仍是后台基线，不混入页面正式分数。交接文档旧 MAE 不作本链路目标，不修改冻结模型追分。

部署须确认归档、使用当前授权的新环境和窗口；实际执行与未验证项见本轮整合报告，不能把离线成绩称为现场验收。

## 后台统一预测

`Consumer.emit` 只在 predictions/scores 成功写入并 flush 后更新 `PredictionView`。它保留最多60分钟紧凑 G2 记录，不预测、不保存原始 payload、不重扫磁盘。B0/B1仍在原正式账本中；provisional记录留档，页面正式预测和统计只采用tracking/degraded。评分规则与5秒签发步长不变，scores新增settled_mono_s及label_received_utc用于显示与增量更新。

读视图更新只有一个错误边界：投影失败后本轮读视图明确不可用，正式采集/账本继续；不重试投影、不重扫记录、不启用备用预测。只有观察器完成ledger.finish后才能声明正式终态。发布线程异常退出写publication_failed=true、ended=false，不把发布死亡当作观察结束。

实时发布缺口与预测账本位置分开。predictions.sock单次JSON请求 `{ "cursor": 0 }`，返回TTO-PREDICTION-PAGE-v1、最多128条按revision排序的记录、cursor/watermark/has_more、身份及forecast资格。cursor只到本页已交付修订，后续评分会更新同ID的revision；最后完整页才可宣称同步。最多共8个发布/查询处理任务；查询编码/等待不持有记录锁或生产者队列锁，单页仍受512KiB限制。

当前参考上限为预测起点+5秒步长+2.5秒原状态时效，并同时受最新后台帧deadline约束。设备/模型失效设置撤回界限；只有界限后的新正式预测可恢复。15/45/90秒绝不是当前参考展示TTL。

Web的Python State不再加载solver，不生成预测ID、不重新匹配实测。补取由独立任务执行，按prediction_id覆盖。Web断开只影响当前展示，不改后台pending/评分。终态快照是正常结束协议的一部分；身份必须匹配publisher和boot，当前参考始终撤回，历史时间轴停在观察结束时刻。异常退出可能没有终态快照，不伪造最终评分或完整同步。

浏览器接入约定见 [前后端接口约定](../../../docs/后台统一预测-前后端接口约定.md)。Web rc7 保留已合入的时间说明，按后台资格、ID 和期限展示。联合回放、浏览器、独立安装及现场执行范围分别记录，不混淆证据。
