# observe.3 本机发布接口

observe.3 在 observe.2 唯一采集、质量判断、投影和模型消费链上增加可选发布通道。冻结模型、规格、原生采集器、采样/轮询/TTL、预测账本算法不变；软件版本和候选文件清单改变，不能称为“整轮软件未变”。本轮只做本地修改、录制回放及自建 loopback 故障验证，没有连接 N305，没有安装或启动 Web，没有部署、现场短测或长期运行。

## 接入位置与依赖

`Consumer.on_record` 仍先记录 observations，再将已处理 frame 交给原有模型队列。仅启用发布时，为这份队列快照附上独立复制的 raw 和原生 quality；其余 processed 字段不复制；不把 engine 交给发布器。`Consumer._work` 使用原有 observer 计算，先落盘 states，再提交该帧、模型状态和原记录的 consumable deadline。

发布线程使用 `WebEncoder` 编码，然后写 Unix socket。编码器的字段白名单沿用 `work/webui-v1/src/tto_web/adapter.py` 的 `Adapter.encode`，构造器不创建或调用 engine、projection、CommunicationBridge、ThermalObserver，不修改 owner。后端没有依赖或安装 `tto-web-ui`；避免其 vendor 的同名 `tto`/`tto_field` 覆盖生产者。单独保留纯编码器是为了让后端包能独立安装；回放验证逐包对比既有 Web 编码，防止两份协议实现漂移。

本机发布不是 HTTP 接口。唯一出口是私有目录里的 `publication.sock`，Web 用现有 follow 订阅。Web 自行 observe 不属于这条接入链路。

## 未来授权窗口中的配置

默认不发布。`tto-observe observe` 可显式追加：

```text
--publication-descriptor /run/user/UID/tto-pub/active.json
```

实际路径由部署时确定；目录只允许当前用户访问（0700），socket 为 0600，路径须足够短，且目录要独立于原始记录目录。描述文件不能命名为 `publication.sock` 或 `publisher.lock`。发布器持有独立的 `publisher.lock`，不会替代或抢占原生采集锁。

启动写 `TTO-WEB-ACTIVE-v1`、`socket:publication.sock`、真实 boot_id、publisher_id、`ended:false`；正常关闭写 `ended:true` 并移除 socket。进程崩溃可能来不及更新描述文件，follow 会因 EOF/超时断开，已收值按原期限失效。发布启动失败不阻止采集，summary 记录错误；修复配置后在新运行中重新启动发布，不自动重启采集。

Web 配置需 `source.mode=follow` 且 `source.active_descriptor` 指向同一描述文件。两者必须同主机、同 boot；当前目录权限要求同用户。Web 独立 venv、全新 prefix、安装参数及服务方式留到另行授权的部署阶段；本轮没有执行。

## 帧、时钟和故障语义

公共包沿用 `TTO-WEB-PUBLICATION-v1`。run_id 和 source_ref 保持 Web 既有短哈希表示，可从对应原生身份计算核对；source_epoch 来自真实 frame。新生产者使用新 run_id，epoch 从其真实初值开始，不伪造跨进程连续编号。

`clock_domain_id=host-monotonic:<boot_id>` 使 follow 可比较本机单调时间；附加 `process_clock_domain` 是 observe 的真实 Clock.domain，`frozen_state_clock_literal` 单独保留冻结模型自身的字面标签，两者不能混用。model_id/spec_id 来自未修改的冻结模型与规格；software_version 如实标记 observe.3。

`input_mono_s` 不重写，`generated_mono_s` 仅表示编码时间。consumable deadline 不得晚于已落盘 state 的截止时间，重连重发 latest 也不续期。模型异常时仅在公共编码中补 `Tf_C/Ts_C/E_C:null`，保持原状态记录不变。

生产者待编码队列最多 8 份快照；每客户端最多 9 份编码数据（允许首次 latest 加一批 8 帧），最多 4 个客户端，每包小于 512 KiB，socket drain 等待最多 0.2 秒。编码和 JSON/socket I/O 都在发布线程，不持有生产者队列锁。慢客户端被断开；发布队列满时清空积压并保留新数据。

模型队列丢帧/超时、发布队列丢帧、编码或序列化失败会撤销发布缓存，并通过 `TTO-WEB-DISPLAY-GAP-v1` 或合格包的缺口标记撤销连续性；恢复包带 `publication_gap:true`。清理显示缓存防止遗漏 fan/temp 撤销事件后旧值重新被标有效。GPU 独立样本的身份、最早失效时间和撤销状态另存一份固定大小记录，普通发布缺口及模型重置保留它；同一旧样本不能续期或复活。只使用原生 quality 已确认的身份；error/unavailable 空状态或不可信时间戳仅撤销旧样本，不替换其记录。新可信样本/来源 epoch 则可恢复。source_reset 由编码器统一清理显示缓存，发布器只标缺口。线程启动异常直接交给 run_observe 的初始化边界处理，不返回失败的发布器，不再入队或二次关闭；启动、入队、编码、传输和退出异常均与采集 stop 分开；错误只保留类型，不发送异常正文、原始 payload、配置 URL 或凭据。summary 给出 published/dropped/errors/slow_clients、worker_stopped 及 lifecycle/callback 错误；收尾时遗留待编码项记为 dropped，不伪称全部送达。

发布仍会增加快照复制、编码 CPU、内存和线程竞争成本；不能宣称零开销或保证 N305 的原预算。真实机器预算未验证。

## 本地验收及复现

详细结果见仓库 `evidence/observe-publication-20261023/`。

1. 30 分钟、5572 条录制输入，通过真实 `Consumer.on_record/_work` 生成记录；无第二观察器。逐条比较公共编码和原 Web encode、公共模型和落盘 states；Web State 直接消费 JSON 包，不启动 HTTP。回放使用明确的虚拟接收时钟，保持原始时间，不能称现场运行。整个回放无强制丢帧，另用实际 socket 故障测试覆盖有损路径。
2. 实际 Unix socket 的 loopback 采集用例，比较接收端 JSON 与对应落盘 states 的值、身份、进程域和期限。测试设备服务完全由本地 fixture 生成，没有访问真实设备。
3. 实际 follow/State 订阅断开及重启、生产者新 run 重启、过期、非读 socket、编码/序列化/超大包错误、启动冲突及退出错误验证。无需安装或启动 Web。
4. 独立进程顺序运行发布关闭、开启无人订阅、开启但订阅者不读数据的 CPU/RSS/回调耗时对比，包含自建源服务的成本，只能作为 Mac 本地影响估计。

示例命令（使用已有锁定后端依赖，不安装 Web）：

```sh
PYTHONPATH=experiments/mainline_observe_v2/src python -m pytest experiments/mainline_observe_v2/tests -q
python experiments/mainline_observe_v2/scripts/validate_publication_replay.py --run evidence/formal-collection-20261013/run-2026-10-13T022246.369032_0000-c1a1bd6a --output /tmp/tto-pub-replay-NEW
python experiments/mainline_observe_v2/scripts/measure_publication_cost.py --output /tmp/tto-pub-cost-NEW.json
```

不要同时运行不同采集测试/性能实验：原生独占锁仍按同一用户共享。上述示例从仓库根目录运行，回放输出目录必须全新。

## 预测验收边界

公共数据保真和页面预测口径是两项验收。Web 根据已收状态重新计算 15/45/90 秒 G2-HOLD；后端 Ledger 默认 5 秒一个起点，Web 最短 1 秒；后端接受 provisional/tracking/degraded，Web 只接受 tracking/degraded。共同起点且 TJ/Ts/E/条件输入相同的 G2-HOLD 应逐项相等；完整起点集合、实际签发时间、断线后的匹配和全体 MAE 不应宣称一致。后端 B0/B1 不由当前公共包直接发布成页面预测。

本次回放共同配对 984 个 horizon 预测，最大差 0；后端起点 355、Web 起点 1635。交接文档的旧 MAE 不是这条 observe 链路的验收目标，不追平旧分数或修改冻结模型。

部署前仍需用户确认归档完成、新软件/窗口授权，并决定页面继续现有独立预测口径，还是未来另做直接展示后端预测账本。本 PR 保持现有页面计算方式。
