## 3．R1：跨run时间和过程分组——关闭

候选现在同时在建立和消费split时重建完整run顺序，使用已记录的接收UTC范围和各run自己的单调时间锚点；非连续复用同名过程不再只按首次出现分组。

独立重跑原反例 `A→B→C→D→E→A`：`freeze_split`和直接`check_split`均拒绝，错误包含冲突的过程、run与时间。相邻`A→A`、反向传入文件列表但实际时间正确、正常唯一过程、跨run支持区间隔离、单run探索等对应测试通过。

**实际改善：**后发生的数据不能仅因过程名重复而悄悄回到训练区；正常相邻同过程仍能合组。没有要求重采旧数据；旧派生清单时序证据不足时，从原始run在新路径重建，不覆盖旧的测试使用记录。

本次没有独立证明本机UTC必然准确；有时钟不一致时明确拒绝严格跨run留出，是当前合同的一部分。单run探索继续使用本机单调时间，但不冒充跨过程泛化。

## 5．R4：真实WebSocket握手重定向——关闭，保留环境边界

本轮使用实际安装的生产`sessions`和两个真实loopback服务，分别重跑跨源跳转和同源未授权路径跳转。**跳转目标实际请求计数均为0，会话正常关闭；ESP32状态GET对照同样拒绝。** 没有使用真实凭据，只有非敏感测试header。

独立执行使用aiohttp 3.13.3；作者的3.11.18锁定环境完整协议测试、81项JUnit与本次候选身份已核对，但本环境没有独立重跑Socket.IO完整服务会话。不能把这两层证据合称“本审查独立跑完锁定协议环境”。

综合实际调用链、当前环境真实握手与作者锁定版本证据，本缺陷可关闭。N305的正常连接、心跳与现场端点仍在首次只读检查中确认。

## 6．R3：历史预测已接入报告，但仍有一项资格遗漏

### 6.1 已修好的部分

原400秒合成旁路夹具中，44个含M1的预测起点、102条M1时距评分，现在进入正式report。替换或移开后来可访问的模型文件，不改变历史统计；移动应有的预测/评分日志，报告明确缺证据。原始日志未被回写。

无模型、无评分、缺日志、部分降级、评分乱序与模型身份不一致的已有回归通过。这证明“报告不读日志”的原问题已修复。

### 6.2 R3b｜P2：已被质量层隔离的段，仍进入有效旁路误差统计

**定位：**
- `src/tto/engine.py:77–83`：同身份冲突/序号倒退时产生`invalidated_segment`。
- `src/tto/dataset.py:52–73`：回放收集被隔离段，并撤下其normal_auto资格及标签。
- `src/tto/report.py:21–44`：已进行质量回放，但调用`recorded_results`时只传run和manifest，未传有效性判定。
- `src/tto/recorded.py:54–99`：只要原保存score为scored且数字/身份能关联，就进入points和误差汇总，没有应用测量段后续隔离。

**根因不是模型重新算错，而是“当时确实记过一笔评分”与“这笔评分现在仍可作为有效证据”没有分开。** 保存原评分是正确的；继续把它列为有效成绩不正确。

### 6.3 最小独立反例

使用未修改的生产Engine、Journal、replay与report，按时间喂入固定合成输入。所有记录明显标模拟，未改真实数据或用户文件。

1. 前350秒为正常模拟输入，已有预测及评分落盘。
2. 第350秒，样本seq351的TJ约43.353°C，用于当时若干预测的未来标签。
3. 0.2秒后，同一stream、同一seq再次到达，但TJ改为约53.353°C。它不是“新采样温度上升”，而是同一测量身份出现两份冲突值。
4. 生产质量层正确拒绝，并把原segment 3标为不可用。
5. 生产旁路报告却继续把该段原有评分全部纳入误差表。

| 核对 | 正常对照 | 加入一次同身份冲突后 |
|---|---:|---:|
| 质量回放认可的normal_auto起点 | 71 | 0 |
| 回放15/45/90秒可用标签数 | 68 / 62 / 53 | 0 / 0 / 0 |
| 旁路报告仍计入的“方法×起点×时距”评分 | 510 | 510 |
| 其中来自已隔离段 | 0 | 510 |
| 其中直接用第350秒争议读数作真值 | 12 | 12 |

**510不是510次独立实验，也不表示已经证明510个数值全部错误。** 它表示按当前程序自己的隔离规则，这510条应退出有效统计；其中12条更直接使用了发生冲突的真值，不能只当作另一个无关异常。

例如M1在305秒发出的45秒预测约43.3466°C，原标签约43.3530°C，误差约−0.0064°C。后来同一标签身份发生冲突，报告仍保留这笔看起来很准的有效成绩。这个例子只解释统计资格，不代表设备或模型真实精度。

`log_evidence_complete=true`在反例中仍成立。**不要求仅因数据冲突就把“文件齐全”改成“文件缺失”；要求的是把日志完整性与测量/评分可用性区分开。** 当前模型误差表没有撤下这些不可用评分，不能靠一个质量计数藏在详情里替代。

### 6.4 恢复段也检查了，不应一刀切清空整轮

独立夹具在冲突后继续送入新的有效序号，直到620秒。质量层正常恢复到新段：新段有54个正常起点、51/45/36个时距标签。报告共有816条方法时距评分，其中510条来自旧隔离段、306条来自其他有效段。

**修复应排除旧段510条、保留其历史记录，同时保留新段306条，不应因一次冲突丢掉整轮采集。** 不需要关闭采集器、要求用户重启Orin、删除文件或修改模型。

### 6.5 最小修复要求

保持现有隔离粒度，不新设更苛刻的规则。将已有质量判定以明确的run/segment/原始引用身份传到旁路汇总；可复用现有回放结果或落盘质量事件，但不能用事后模型重算替代历史预测。

报告应区分：当时已发预测、当时已记评分、当前仍可用评分、后来因质量问题排除的评分及原因。MAE/RMSE、欠/过预测、覆盖率和图中的有效成绩使用同一资格集合；原始预测/评分字节保持不变。已隔离数据可单独展示，但不能混在有效指标中。

建议补三个聚焦回归：正常旧夹具的102条M1评分保持；本次冲突段不再进入有效指标且直接关联争议标签的评分被排除；恢复后的新段继续正常计分。按已有相同隔离语义检查序号倒退，不扩成故障笛卡尔积。

**此项阻挡的是旁路效果报告接受，不阻挡只读doctor、保留原始观测或合法split上的离线评估。**
