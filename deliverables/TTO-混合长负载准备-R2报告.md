## 2. 两种节奏、分轮优先级与预算

### 固定锚点轮：优先用原驻留27B稠密

| 阶段 | 计划 | 目的与限制 |
|---|---:|---|
| 驻模背景 | 300秒 | 保留实际热前史，不称冷机或热平衡 |
| 单路工作 | 360秒发起窗口 | 冷/初始单路锚点，repeat_key=single-anchor |
| 回落 | 90秒 | 固定时间，不等相同温度 |
| 双路工作 | 270秒发起窗口 | 客户端最多2在途；GPU调度另记 |
| 回落 | 240秒 | 与其他回落不等长 |
| 四路工作 | 450秒发起窗口 | 客户端最多4在途；不是4个独立调度器 |
| 回落 | 120秒 | 保留热机背景 |
| 重复同一单路工作 | 360秒发起窗口 | 同模型、同payload、同采样，不换成另一题/配置 |
| 最终回落 | 480秒 | 不自动扩展至等温 |

名义合计2670秒=44分30秒。准备最多300秒，四个工作块各留90秒自然drain，清理120秒：**3450秒=57分30秒**，相对3600秒封顶余150秒供离散步进/软件开销。工作块时长是维持槽位的发起窗口，不要求单条回复持续几分钟；窗口关闭不再发起，已有请求自然完成后才起算下一段回落。

### 同固定方案的第二模型轮

另一个完整run只选择本机已有的一个MoE或小稠密，不下载/加载。原清单、回落与重复块不变；模型切换及之前等待另记，跨run不当独立热过程。当前模型ID、量化、模板和容量未配置，`model-profiles.json`留null，假接口仍可验证整个软件，不因此全局停工。不自动接着第一轮跑第二轮。

### 后续有界不规则轮

原包明确清单：300背景→单路345→回落45→四路330→回落210→双路255→回落75→单路480→最终回落600秒。名义2640秒；加300+4×90+120=**3420秒=57分钟**，余180秒。顺序是预先明确清单，不按温度选择；模拟seed61018010只冻结合成请求12～22秒的复算，不把随机耗时当真实模型性能。

该后续完整run保留到候选冻结后；如果日后暴露给开发，则撤下独立确认标签。没有把当前模拟结果或请求条数当模型泛化证据。

## 3. 请求/资源上限与实际配置缺口

- 每轮最多4096条、最多4在途；到请求上限停止后续发起并有界收尾，不换run偷偷续跑。
- 原包允许单请求最多60秒；本候选**沿用原0.2.4 Requester的30秒协议上限**，没有为拉长请求重写SSE解析。超时、不完整SSE或HTTP失败均保留服务端结束未知，不自动排下一条。
- 原本地M配置可确认`RM-01 VLM`、256生成预算、独立请求、stream+usage、原中文长输出消息及默认sampling。Qwen3.8-27B-NVFP4路径、vLLM只属于历史报告身份，不保证未来驻留/权重相同。
- 1/2/4是客户端槽位；真实排队/引擎并发容量、模板SHA、精确上下文/缓存命中、当前量化及权重身份仍需未来冻结。缺失服务端指标保存unknown，不能从客户端并发倒推GPU占用或发热。
- 独立GPU、CPU/SOC/MSS rail保留，5V仅诊断，不相加为总功率。模拟不提供GPU/rail的物理负载效果，更不推断小模型/MoE一定怎样变化。

## 4. 单一状态流与分层readiness

选择**有序本地JSONL**一种入口，`StateConsumer.at(now)`只向调度器暴露不晚于当前时刻的状态。生成时刻、观测截止、同主机单调钟域与run/config/firmware/collector/model/spec身份分别保留，未来或跨主机未映射时钟拒绝准入。驱动仅一份fixture生产流、一个消费适配与一个请求调度链，没有额外主板轮询。

| 层 | #10消费内容 | 不得混淆 |
|---|---|---|
| collection_available | #9给的raw_valid、TJ/独立rail/最近成功PWM的原引用、时间与到期 | HTTP请求超时不自动否定仍未到期的旧成功值；估计器也不能续龄它 |
| model_available | #8的uninitialized/provisional/tracking/degraded/unavailable、条件Tf/Ts、E来源、假设/年龄、范围与evidence_ready | 有数值不独自允许负载；缺测估计不变成raw_valid=true |
| field_safety_available | 当前guard/fault/mode/binding及新鲜度 | null/过期就是unknown，不能写false/normal |
| execution_authorized | 本轮run授权与local_demo/formal_field | 旧M/Y授权不自动迁移 |
| instrument_clock_ready | 仪表已记录、探头固定、独立时钟对应、时区、显示分辨率、误差已如实说明 | 显示1秒不等于误差1秒；未知仍为null |

`interface-map.json`提供等价字段语义，#8/#9真实实现未交付时明确用synthetic fixture，不能把fixture tracking/degraded称上游研发已通过。#10不估计Tf/Ts/E、不重写源质量算法，不用YET值调状态/参数/时钟。

短缺口不延长工作窗口：采集事实继续保留，暂停新请求，到有效数据/状态恢复再填空槽。新调度等待上限60秒只是有限准备默认，短于90秒drain预算；不是原TTL、不是旧连续60秒初始化准入，需在未来批准的现场政策中冻结。过久输入/估计器不可用、明确故障/保护/模式绑定变化、用户停止、硬预算、未知请求结束分别记录原因。剩余请求有界自然drain或明确记无法确认服务终止；客户端取消从不冒充服务端停止。
