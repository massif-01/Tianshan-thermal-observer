# 唯一离线适配合同

输入为同run的`cpu-sidecar-arrivals.jsonl`、`sidecar-events.jsonl`、`states.jsonl`、`native-binding.json`、`launch.json`、native manifest/raw及source-config。wire仅作原始字节/接收一致性核对，不绕过测试端错误判定。拒绝/EOF/停止以sidecar-events最新语义撤销，完整被拒行仍在wire中；撤销ledger保留原事件/引用。

旁录CPU的source host/boot/session/seq、全部possible/online状态、累计计数、SC_CLK_TCK、前后读取窗保留。完整在线集合用同一对窗口，`busy=(sum首8差分−idle−iowait)/sum首8差分`；guest不重复加。CPU mean为完整在线集合的非加权均值，max为每时刻最大值。缺一项、计数回退/零窗、source明确incomplete或在线集切换窗口均撤销两者；不回找以前valid，也不缩小集合制造可用值。之后真实完整的新合法窗恢复。实际在线集合稳定后可恢复，离线核仍在原始possible/online映射中。

CPU update_id由真实source身份、seq与源读取窗构成，不能按数值去重。相同值的新合法窗保留；同一个buffer再次出现不增加确认/不续截止。新source session先撤销旧资格，下一合法窗才恢复；已退休source不得回来覆盖。native epoch变更撤销旧CPU/粗特征，不调用或重置原热观察器。

接收端时刻只用实际`received_at_mono_s`和`decision_generated_mono_s`，domain与native-binding/launch/真实state envelope一致。Mac联合样例的receiver boot未知就是null，不把domain中的会话UUID冒充boot。源端独立clock及前后窗不改名为接收时刻；source→receiver映射、传输延迟和精确源龄均未知。若接收端domain都不能关联，则拒绝把该文件放上此时间轴，输出明确failure，不作跨钟相减。

本轮冻结的是**接收顺序研究资格**：CPU只能在实际decision完成之后使用，支持截止不晚于真实received_at+1秒，与已有旁录无包停线预算对齐。这不是CPU源龄测量、不是0时延，也不修改生产TTL。若解析已经超过支持截止，立即不可用。真实60秒能力核对仍要补源时间/有效信息与开销证据，不能把此资格当成物理先导验收。

GPU与两rail只取同run保存的原生处理结果/raw，采用原source ref、GPU身份/采样标记和原有效截止。CPU包只携带这些粗来源的原值及原截止，不更新update_id、available_at或valid_until。最新原生失效/断连撤销BASE；CPU还在收包不能让BASE恢复。旁录直接查询的GPU/rail若独立窗/generation未知，原样放诊断，不造新身份、不与原生功率相加。

每个原有效TJ只生成一个thermal origin。该新接口的t为真实state envelope生成/可用时刻，原TJ接收时刻另存`measurement_received_mono_s`；不把刚计算出的状态倒填到较早raw接收时刻。全部分支共享这组约1秒起点及15/45/90秒/+2秒逐时距标签规则，缺90秒不删45秒。原旧run的raw时间起点评分原样保留，本接口不替换旧评分。Ts/E、当前TJ、条件PWM和安全状态完全取原state，不以CPU修正状态或热θ，不产生高频TJ标签。

顶层FRAME epoch是原native epoch，CPU source session/seq单独保留；不因CPU重启切断热过程或重置慢态。CPU跨session序号不可比较，所以FRAME中不伪造单调source_order，原序号在`source_order_original`，严格顺序/退休检查由本唯一适配层完成。原Activity仍只执行原冻结规则。

causal-1s-decimation是每秒选最后已到达的200ms统计窗结果，改变交付节奏，不重建真正1秒累计计数窗。正常/不适用/unknown分别保留。本轮只证明两端可执行衔接和撤销语义，没有新的CPU先导、温度预测增益、风扇控制或现场放行结论。
