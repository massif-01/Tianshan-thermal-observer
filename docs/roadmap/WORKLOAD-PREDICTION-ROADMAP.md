把已到达的运行历史变成未来两路功率轨迹，再通过热模型评价提前量，最终通过真实对照判断预测是否改善温峰、高温持续、热降频或风扇代价。业务模型在 Jetson，辅助预测器目标主机为 N305；训练可在独立计算环境进行，训练依赖与观察运行依赖分开。

本次 **DOC0 只提交文档 PR**：核对资料、拆任务、衔接入口；不训练、不安装依赖、不恢复 CPU 高频/12 请求研究、不采集、不发模型请求、不部署、不调风扇，不以规划自动批准任何后续现场动作。外部局部表面测温继续是研发参照，不是数值预测的全局前置。

## 4. 首轮统一合同与落实位置

以下是 #17 已确定的约束；WP0.4 将其落实成有哈希的实验 spec，而非现在编造阈值或让已用测试集成为新预登记。

### 4.1 数据角色、时间与样本

- 来源清单从 [dataset.json](../../experiments/thermal_mainline_calibration_v1/inputs/dataset.json)、[source-registration.json](../../experiments/thermal_mainline_calibration_v1/inputs/source-registration.json)、[original-source-inventory.json](../../experiments/thermal_mainline_calibration_v1/inputs/original-source-inventory.json) 和 observe 原件开始。每源登记 actual run UUID、device/config、软件/model/spec/时钟身份、原件哈希与保管位置、真实时长/采样周期、质量/事件完整度、既往用途。未确认物理配置用 null+原因。
- L/M/S 是已分析且进入冻结 G2 拟合的开发资料；Y/fixed-anchors 已被查看；本地长窗 run 是已分析的单一连续物理过程，字段副本、导出文件、质量段和请求行数不能变成独立过程。缺总结的原件先离线恢复身份、预测和成熟标签，派生总结不冒充原最终索引。
- 优先用不同完整真实 run 分训练/验证/确认。只有一个长 run 时允许透明回顾性时间外推：先登记真实会话/时间边界、过去状态预算和覆盖窗口及最长 90s 标签的隔离；现存 v1 的 60/20/20 不倒填为历史全盲。后续新确认 run 冻结前不看答案选参；一旦用于开发便登记用途变化。
- 起点只能使用到达截止前的遥测/事件；发生早但晚到的事件不可用。源 epoch/时钟/模型/配置边界不跨越，as-of 与原 TTL 保留；未知不补零、不使用未来插值。归一化、缺失处理参数、特征选择及 RELAX30 的两 rail P10 只拟合/统计训练侧。
- 输出为 GPU、CPU/SOC/MSS 两路独立 W 轨迹，不称两 rail 求和为整机功耗；CPU/SOC/MSS 不是纯 CPU。成功 PWM、目标 duty、RPM 不互代；百分比与 0—1 转换显式。未来 PWM 假设独立于 power 模型并对所有候选相同。
- 网格、窗口、重采样/区间均值含义在训练前冻结；可接续本地 60s 历史、5s 网格、18×2 区间均值，不能把它升级为唯一物理采样方式。明确其对短尖峰的损失和适配误差。
- 功率标签按区间独立保留缺失 mask；TJ 是目标后最早合格接收值、最多 +2s、不插值。训练可要求完整 90s 功率目标；评分分别保留合法 15/45/90s 标签，不能因 90s 不足删掉短时距答案。标签不跨保留分区边界。
- `LEGACY-R2-PAST60-REPLAY-v1` 与 `TTO-RECEIVE-ANCHOR-v1` 分表。首轮学习型比较接续同一保存的 RECEIVE-ANCHOR 因果状态；新预测分支复制当时状态，不用完整未来 M 或表面温度反推初态，不把 E=24°C 移用新 run。历史前缀是否带入后分区要写清，不与从零冷启动分数混合。
- 原始 prompt/output 不是默认输入；完成后才能知道的长度/耗时/usage 只作监督或事后分析。未发生计划、任务结束时刻、未来 Agent 步骤不进主比较；时间关联未知的跨主机值保持未知。

### 4.2 候选、轨迹与模型包

正式五候选固定为 **功率 HOLD、一个树模型、GRU、TCN、紧凑时序 Transformer**，三神经网络独立参赛；继续报告 **RELAX30** 功率情景及 **B0/B1** 温度参照，区分功率 HOLD 与 G2-HOLD。RELAX30 按原定义两 rail 各向 min(当前值, 训练侧 P10) 以 30s 时间常数回落，PWM 保持。不能挑某情景的逐点赢家。

接续本地有限搜索：ExtraTrees 深度 4/8（128 棵、最小叶 4），GRU 单层宽 16/32，TCN 三个因果残差块、核 3/膨胀 1/2/4，紧凑 Transformer 一层两头宽 16/32。固定种子 20261023；NN 上限 100 epochs、patience 15、batch 32；验证归一化两 rail MAE 选参，测试不选参、不补扫配置。它们是**已发生的本地 v1 设置**，由 WP0.4 核实原冻结记录；未来调整须先封新 spec，不能把这些参数冒称 DOC0 新运行或新的先验赢家。

拟新增轨迹协议须表达：历史截止/源引用、actual run/设备/模型/时钟身份、时间网格与区间语义、两 rail W/有效 mask、独立未来 PWM 条件、功率包 ID/SHA 和适配器版本；实际函数名/CLI 在 WP1.2 确定，不在文档伪造现成接口。恒定轨迹必须在预定数值容差内复现原 G2-HOLD；阶跃/分段轨迹按正确时间推进，预测不修改实时状态，所有候选共用同一起点/因果状态/风扇假设。容差有单位并在检查前登记，不因失败临时放宽。

power 权重/特征 schema/预处理/窗口/网格/依赖锁/设计与数据切分哈希、适用范围、代码版本和训练状态分别入包；G2 model/spec/运行时哈希独立保留。共享 registry 的审计、人工选择、新会话 pin/回退原则可复用，**现有热包 registry 未经适配不能直接登记 power 包**；组合 pin 需包含 power + G2 + adapter + feature schema。登记或本地加载不等于自动上线。

### 4.3 评价、决策与证据目录约定

功率层按 rail、15/45/90s 报 MAE/RMSE/bias，必要时附能量误差，不能混淆 rail 含义。温度层同起点/标签给 MAE、bias、P95 abs、P95/最大低估与覆盖，45s 为主同时保留其他时距。先定上升/高载/回落/空闲分层规则，给时间加权和完整过程等权视角；过程 n=1 就明示，不能把相邻秒当独立样本估显著性。

所有候选共享原始信息和历史预算、G2/状态、未来 PWM 假设；树可用统计、网络可用序列。逐时距保存共同起点/标签集合及其哈希，同时列全量有效 TJ → 计划起点 → 特征合格 → 各方法输出 → 成熟标签分母；保留不输出、缺失、降级与困难样本。真正实时以 receive+h 为目标，issued_at 是真实发布时刻，有效提前量 target−issued，迟到不能伪装有完整提前量。

A 类真实未来输入仅作热模型诊断，B 类只用起点已到达信息，两类分表。未来功率已知但 PWM 固定的诊断还须声明 PWM 未知限制，不把它当真实未来双输入 oracle 或上线成绩。缺失值不能用最终答案反填过去预测；发布账本只追加成熟评分。

晋级、保留基线、补数据、修改假设须有冻结规则和原因，均允许合法完成研究。数字门槛/容差/有限重复在 WP0.4 及 WP1.4 前登记；当前不编造必须改善 20% 或降温 X°C。差异接近训练随机波动时只做有预算的重复或过程级不确定性；不是无限调参。当前本地报告建议保留 HOLD，DOC0 不推翻它。

证据复用既有目录：本地候选以其原 `results/`、`verification/` 和原件清单接续；正式补充输出必须新建不可覆盖目录，用任务 ID 关联 job/spec、逐点预测、分母、报告、模型包与环境/资源。下面 `evidence/<任务ID>/…` 是**后续逻辑归档槽位，尚未创建**；也可在现有实验目录采用同等身份化子目录，不另建重复框架。原件不复制成“新数据”，私人原件只给清单/哈希/保管说明，公开链接须在实际归档后回填。
