# observe.11 常驻运行与 TianshanOS 文案修复

基于 main `5afaa8df`，分支 `fix/continuous-observe`。后端 `0.2.4+observe.11`，Web `1.0.0rc11`。本轮为本地代码、回归与安装包验证，不连接、部署或更改 N305。

## 运行与记录

- 默认不传 duration 时常驻；显式 duration 保留原限时测试的窗口、预算、停止和收尾行为。常驻登记明确 continuous，一次确认后可用相同配置再次启动；每次新进程使用新的真实 session/native/clock 身份，跨天不换身份或模型。
- 继续使用一个原生采集器、一个冻结有状态模型和已有发布/预测读视图。没有新增观察器、写入队列、模型恢复、设备写入或负载调用。
- DailyStore 复用 SessionStore 压缩写入实现，按 UTC 日期组织数据。正式预测和评分归属预测发出日；原生辅助日志按写入日。原始引用仍使用同一个运行 ID 和连续序号。
- 消费线程结清旧日的预测后，才标记可封存日期。旧日写入器脱离当前写入路径，哈希/fsync 使用现有异步线程池；退出只封存未完成的日期。保留当天加前 29 天，同步删除过期记录和索引，保护独立归档、其他设备/主机及未标记历史。
- 无新数据时按单调时钟结算缺标签；计时推进考虑原有可接受投递延迟，避免把已经收到、仍在落盘/投递的合格标签提前判缺失。标签窗口仍为目标时刻后 2 秒，没有放宽。
- 精确 P95 按预测发出日汇总，误差数组随日封存释放；累计计数没有次数上限。常驻汇总使用独立的 SCORING-DAYS 合同，不冒充全程 P95。小幅校时回拨不会重开已封存日，记录本身保留实际 UTC。
- 常驻移除测试累计字节/次数/CPU/RSS自停预算，保留资源记录、文件分片、唯一采集、身份和实际写盘失败边界。服务模板没有 RuntimeMaxSec；仅渲染用户服务，不启用或启动。
- 新日记录可查询和停止后逐日校验归档。已淘汰起始记录的窗口不当作完整运行重放；完整回放入口明确拒绝常驻日记录。旧限时明文/压缩记录仍可按原方式读取、回放和归档。按结算时间合并日评分，查询内存只保留所请求的尾部；查询可能扫描保留的评分文件，页面实时展示不走这条扫描路径。
- `TTO-OBSERVE-DAYS-v2` 的根文件清单登记每个应保留日索引的大小与 SHA，日期来自实际创建记录而非收尾扫描现存目录，校验值在日封存时固定，总收尾只核对而不重新认可当前文件；整天消失或日索引被等长有效 JSON 替换都会报错。正常淘汰先更新清单，再删除过期目录；已关闭会话的查询和 ZIP 都按清单读取，删除中断留下的过期残留不会混入归档。旧日布局 v1 缺完整清单，不能证明完整性，明确拒绝归档；旧限时会话仍兼容。复用原有原子写入逻辑，无恢复框架或额外日扫描器。
- 跨日维护一次只读取一个记录日期，用于评分结清与可封存日判断。原子替换每次使用独立临时文件，正常失败时清理本次文件；历史残留不被覆盖，也不阻塞后续淘汰。生产者与模型线程结束后，已有 `finalizing` 状态统一传给日写入器，再结清待评分预测、写日报/总报告与索引；只有收尾使用磁盘预留水位，普通采集水位、真实剩余空间检查及限时字节上限不变。最终评分、报告和根索引的存储失败统一报告 `recording_finalize_failed`，不补造成功结果。

## 文案

前端、翻译表、Web adapter 和实际后端发布编码统一使用 TianshanOS。删除动态追加的控制权后缀，复用已有只读说明；后台原因不再夹带重复控制权说明。指标 ID 和发布协议不变。前端源码与生成资源同步更新，未重写历史归档。
