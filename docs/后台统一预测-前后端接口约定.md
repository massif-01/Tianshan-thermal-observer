# 后台统一预测：给 Cloud Sonics 5.5 的接口约定

状态：PR #20 已合入 PR #16；整合 main 的前端时间说明，Web rc9 直接使用 forecast 的资格、ID 和剩余期限，移除前端 15 秒筛选规则。

## 分工与唯一来源

observe 后端负责 Unix 发布/补取、Web Python 接收与 `/api/v1`；浏览器保留 Cloud Sonics 5.5 的时间说明，并按后台资格和 ID 选取/撤回当前预测。不要继续依赖“预测起点必须等于最新 TJ 时刻”。

observe 仍是唯一采集/观察器。预测约每 5 秒一组（以合格新 TJ 为起点，间隔至少 5 秒），每组 15/45/90 秒。网页不计算预测，不自行选择实测评分。预测保存成功才对外可见，ID 使用 predictions.jsonl 的 prediction_id，评分来自 scores.jsonl。B0/B1 继续作为后台研究基线留档；页面 API 展示 G2-HOLD，正式展示/评分筛选 tracking/degraded；provisional 继续留档，不作为正式页面预测。

## 浏览器 API

保留 `/api/v1/snapshot`、SSE 和 `/api/v1/predictions?horizon_s=15|45|90&from=...&to=...`。所有 elapsed_ms 沿用 packet 的 origin_mono_s 时间原点，不是收到网页消息的时刻。

snapshot 增加 `forecast`，含：
- `provider: "observe-ledger"`；`status`: available / initializing / unavailable / disconnected / syncing / not_connected。
- `stride_s: 5`、`history_window_ms: 3600000`、`synced_through_cursor`（记录修订位置；同一 producer 内递增）。
- `remaining_valid_ms`：当前参考的剩余展示期限（预测起点 + 5 秒步长 + 原有 2.5 秒时效为上限，并受最新后台帧期限约束），独立于模型状态的 2.5 秒期限；由后台资格与发布接收状态共同约束。15/45/90 秒是预测跨度，不能当成展示有效期。
- `latest_prediction_ids`：可作为当前参考的三个正式预测 ID。只有 status=available、期限未到、数据连接正常时才可展示。新实测到来不要求重算或改动旧预测起点；设备失效/模型重置会撤销当前参考。

snapshot.predictions 保留既有基本字段，并增加 `issued_at_utc`、`target_at_utc`、`origin_at_utc`、`conditional_assumptions` 和 `revision`：
- prediction_id 原样使用后台账本 ID；run_id 保持现有 Web 短别名，另加 ledger_run_id 保留完整后台 run_id；model_id=后台 model_sha256，另加 backend_model_id 保留模型逻辑名称；spec_id=后台 spec_sha256；source_epoch、scenario=HOLD、horizon_s；
- origin_elapsed_ms、issued_elapsed_ms、target_elapsed_ms、input_cutoff_elapsed_ms；value_C、phase_at_origin、evidence_mode；
- status: pending / matched / missing_label / not_comparable / late_publication / unavailable；observed_C、error_C、reason_code。value_C不可用时为null，不能显示成0。

时间字符串由后端原始记录的签发 UTC + 同一单调时钟差换算，UTC 仅用于显示；遇墙钟跳变，目标和评分仍按单调时钟判断。前端可显示“最近一次预测（n 秒前）”及具体目标时刻，不把旧预测重新称作“从现在起 +45 秒”。不得修改预测值/起点/目标或生成新 ID。

`/predictions` 保持 records / labels / summary，并带 `provider`、`sync_status`、`synced_through_cursor`。sync_status取synced / syncing / unavailable / not_connected；读视图失败时unavailable且records_complete=false，不宣称记录完整。summary 依据后台评分、snapshot.prediction_history_identity 指定的 run/epoch/model/spec、所选 horizon、页面正式阶段及 from/to 范围计算。MAE 不混入缺标签、未到期、不可比较或不可用预测。records_after 沿用时间增量参数，评分更新仍须返回；records_complete 表示响应是否完整。页面缓存仍按 prediction_id 覆盖更新，不累加重复计数。Web Python 的 advisory 同样使用 latest_prediction_ids 与当前资格，不再要求预测起点等于最新 TJ。

增量筛选使用 Web 收到新修订的本机单调时间，换算到同一 origin_mono_s 原点；它只存于 Web 内存，不修改或替代记录中的后台签发、目标、结算时间。断线后补回的旧预测或评分也须返回；重复接收同一 revision 不算新更新。该内部时间随记录过期、随发布者切换一起清理。conditional_assumptions 无内容时为 null，正常假设对象原样保留。

## 断开、恢复与边界

- 浏览器关闭、Web 服务重启或发布丢帧：observe 的预测与评分不变；Web 通过本机只读补取恢复本次观察最近 60 分钟，再切回已同步状态。同步中可以保留历史，但不得宣称统计完整或展示当前参考。
- 仅 Web 断开不把后台 pending 改成 not_comparable。重新接上后以后台真实结果为准。
- 设备数据失效：撤回当前参考；历史原预测保留。到了目标后，原有后台规则用目标时刻后 2 秒内首个合格 TJ 验证；没有则缺标签。重置/换来源导致不可比较时，后台明确记原因。
- follow 是唯一生命周期负责人：读取并校验描述文件、回收旧接收任务，再切换 publisher_id 和启动接收。实时与预测子任务不读取描述文件、不决定身份切换。新发布者清理旧游标、实时上下文、曲线和预测缓存；同一发布者重连保留已有历史。新发布者已结束且没有实时帧时，也能直接恢复其最终预测快照。不能跨观察过程拼接评分；旧 epoch 的记录可以留在后台档案，当前页面不混用。正常终态单独选取最后一组正式预测的身份供历史查询，实时身份仍保留最后一帧的真实停机边界；两个身份在页面上明确区分。
- 兼容旧版仅含 schema/boot_id/ended=true 的无身份结束描述文件：撤销当前显示并等待新注册，不补造 publisher_id，不据此结算或宣称预测账本完整。描述文件缺失或格式无效时，同样撤销当前显示并等待有效注册；不终止跟随入口。
- 不支持正式预测的旧发布源显示 not_connected，不退回 Web 计算。
- 本轮不恢复过去整轮归档到页面，不跨进程重启续接旧观察器，不改模型、不改采样频率、不改设备控制。

## 正常结束与发布失败（observe.6 / Web rc8）

实时身份 `run_id/source_epoch/model` 始终来自最后一帧；正常停机的新空 epoch 不回写为旧 epoch。预测页另给 `history_identity`，正常结束时指向保留窗口内最后一组 tracking/degraded 记录的真实身份，没有正式记录则仍为空组。运行时它等于实时身份，不跨 epoch 查找当前预测。Web snapshot 提供 `prediction_history_identity`，预测 API 也返回 `history_identity`，缓存按这个完整身份清理；同一组内统计，不拼接不同 epoch。终态不滚动延长时间、恢复当前预测或补造记录，Web 冷启动同样可从最终文件恢复。

snapshot 的 `publication_status` 为 waiting / live / ended / failed，页面遇 failed 明确显示“发布失败 · 最终结果未确认”；不能把 Web 自身连接正常当成采集或收尾正常。最终快照生成并写成功后才登记 ended；生成、写入或成功登记失败，只尝试一次失败登记。若整个目录不可写，失败通知本身也可能无法持久化，此时发布错误记入后台结果、socket 关闭、实时资格撤回，不虚构成功；原始账本和日志须保留排查。

## 内部接入（Codex 实现）

描述文件保留 publication.sock，并新增 prediction_socket=predictions.sock 与预测协议版本。原实时快照仍可丢弃；独立本机只读查询按 cursor 分页补取已提交记录，单页最多 128 行，不扫描“最新目录”，不访问设备。后端保留最近 60 分钟 G2 紧凑读视图，记录修订游标覆盖签发与评分更新；读视图不是第二套预测器。每页按 revision 排序，返回 cursor 只推进到实际交付的最后 revision；has_more=false 后才确认当前 watermark，不能第一页就跳过尚未收到的行。同一 ID 后续评分修订可以重发覆盖。正常结束先写终态 predictions-final.json，再标 ended；快照含 publisher/boot身份与最终cursor，当前参考永远撤回，历史时间轴停在结束时刻。发布线程异常退出写publication_failed=true、ended=false，不生成正式终态；后台观察状态未知，不宣称观察已正常结束或最终评分已同步。Web 同步由独立任务执行，读取原消息不等待历史补取。

入口只按协议状态要求字段：运行态要求非空 publisher_id 和固定 publication.sock，预测能力须同时提供固定 predictions.sock 与协议版本；正常结束带 predictions-final.json 时仍要求身份；发布失败要求身份且不能同时声明正常结束。旧版匿名结束单独识别。每次状态切换先取消并等待两个旧子任务退出，再修改状态；未知子任务异常由入口观察并向上传播，退出时回收其余任务、撤销当前显示，不增加吞错重启兜底。

## 共同验收

同 ID 的温度、起点、签发时间、目标、模型身份、实测和误差与后台记录一致；刷新/重连不改变预测及分数；断流撤回当前值，恢复不能伪造连续；慢网页不影响采集落盘。本轮整合增加本地 HTTP/SSE、浏览器与独立安装包验证；现场短测须在用户确认旧测试归档后，按其另行授权进入独立目录和环境。不合并 PR，不覆盖历史记录或安装；汇总及历史结果见 [发布验收报告](reports/observe-publication.md)。
