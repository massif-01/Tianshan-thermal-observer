# TTO Web UI 产品需求文档

**版本：TTO-WEB-PRD-v1.0｜2026-10-20｜状态：供独立Web UI任务实施与复审**

产品名：**TTO 热观察台**。部署目标：N305／16GB／Linux，沿用项目支持的Python环境。服务端口：**59009**。本文定义产品、页面与交互；`03-接口与计算合同.md`定义前后端数据；`02-给Codex的开发指令.md`定义执行任务。本文是需求交付，不代表Web UI已经开发或部署。

## 0. 一页决策

本次做一张专业、紧凑、可长期打开的**只读监看页面**。首要内容是温度、功率和PWM趋势；热模型小节点、预测与观测对照、当前运行语义必须真实实现，不能只画静态占位。支持后端字段整理、因果计算和版本化观察建议，但不新增未知设备数据。

- **保留并默认展开：**紧凑指标条、三个纵向趋势图、A事件标记带、C热模型节点图、D预测与实测对照、E当前运行上下文。
- **保留但默认折叠：**B数据源详细健康、完整事件/告警、所有已接入字段。
- **不做：**摄像头／红外画面、结构温度传感器及YET接入、录制管理、历史run播放器、诊断操作页、训练按钮、负载控制、风扇写入、功耗模式修改、源采样设置。
- 当前风扇仍由**TianshanOS**执行。页面上的目标、参考和估计都不构成设备指令。
- 不沿用旧示意图中的假日期、3200 RPM、72%建议、0.78置信度、5分钟预测或“过热概率”。PRD和数据合同优先于所有旧效果图。

## 1. 产品目标与使用场景

### 1.1 核心目标

用户在同一屏里回答：**现在测到什么；最近怎样变化；模型怎样理解它；之前的预测与后来实测差多少；机器和TTO此刻分别在做什么。** 无需去日志里对齐每份JSON，也不需要理解内部字段名才知道读数是否过期。

### 1.2 三个主要场景

| 场景 | 用户动作 | 预期结果 |
|---|---|---|
| 日常监看 | 打开59009页面 | 有当前生产者就展示其真实数据；配置为独立观察时只有一个只读采集源；未配置时明确等待，不显示演示数字 |
| 实验旁观 | 已有测试进程在运行，另开网页 | 只订阅同一run，不启动第二采集器、不发新请求；曲线与阶段标记能对上 |
| 产品展示与解释 | 打开热模型和预测对照，暂停画面/放大区域 | 小节点表明真实输入—状态—输出；说明实验性边界，暂停只影响画面不影响采集 |

### 1.3 成功标准

三大趋势可同时阅读；C/D/E不是未来待办；已取得字段可在主面板或字段抽屉找到；数据到期、断连、模型暂不可用的表达真实；安装候选具备自动服务启动能力，浏览器数量不增加设备轮询或热模型计算次数。源采样、TTL、控制行为不改变。

## 2. 已知能力、缺口与本次新增

以下是本轮读取既有交付和原始记录得到的边界，不拿公开main或效果图替代实际运行版本。详见`reference/数据核对摘要.json`及`04-字段来源与能力矩阵.md`。

| 项目 | 既有事实 | 本次怎么做 |
|---|---|---|
| TJ、CPU/GPU/SoC温度、逐核CPU、RAM/SWAP、rail | 原始WS记录有对应字段；Thor GPU利用率带独立NVML年龄 | 按现有质量结果映射，保留每项单位/来源/时间；不新增源查询 |
| PWM、模式、gain、主板预测/斜率、故障/失温 | 来自主板fan/status和temp/status，不来自tegrastats本身 | 区分成功输出、主板目标和主板预测；不改原接口 |
| RPM | 核对的fixed-anchors原包2710份成功fan记录均原报rpm=0且running=true；无独立测速有效性字段 | UI保留RPM能力和原值，但默认显示“测速有效性未确认（原报0）”，不写“已停转”，不从PWM换算RPM |
| Tf、Ts、E和模型状态 | 现有冻结顺序估计器输出，包含协方差但明确未校准 | 可实时映射；Ts称“慢热状态（估计）”，不称结构测温；不造0—1置信度 |
| G2未来TJ | 已有离线B-HOLD评价数学与冻结θ，现场状态不等于已经生成全部未来预测 | 新增轻量只读因果预测发布与到期评分；不是重训、不是使用未来真实输入 |
| 平稳需求 | 已有离线增量指数/塑形；不是PWM百分比 | 有有效版本化provider时显示原单位与参考；未接入时保留“本轮未计算”状态，不把指数×100变PWM |
| 建议PWM | 当前没有已验证的G2→最佳PWM控制器 | V1保留“PWM观察建议”区域；接真实建议provider或按本PRD的已核对曲线映射，不能伪造完整控制优化器 |
| 任务/并发/推理模型 | 测试runner有日志；普通tegrastats/WS不能知道用户提交了什么 | 有已接run事件就展示；无则“未接入任务记录”，不能从GPU高占用猜4并发 |
| 结构温度、环境测温、摄像头 | 当前UI不接入 | 不设置卡片、曲线、节点或配置页；E是内部边界不是环境温度 |

**术语处理：**用户口述“Tiger Test”在现有资料未找到同名接口；本需求使用已经存在的遥测链（tegrastats/NVML经WS、TTO、本机已保存的TianshanOS状态和任务事件）。不建立新同名系统，也不假定tegrastats独自提供风扇、任务和模型状态。确实没有来源的字段，不生成数值。

## 3. 信息架构与页面布局

### 3.1 一页为主，不做控制台式多级菜单

主路由`/`。顶部页内锚点：**趋势｜热模型｜预测对照｜运行信息**。不保留侧边“录制”“回放”“诊断”“设置”页面。右上角只有时间范围、显示设置、暂停画面、全屏；显示设置仅影响浏览器本地偏好。

布局从上到下：

| 区块 | 默认状态 | 桌面参考尺寸/关系 | 主要内容 |
|---|---|---|---|
| H 顶栏 | 展开 | 高约52px | 名称、只读标识、被观察设备/TTO主机、服务/数据/模型状态、数据时区 |
| K 紧凑指标条 | 展开 | 单格高约56–64px；宽约120–150px；大屏一行，窄屏两行 | TJ、CPU温度、GPU温度、成功PWM、RPM、两rail、CPU/GPU利用率、RAM；可横向溢出，不放大撑满 |
| T1 温度趋势 | 展开 | 宽100%，图高约200–220px | 默认TJ/CPU/GPU；已接SoC及主板控制温度可勾选 |
| T2 功率趋势 | 展开 | 与T1同宽，图高约180–200px | 两条独立主rail；其他已有rail可选 |
| T3 PWM趋势 | 展开 | 与T1同宽，图高约180–200px | 成功PWM主线；主板目标和有效RPM可选；RPM用独立右轴 |
| A 事件带 | 展开 | 28–40px，同一时间轴 | 开始/结束、并发、暂停恢复、失温、模型阶段等有来源事件 |
| C 热模型节点图 | 展开 | 下区左约58%；最小宽620px、高340–420px | 小节点与连线；实时输入、内部状态、预测及独立观察输出 |
| D 预测与观测对照 | 展开 | 下区右约42%；高约260–300px | 15/45/90秒选择，已经到期预测与实测，误差/样本数 |
| E 当前运行信息 | 展开 | D下方，或窄屏独占一行 | 被观察模型/任务、TTO模型、控制归属、数据模式、run和观察时长 |
| B 数据源详细状态 | 折叠 | 单行摘要，展开表格 | 每项源年龄、连接、最近成功、错误、实际间隔 |
| 事件/告警明细 | 折叠 | 单行计数，展开列表 | 事件发生时间、来源和直白解释 |

本页允许自然纵向滚动，不以“全部塞进一屏”压成无法阅读的字。1920/1440宽度三张趋势全宽，C/D并排；≤1100宽度C、D、E依次纵排；手机允许单列，节点图可水平拖动但不能把C/D/E隐藏。不得恢复大圆盘或大号卡片。

### 3.2 页面内默认关注顺序

趋势是主视区；C/D/E是第一版不可裁剪内容。指标只作速读，不取代趋势。B/详细事件/字段抽屉节约空间，但持续存在的“来源失温”“数据断开”等重要状态必须在顶栏保留提示，不要求用户先展开才能发现。

## 4. H与K：顶栏、关键指标和真实状态

### 4.1 顶栏

左侧“TTO 热观察台 / 只读观察”，不叫“风扇控制台”。设备名和主机明确分开，例如“观察对象：RM-01 Thor｜TTO主机：N305”。右侧分开显示：Web服务可访问、设备数据最近更新、模型阶段。网页连上不能等同设备在线。

显示TTO版本、热模型版本短名和run短ID可放详情，不在顶栏铺一串SHA。展开信息时可复制完整非敏感身份。时间轴默认用N305配置时区，页内注明；浏览器在其他时区不能静默转换同一屏的部分时刻。

### 4.2 指标条

默认顺序：TJ / CPU温度 / GPU温度 / 当前PWM / RPM / GPU功率 / CPU·SoC·MSS功率 / GPU利用率 / CPU平均利用率 / RAM。

数值建议温度1位小数、功率2位、PWM整数、利用率0–1位，原始精度在tooltip可看；不声称显示精度等于传感器精度。RAM同时显示来源单位及used/total，不把来源MB私自叫GiB。可在显示设置收起低关注项，C/D/E不可作为默认裁剪项。

卡片包含小标题、数值、单位、微型状态标识；sparkline可有但不超过卡片下沿20px。任何含最后一次值的卡片都可查“几秒前取得”。零是真实数值时保留；缺失用“—”而不是0。

| 状态 | 主显示 | 简短解释 |
|---|---|---|
| 正常有效 | 当前值 | 最近更新0.8秒前 |
| 到期 | —；次级灰字上次值 | 暂无新读数，上次68.2°C（6秒前） |
| 明确失效 | — | 温度来源已报告失效 |
| 不支持/无字段 | — | 当前设备未提供 |
| 仅测速语义未确认 | —；详情原报rpm | 暂无可信转速（原报0） |
| 模型暂定 | 值+“初始化参考” | 正在积累状态，不代表准确度已验证 |

不把RPM=0、running=true直接推导成故障或停转；也不隐藏原报0。确认设备有可靠测速定义后，零转速才可作为该测速量展示，仍不自动推出故障。

## 5. T1/T2/T3：三个核心趋势图

### 5.1 公共交互

统一选择最近5/10/30/60分钟，默认10分钟；三图共用时间范围、缩放和光标。悬停同一时刻时，各系列显示自己的最近有效样本时间与年龄，不能把不同采样时刻拼成一份同步测量而不说明。

“暂停画面”只固定当前窗口并显示暂停起点；后台和其他用户继续观察。恢复后跳至实时，不补造缺失点。“全屏”或“放大此图”是显示功能，不改变源频率。

趋势按时间排序；相同值的新采样保留，重复缓存不新增样本。到期、断连、run/epoch切换绘制缺口或边界，不跨缺口平滑连接。前端可以动画滚动，数值曲线不能启用会抹掉尖峰的样条平滑。长窗下采样必须保留桶内极值、首末、缺口与事件；tooltip明确“区间最小/最大”，不能冒称每个渲染点都是真实采样。

### 5.2 温度

默认实线为实测TJ、CPU、GPU，单位°C。同名传感器只能按源语义，不把TJ叫CPU温度。主板控制温度是另一份状态量，可选虚线且注明主板来源；不是新增结构温度。

可选叠加“已经到期的TTO +45秒预测”时，预测点放在**目标时刻**；默认不开未来扇形覆盖主图，以免挤压真实温度。模型Tf/Ts在C及详情显示，非默认实测曲线。绝不画“实测结构温度”“出风空气温度”“室温”。

### 5.3 功率

两主线完整标签：`VDD_GPU`、`VDD_CPU_SOC_MSS`，单位W；从源mW除1000。`VIN_SYS_5V0`等确已拉取的其他rail可在图例追加，默认不挤占主线。current与average保留不同语义，平均窗未知要说明。没有合法汇总定义不画“整机总功率”，不把rail名称VDD误当电压V。

### 5.4 PWM/RPM

成功PWM为主线，0–100%左轴；主板`target_duty`可选，名称“天山OS目标PWM”，不能称G2建议。RPM可选右轴且独立单位；测速未确认时不绘伪转速线。建议PWM可选细虚线，来源/算法/version必须显式标注，不能叠成已执行曲线。

主要趋势不作“越低越好”的排序。慢退可能是既有策略或热历史，UI不将慢退本身判成告警。

## 6. A：事件标记与时间轴

主图下方始终保留简洁事件带，与三图共用光标。来源包括已接runner/scheduler/protocol、TTO质量/模型状态、主板明确flag，以及Web显示链自己的断连。不得从GPU波动自动构造“用户提交”“4并发”“模型切换”。

事件类型：run开始/结束；工作块开始/结束；已知并发槽位变化；有来源的请求开始/协议完成；任务暂停/恢复；主板失温/恢复；采集断开/恢复；模型初始化/降级/恢复；Web数据重同步；可选已存在人工备注。没有来源的类型不触发。

密集请求可聚合为“此处12条请求事件”，放大后看单条；默认每个视口不超过8个文字标签，标记本身保留。点击显示发生时刻、记录/到达时刻、事件来源与含义。协议完成不说GPU已空闲；停止调度不说所有服务端任务已退出。

完整事件表默认折叠，按时间倒序，可按来源/级别筛选。连续重复错误显示首次/末次/次数，恢复另记一条，不每秒弹Toast。不提供“清除设备告警”“删除历史事件”按钮。

## 7. C：热模型小节点图（核心必做）

### 7.1 图的语义

采用小型矩形节点、细连线，不用3D散热器、芯片照片或巨大卡片。节点宽约112–156px、高44–64px，最多两行文本和一个主值。节点布局固定、数值更新不跳位置。

**核心G2路径：**

- GPU功率节点、CPU·SoC·MSS功率节点进入“快热状态Tf”。
- Tf与“慢热状态Ts”按真实等效耦合关系连线；PWM作用于慢态的散热项。
- TJ以**测量校正**虚线进入状态估计模块，不画成另一条发热功率。
- E是“等效边界（模型内部）”，默认放慢态详情；不是环境传感器节点。
- 当前状态+冻结θ+明确输入情景进入“TJ预测参考”，输出+15/+45/+90秒。
- RPM、CPU利用率、GPU利用率、RAM放“运行观测”一侧，不擅自连成当前G2动力学输入；失败的CPU活动候选不自动启用。

**观察支路：**真实保护状态卡独立读取主板flags；平稳需求、PWM观察建议使用各自provider。没有provider时节点仍在，显示原因；没有真实依赖的边不动画，不能画成G2已给出可靠风扇闭环。

### 7.2 节点清单

| 节点 | 主显示 | 点击详情 | 失效处理 |
|---|---|---|---|
| GPU功率 | 当前W | rail原名、单位转换、源ref/时间 | —并停止对应连线脉冲 |
| CPU·SoC·MSS功率 | 当前W | 非纯CPU说明、ref/时间 | 同上 |
| 当前PWM | 成功百分比 | 原duty/target、原始有效性、年龄 | 上次值仅灰字；条件保持不是测量 |
| TJ观测 | 当前°C | 温区/来源、测量校正含义 | 不用Tf填补为实测 |
| 快热状态Tf | 估计°C、phase | 当前观测残差、已用信息截止 | 暂定/降级有标识；不可用显示原因 |
| 慢热状态Ts | 估计°C、phase | “模型内部慢变量，不是结构传感器读数”；内部不确定性可展开 | 保留状态历史与当前资格分开 |
| 预测参考 | 重点+45秒，附15/90 | 起点/目标、情景HOLD、数据截止、model hash | 无模型时明确未启用，不用B0假装G2 |
| 当前保护反馈 | 未报告保护/保护中/未知 | guard/fault/stale各自三态 | 不把unknown显示正常、不造风险概率 |
| 平稳需求（研究） | 原单位index或相对量 | 算法、固定参考、输出含义、重置/缺口 | 无可信provider就“本轮未计算” |
| PWM观察建议 | 有来源的参考百分比或未就绪原因 | 见§10，非设备指令 | 原因文本，不填假百分比 |

### 7.3 动效

沿线轻微流动点只代表数据传递/计算关系，不代表瓦数、热流方向实测或传热速度。仅对当前有效依赖动画；降级使用虚线/暂停脉冲，未知显示静态线。支持prefers-reduced-motion、后台页和暂停画面时停止动效。不能为了动画每帧请求后端或重算模型。

## 8. D：模型与观测对照（核心必做）

### 8.1 一个清楚的主问题

默认选+45秒：**过去发出的45秒预测，到了目标时刻，实际TJ是多少？** 主图实线为实际TJ、虚线为该时距的已发布预测；以目标时刻对齐。15/45/90切换后图和指标同时切换，不能混时距。

右上角未来参考显示“现在发出的+15/+45/+90秒预测”，与已经到期的验证图分开。点数只有3个时，不绘假装已计算的5分钟连续预测。可用折线连接3点须标明“仅连接参考点”。

### 8.2 时间与误差规则

每条预测保存`prediction_id、run、epoch、model/spec、scenario、origin、issued_at、target、horizon、input_cutoff、value`。预测的“45秒”从观测截止origin计算，另显示实际发布时刻，不能把计算延迟藏进提前量。实际发布晚于target不得进入实时预测验证。

标签使用已核对的冻结合同：同source epoch、目标时刻之后（含目标）的第一条有效accepted TJ，允许延后最多2秒；15/45/90秒各自匹配。适配实际代码时核对这一合同，不得临时扩大匹配窗凑样本。新页面分数只取Web观察过程中真正已经发布的预测及随后到达的有效TJ。历史文件事后计算出来的预测不得冒称当时已发布。

误差定义固定为**预测−实测**：正数“预测偏高”，负数“预测偏低”。没有到期答案显示“等待实测”；到期但没有合格标签显示“缺少对应实测”；模型/run切换、身份或时钟不可比时不强配。答案未到时绝不拿当前TJ减未来预测。

### 8.3 指标

紧凑摘要：当前时距、最近匹配时刻、预测值、实测值、带方向误差、当前窗口MAE、绝对误差P95、最大低估、匹配样本数/应到期数。指标按同run/epoch/model/scenario/horizon分组；样本不足用数字+“样本较少”，不用凭空的准确率百分比。

“Tf当前观测残差”另在模型详情中展示，不和未来预测误差混算。A类使用实际未来功率的优秀成绩不出现在实时预测主面板。未校准协方差只可显示“模型内部不确定性”，不得画成保证95%覆盖的置信带。

无模型、初始45秒未满、降级、只有遥测四种状态都保留D区，不留空白错误页，也不删掉该功能。

## 10. PWM观察建议与平稳需求：必须有区域，数值必须有依据

### 10.1 三个不同东西分开

**当前PWM**是已成功执行值；**天山OS目标PWM**来自主板`target_duty`；**TTO PWM观察建议**是新增或已接provider的计算参考。三者不混名，不因为两者恰好相等就只留一条“建议”。

### 10.2 V1的可实现数值路径

采用轻量`advisory provider`接口，按以下顺序启用，不自动搜索“最佳PWM”：

1. 若当前工程已有明确版本、输入截止和输出语义的只读建议provider，复用并展示真实身份，不复制另一个算法。
2. 否则，可新增**CURVE-REFERENCE-v1**：仅在已有本地记录/配置里取得并核实与当前设备一致的温度→PWM基础曲线时，用真实当前TJ与+45秒HOLD预测取较高值作为`T_ref`，按该曲线原有插值/限值计算`u_ref=f_curve(T_ref)`。这个新计算是“依据现有曲线与条件预测的参考”，不是复刻含gain/保护/延迟的天山OS完整控制器，也不是G2逆向优化。
3. 没有经过核对的曲线或真实provider时，仍显示建议区域，明确“暂无可用建议映射”；不添加默认75°C目标、不套旧错误曲线、不新拉设备配置来伪称已取得、不令需求指数×100或用当前PWM冒充建议。

使用CURVE-REFERENCE时，曲线ID/hash/设备及温度绑定匹配、预测ID/时距/HOLD假设、T_ref、取值域均随值交付。曲线域外、数据到期、模式改变、明确stale/guard/fault或保护未知时撤下数字；说明“暂停建议，天山OS继续负责保护”。不对缺少45秒预测静默改成只看当前温度；要有独立且明确命名的provider才显示不同路径。

**该映射是本次新增的展示计算规格，不是已经验证的控制算法。** 即使显示比当前输出低，也不出现“风扇过转”“应立即降速”等建议。能计算参考，不等于改变风量以后能保持原温度。没有批准的新算法不由Codex临场发明。

### 10.3 平稳需求

已有需求provider可按原index、原参考和更新规则实时化，但必须保留来源、参考建立时刻及失效重置。只有离线研究指数而无当前有效状态/参考时不能持续播放旧曲线；显示“本轮未计算”。慢退不默认判失败，零相对增量不等于基础散热需求为零。

首版整体交付不因缺少建议映射全局停工。C/D/E要完成真实分支和明确不可用分支；**没依据的百分比不属于“后端包装一下”就能补出的事实。**

## 11. B、事件告警与全部字段抽屉

B折叠摘要显示“数据源：2路正常 / 1项待确认”等真实计数；展开为来源、最近接收、实际更新依据、年龄/到期、连接、错误类型、run/epoch。WS在线、HTTP成功、温度有效、模型可用四者分开。

告警只传播现有明确设备事件或展示链事件；不新增跨Jetson统一90°C报警阈值。设备提供合法阈值才可画其阈值线，注明来源。未知保护不写“系统安全”。

字段抽屉按温度、CPU、GPU、内存、功率、风扇、模型、主机/通信分组，保留所有当前已拉取且可公开的数值/状态；支持名称搜索。高频逐核旁录只在现有旁录已就绪时消费，不借Web UI开启SSH/jtop或改变200ms/1s源设置。默认使用原WS逐核数据，不能以一块空图强制开启旁录。

原始数据展示须allowlist；不发送认证header、授权聊天、推理prompt/回复、私有绝对路径、模型权重路径、SSH参数或整个binding。调试源引用可用脱敏run/ref，详细设备信息只显示用户配置的名称。

## 12. 服务与采集生命周期

### 12.1 安装以后是什么样

安装候选包含后端、编译后静态资源、配置模板、服务文件和独立卸载/回退。**正式获准安装以后**启动`tto-web.service`并开机自启，监听59009；没有数据也能打开页面并显示准确等待原因，不能将“装了包但端口没起来”算完成。运行不依赖Node、CDN或外网。

### 12.2 数据来源模式（一次配置，不在网页里启动实验）

- **follow（实验/现有采集首选）：**消费当前明确注册的本地active-run描述及只读发布流。已有测试进程拥有唯一collector/observer，Web只追踪它。源未注册/已结束就显示等待/结束，不扫描最新mtime文件并认作现场。
- **observe（日常持续监看）：**安装时显式配置只读观察进程，复用现有collector和冻结observer，不构造Requester，不执行测试计划。只有确认公共采集锁及端点配置后可启动；已有活跃生产者时不争抢、不重复读取。不能仅改一个诊断duration为无穷而产生无限原始日志。

默认follow避免打断既有实验；安装器必须说明怎样选择observe来实现无人值守日常监看，并给实际可运行入口。两种路径都需要实施/本地验证，不以“后续再接”代替。若安装时缺设备配置，仅起Web壳并明确“尚未配置观察来源”。

不自动杀或接管其他进程。observe与实验的切换在主机CLI/明确操作卡中完成，原实验关闭/开启有原权限边界；网页没有停止collector或启动负载的按钮。若旧入口未参与共享锁，必须接入最小统一拥有权或要求安装配置显式follow；不能在无法确认单实例时自动开observe。

### 12.3 展示不反向影响观察

生产者每个更新只做一次非阻塞只读发布；慢浏览器/后端队列溢出允许显示侧丢帧并标注，不反压采集和状态估计，不改原始证据。Web重启不让外部实验停掉；观察进程重启导致数据epoch变化，曲线明确断开。只清理自己的资源。

## 13. 后端和接口原则

优先沿用现有aiohttp依赖提供HTTP+SSE，前端TypeScript+Vite+ECharts，节点使用SVG/CSS。不是强制升级底层依赖；如现有前端工程已用等价栈，记录差异后复用，避免并行两套框架。

后端负责字段单位、来源/质量、时间轴、模型只读预测、成熟配对和建议provider。前端只格式化、交互、画图，不自己训练、不重建质量规则。SSE单向推送，心跳只证明UI链路，不给设备字段续龄。

完整接口见`03-接口与计算合同.md`与`contracts/dashboard.schema.json`：boot/capabilities、snapshot、series、model、predictions、events、context均由一个版本化公开快照派生，接口不返回原始敏感对象。

## 14. 性能、可用性和边界

默认UI更新1Hz；已有200ms数据可以缓存保留，由显示侧按预算合并，不能驱动源提频。SSE心跳5秒，快照与质量到期按自身事件发布；前端依据后端给的剩余有效期本地撤销数字，UI网络断开时立即标断开，不必等最后一条device数据再次到达。

展示缓冲默认最近60分钟，限定系列/事件/客户端队列；不新增全量录制数据库。observe监看模式采用有界显示缓存和小型限额诊断日志，不按实验原始每秒大JSON永远写盘。滚动保留策略只作用新Web目录，不删既有run。成熟预测表可维持当前60分钟加最大90秒待匹配，不按浏览器开启次数重复计算。

研发目标（待测，不是假现场成绩）：1浏览器持续30分钟，Web附加RSS≤192MiB、均值CPU≤5%单核等效；4客户端时原生请求并发/频率与无UI一致，源回调非阻塞。达不到先报告热点与真实数值，不能降低源频率/放宽TTL凑通过。前端首屏本地静态资源≤3MiB压缩、关键趋势可操作，不要求追求没意义的极限包体。

## 15. 访问与只读安全

默认本机`127.0.0.1:59009`；安装器提供显式LAN模式，设置N305监听地址/允许访问来源及只读口令。要从另一台电脑看时使用N305地址，不把那台电脑的localhost写成设备地址。不自动改防火墙、UPnP或暴露公网。

LAN访问使用一次本地生成的只读访问凭据和会话cookie；不要把令牌放URL/SSE query或日志。HTTP只适用于可信本地网络，不声称加密；已有TLS反代可复用，但不为首版建设账户平台。无凭据时不能启动匿名对外监听；无权限部署systemd如实交service候选和安装命令，不假称已自启。

除登录/退出会话外，业务API均只读。没有PUT风扇、执行Shell、代理任意URL、启动任务、改配置/阈值/模型的接口。页面偏好存在浏览器，不改变设备。恶意源字符串当文本显示，不插HTML。
