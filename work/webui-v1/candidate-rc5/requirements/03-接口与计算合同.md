# TTO Web UI 接口与只读计算合同

**TTO-WEB-API-v1.0｜配套PRD v1.0。** 下列是本次新公开DTO设计，不是上游现有字段名。`04-字段来源与能力矩阵.md`给已核对输入路径。数据适配只做来源/单位/有效性映射；所有新增计算带method_id和版本。

## 1. 原则与来源等级

统一`kind`：`observed`（设备原报）、`derived`（确定性聚合）、`estimate`（模型状态）、`forecast`（未来条件预测）、`advisory`（观察参考）、`configured`（本地登记）。配置里的模型名、静态方案不能冒充当前现场查询结果。能力与当前值分开：`supported:false`不是零，`supported:true`但数据过期也没有当前数值。

Metric公开结构：

```json
{
  "id":"power.gpu", "label":"GPU功率", "kind":"observed", "unit":"W",
  "value":26.532, "status":"valid", "reason_code":null,
  "source_ref":"run-alias/observation:42", "source_id":"jetson-ws", "sample_id":"epoch-2:123",
  "source_time_utc":null, "received_at_utc":"2026-10-20T10:00:00Z",
  "as_of_elapsed_ms":120000, "age_lower_bound_ms":150, "remaining_valid_ms":4850,
  "time_quality":"receive_approximation", "last_observation":null
}
```

这是格式样例，不是当前设备数据。所有同一数值也保留合法新sample_id；无新sample的UI快照不重置age。到期时`value:null,status:stale`，上次值转`last_observation`并带原时刻。明确invalid/disconnected事件先撤旧值，不能“先过滤无效再找有效”。epoch/binding模式变更不跨历史续用。

API不暴露原SSH、完整binding、私有路径、授权文本、prompt/输出；ref采用当前公开run别名或可审计的不敏感ID。

## 2. 只读HTTP路由

| 路由 | 内容/约束 |
|---|---|
| `GET /` | 编译后的静态页面，运行离线可用 |
| `GET /api/v1/bootstrap` | schema版本、服务epoch/时钟、当前source_mode、可用字段、profile、当前run、功能能力；不读设备/模型列表 |
| `GET /api/v1/snapshot` | 原子快照的K/C/D/E/B摘要；同snapshot_seq |
| `GET /api/v1/stream` | SSE snapshot/quality/event/run_changed/resync/heartbeat；每连接一个有界队列 |
| `GET /api/v1/series?ids=...&from=...&to=...&max_points=...` | 仅当前会话/最近60分钟，时间范围有上限；每条series自带单位/抽样/缺口 |
| `GET /api/v1/model` | model/spec身份、phase、Tf/Ts/E、真实依赖图及provider状态 |
| `GET /api/v1/predictions?horizon_s=45&from=...&to=...` | 当前会话已发/待到期/已匹配/缺标签，符合条件的汇总；不从未来答案重算 |
| `GET /api/v1/events?after=...&limit=...` | 按事件ID分页，带首次/末次/次数；来源明确 |
| `GET /api/v1/metrics` | allowlist的已接字段，搜索/分组/分页，不返回原敏感JSON |
| `GET /healthz` | Web进程状态；200不等同设备温度正常或模型通过 |
| `POST /api/v1/session`、`DELETE /api/v1/session` | 仅LAN只读登录/退出，不含任何设备动作 |

其他写操作返回405；不存在通用proxy、shell、start-test、set-pwm、train、upload-config接口。没有后台外部遥测/分析请求。

## 3. 服务与时间信封

快照外层：`schema_version, snapshot_seq, service_epoch, run_id, source_epoch, mode(live/waiting/ended/test_replay), server_time_utc, clock_domain_id, run_elapsed_ms, metrics, model, predictions, advisory, context, health, event_cursor`。

同一run中的series统一使用N305生产者单调时刻/明确映射后的elapsed_ms；墙钟仅显示，系统时间跳变产生clock事件，不影响已发45秒的真实长度。Web进程不得假设自己的启动原点等于生产者原点；同机boot与clock定义要核对。跨主机数据仅使用已存在到达/映射证据，不能直接相减两台monotonic。

从存量`TTO-FIELD-CONSUMABLE-STATE-v1`消费时用**外层clock**的实际生成/输入截止/消费期限；内部保留的`offline_virtual_observer_clock`字面量不是现场时钟证明。UI显示流只派生状态，不覆盖原数据/旧模型。

SSE快照默认最大1Hz；关键invalid/guard/disconnect事件允许立即发质量变更。`id=service_epoch:seq`，断连重连验证Last-Event-ID，已出缓冲则resync全快照；心跳不改任何metric的样本时间。浏览器丢链时更新页面连接状态并冻结实时新鲜标记。慢客户端丢弃过期显示快照、发resync计数，不阻塞生产者。

## 4. 存量输入适配与单实例

标准新增本地发布面为一个有限只读描述文件+Unix socket或等价有界消息通道；选择已有发布机制优先，不能两种都做成维护面。生产者钩子仅复制公共字段入有界队列，不在collector回调里HTTP/SSE写网络。

follow读取生产者manifest/epoch/消息，0设备读取。observe由指定主机程序获取与现有采集一致的排他锁，复用原只读collector、quality、I-02、observer；0 Requester，不读推理API、不启动CPU旁录。现有采集运行时observe只能退出采集职责或等待，不接管、重启、复制轮询。锁的实际路径/机制在本次实现基线报告登记，不能只写进程数常量当验证。

无统一旧入口锁支持时，先完成follow，并用离线候选补最小共享锁/发布钩子；部署前不允许盲目同时启动两种采集。source_mode是本机安装配置，不由网页动态切换。

## 5. 热模型节点与phase

phase原值与用户文案一一对应：uninitialized=等待模型初始化；provisional=初始化参考；tracking=状态跟踪中；degraded=部分输入缺失，条件估计；unavailable=当前无法估计。跟踪中不是准确率。

`model.nodes[]`携带node_id、role、metric_id/state_path、status、description；`edges[]`携带from/to、relation(power_input/measurement_correction/coupling/cooling_input/prediction_input/reference_mapping)、animate_allowed。前端只绘制服务端实际模型定义的依赖；RPM不接入G2热方程。

Tf/Ts/E复用被冻结估计器的结果；若当前数据模式只有raw无状态，可在**同一个观察拥有者**内执行已验证observer而不新增collector。不能在每浏览器各做一遍。内部不确定性原字段可展开，不渲染0.78之类主观分数。状态不同步/不可消费时允许展示“上次估计”，但不用于当前预测。

## 6. 新增G2-HOLD实时预测发布

若生产者已发同model/spec/scenario的合法预测，直接消费；否则由后端唯一prediction provider在新有效TJ/状态起点最多1Hz计算。必须复用已有冻结G2传播实现或其等价独立已验证函数，不重新拟合。

基于本项目已有比较合同：动态θ固定；预测快温度起点锚定当前有效TJ，慢态Ts/E取当时已到达的因果状态；保持当时可用的两rail和PWM情景，使用真实秒长精确/稳定离散传播。是否采用条件保持PWM必须遵守当前observer合同并随预测明确列出，不能在UI侧擅自将过期PWM改有效。

若实际最新比较代码的锚定/初始化规则与此不同，先在baseline.md具体指出，以已接受合同校对实现；不默认把Tf与实测TJ互换。预测产生时间为真实完成时刻，原点是输入截止。公开支持15/45/90秒；不额外做5分钟、新θ、CPU活动增强、自动HOLD/RELAX挑优。

预测记录不可原地改值。每条带`origin_elapsed_ms, issued_elapsed_ms, target_elapsed_ms, horizon_s, value_C, model_id, spec_id, scenario, input_cutoff, assumption_codes, phase_at_origin, evidence_mode=issued_online`。开发回放样例用`test_replay`，不能显示LIVE。

## 7. 未来标签和当前观察误差

本次核对的冻结analysis-spec规定：同source epoch，目标时刻之后（含目标）的第一条有效accepted TJ，延后最多2秒。以此实现并在adapter-baseline.md记录源函数/版本；若最新已接受版本有明确变更，先报告差异再对齐，不能静默借旧生产Ridge另一套容差。成熟匹配只使用新到达的真实有效TJ和同run身份。前端的最近点悬停与科学标签匹配不是同一逻辑。

`error_C=forecast_C-observed_C`，`underprediction_C=max(observed_C-forecast_C,0)`。对比表按horizon、model/spec、scenario、run/epoch分组，MAE/P95及count用同一matched集合。保留issued_count、due_count、matched_count、missing_label_count、unmatched_future_count；未到期不进误差分母。

观察窗口跨run/模型切换停止合并。即使模型后续失效，也不能改写已经发布的预测；随到期答案追加质量层和失效/恢复备注，不能因为预测错就删除。没有匹配标签不得用后续任意最近点填补。

## 8. 观察建议provider

公开`advisory`对象：`status, provider_id, provider_version, value_percent, basis, issued/expiry, input_refs, model_ref, curve_ref, scope_note, unavailable_reason, device_write_permitted=false`。

优先真实已定义provider；否则CURVE-REFERENCE-v1只消费经过核对的已有本地温度-PWM曲线，使用`T_ref=max(TJ_now, forecast45_hold)`并执行原曲线查表/限值语义。需要曲线与当前控制设备绑定证据。没有则status=not_configured、数值null。target_duty只作为主板目标，不冒充advisory。

保护/控制上下文未知或显式异常时status=withheld；曲线范围外status=out_of_domain，禁止外推。输出过期立即撤数字。PRD允许显示这个实验参考，但不允许接入任何控制写口或声称已验证减少噪音。

平稳需求独立`demand`对象，单位默认`index`，带reference_id/raw_value/shaped_value/validity；provider没接上就是not_available。原离线算法未迁移/未满足参考不能填0或拿历史曲线循环播放。

## 9. 运行上下文

`context`分被观察设备、TTO主机、热模型、任务模型四类身份。实际任务来自同run事件，`task_metadata_available=false`时并发/任务数均null，不默认为0；只有能证实当前0在途才显示0。

客户端槽位capacity与active_requests分别显示；server_running/server_queued只有实际来源才有值。memory保持“使用量”，不能由一个阈值推断驻留模型。普通自主observe没有runner字段仍能给完整C/D与E中的只读状态。

## 10. 部署与资源配置（新配置，不改变旧源设置）

```yaml
web:
  port: 59009
  bind: 127.0.0.1
  access_mode: local
  public_update_hz: 1
  heartbeat_seconds: 5
  history_seconds: 3600
  max_clients: 4
  client_queue_depth: 8
  max_events: 1000
  max_series_points: 2000
source:
  mode: follow
  active_descriptor: null  # 安装时填允许目录内的当前生产者注册入口
  observation_config: null # observe才填，私有本地配置不返回浏览器
model:
  provider: frozen_g2_hold
  horizons_s: [15, 45, 90]
  model_manifest: null
advisory:
  provider: null           # 接口和不可用状态必做，不能填假曲线
  curve_manifest: null
```

生产配置缺项：Web仍启动，只有对应功能不可用；不能套演示host/model/curve。常驻记录的磁盘上限、rotate策略在实现中固定并测试，不改旧原始run。安装只增Web候选和服务，不升级Conda base或替换CPU专项正在验证的安装。

## 11. 非目标

没有设备发现、动态修改WS间隔、jtop启动、CPU高频读取、新传感器、GPU推理请求、训练/在线参数更新、实际控制、全局PID/MPC、录像或历史播放。新增view偏好不扩成服务器配置后台。
