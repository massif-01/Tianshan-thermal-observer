# TTO Web UI 1.0.0rc5 独立审查报告（原交接文档作者 / 前端实现者）

审查日期：2026-10-22。审查对象：`TTO-WebUI-v1-rc5-Claude-Sonnet-5_5-审查交接包.zip`（SHA256 `16028173…45f6af`，与回执一致）。
范围：只读审查；未改原包、测试、合同、候选；未连设备、未部署、未提交。

## 0. 结论

**可接入（后端无需修正即可接入）。** 没有发现阻塞问题。
接入有 8 条条件，全部落在前端侧（见第 5 节），其中 3 条会让我现有的视觉稿需要小补充。后端另有 8 项非阻塞建议（第 2 节）。

判断依据，按重要性：

1. **Tf/Ts/E 确实是吸收该次 TJ 之后的后验状态，没有用预测值或后续传播状态回填。** 我用真实适配器+真实观察器链路（非合成 Tf）喂了 181 s，171 个有效行里“残差 ÷ innovation”全部落在 [0,1]，符号一致，即 Tf 是校正后、未被 TJ 顶替。
2. 相对 rc3 的运行代码改动只有 4 个文件：`__init__.py`（版本）、`server.py`、`state.py`、`web-candidate-files.json`，加 5 个合同文件。其余 59 个文件（含 vendor 观察器、冻结 model/spec、适配器、静态资产）与 rc3 逐字节相同。预测与建议函数未动。
3. 73 项测试我在独立环境复跑通过，并做了 19 项变异测试，16 项被抓住，3 项存活（1 项是真实的测试盲区，2 项是冗余守卫；都不影响运行结论）。
4. 资源数字能复核到“量级”，但口径较窄：它们是 macOS arm64 上默认 10 分钟窗口、120 s 的短测。N305 与长时间稳定性没有任何证据。

### 1.3 开销

我能复核的：

- **新增缓存**：18002 行，tracemalloc 差分 9.3 MiB（我的合成字符串略长），自审为 8.09 MiB，均 <16 MiB。
- **查询成本**（我的 x86 容器，慢于 Apple 芯片）：

| 请求 | 耗时 |
| --- | --- |
| 默认 10 分钟窗口（3000 行 @5 Hz） | 19 ms |
| 1 小时 @1 Hz（3600 行，真实源速率） | 24 ms |
| 1 小时 @5 Hz 满载（18002 行） | 85–120 ms |

  自审的“最大 17.18 ms”对应默认 10 分钟窗口（返回 252 行），与我的数字一致，但它没有覆盖整小时窗口。
- **缺口密集最坏情况**：交替“有效/缺口”18002 行，`max_points=2000` 时返回全部 18002 行、约 12 MiB JSON。合同已明示软预算会超额，机制符合设计，只是前端必须限频。

我无法复核的：

- 3.07% CPU、163.9 MiB RSS 来自 `runtime/resources.json`（macOS arm64、一个 Chrome、120 s、`not N305`）。
- RSS 从 155.4 升到 163.9 MiB；最后 60 s 斜率仍约 +1.3 MiB/min（前 30 s 为 +10 MiB/min，在衰减但没有走平）。距 192 MiB 上限余量约 28 MiB，且“未同时填满预测/事件缓存”。**长稳不能由此证明。**
- 批准方案要求的“与封存 rc3 同口径短测”在 rc5 证据里没有 rc3 对照，只有 rc5 单组数字。新增成本只能靠分配差分归因，不能靠总量差。

## 2. 非阻塞建议

每项：文件 / 触发 / 证据 / 影响 / 最小修正。

**N1 缺口屏障分支无测试覆盖。** `state.py:357` `if t<=self.model_gap_t: return`。
触发：先静默过期（缺口行 2.5 s），再断连（检测时刻 4.0 s，缺口行被合并但屏障推到 4.0 s），随后到达一条源时刻 3.0 s、仍在自身 TTL 内的样本。
证据：去掉该行，该样本被写入 3.0 s 的有效行，73 个测试全过；保留该行则被挡住。复现脚本在我的工作目录 `barrier.py`。
影响：屏障被误删或回归时无人发现。
修正：把该场景加为一个测试；并建议再加一个“真实观察器链路下 TJ−Tf 与 innovation 同号且比例在 [0,1]”的测试，以固化“后验”语义（目前单测用手填 Tf，后验性靠未改动的适配器保证）。

**N2 两处冗余守卫。** `model_history_sample` 去重（M13）与 `record_model_history` 内的 `model_expired` 分支（M18）删除后全部测试仍通过：前者被“时间单调”与屏障覆盖，后者被 `refresh()` 末尾的 `expire_model_history` 覆盖。
影响：多一份状态与一条代码路径，无功能收益。
修正：现场验证前不建议动；之后可择一删除或补测试证明其必要。

**N3 联合视图里 TJ 在“模型未就绪”时也是 null。** 冷启动前约 9 个样本（provisional）以及 unavailable 期间，TJ 本身有效，但联合行四列均为 null（`phase_unavailable`）。批准方案 3.5 写的是“可保留该行 TJ 数值”，实现选了全 null。
影响：用联合 TJ 画实测线会在这些时段断开。
修正：合同与接入卡写明；前端实测线用独立 `temperature.tj` 序列（条件 F6）。

**N4 schema 两处宽松。** 联合组里的 `temperature.tj` 行：`kind` 可为 `estimate`（已验证接受），`estimate_stage` 也未被钉成 null（读 schema 所得，未单独验证）；有效点的 `sample_id` 可为 null（已验证接受）。
修正：对 TJ 行补 `kind=observed`、`estimate_stage=null`，有效点 `sample_id` 要求为字符串。

**N5 缺口密集时响应可达 12 MiB。** 触发：来源在有效/无效之间抖动一小时。设计上“绝不丢缺口”，我认同；接入侧限频即可（F2）。可选后端保护：为强制保留索引设上限，或把相邻短缺口合并，但这会改语义，需你决定，现在不建议。

**N6 资源证据口径窄。** 见 1.3。现场前至少需要：N305 上 ≥30–60 分钟浸泡，同时填满预测/事件缓存；与 rc3 同口径对照；整小时窗口请求成本。

**N7 缺口原因文案。** `phase_unavailable` 同时代表“冷启动 provisional”和“unavailable”。前端展示应统一为“模型未就绪”，不要暗示故障。

**N8 偏离批准方案的三点（均已披露，我同意收窄）：** 取消 `arrived_after_gap` 处置属性；取消“合法热切换”测试；`identity.verify()` 不再由 pytest 调用。另有一点未披露但已核对：rc5 证据没有 rc3 同口径资源对照（方案 4 节要求）。

## 5. 前端接入条件（我据此改 rc3 前端）

对照 rc3 `frontend/src/main.ts` 的现状。

- **F1 请求与能力检测。** 一次联合请求，四个 id 始终一起：`ids=temperature.tj,model.Tf_C,model.Ts_C,model.E_C`。用 `bootstrap.series_capabilities.model_state_history` 判断后端是否支持；不支持或空数据显示“暂无模型历史”空态，不造数据。
- **F2 不走 rc3 的增量合并。** `main.ts:181` 用 `[t,sample_id,status]` 做键合并增量，而新响应是“选点结果”，不是可累加日志，且同位置“缺口替换有效行”会让旧有效点残留。模型组改为每次按可见窗口整体替换；刷新节奏降到 ≥5 s 或在窗口变化时触发，不随每秒 SSE 刷整小时窗口。
- **F3 身份与代次。** 响应回来要同时核对 `service_epoch/run_id/source_epoch/model_id/spec_id`、请求代次、窗口/ids、暂停状态。rc3 的 `source` 键只含前三项（`main.ts:177`），需补 model/spec；也不应被旧请求的 `busy`（`main.ts:175`）阻塞新数据组。
- **F4 null 断线、带符号分解。** ECharts 保持 `connectNulls:false`（`main.ts:72` 已是）；堆叠面积按段分开画。Tf<Ts 或 Ts<E 时不能用普通堆叠（负值会堆到相反侧）。**设计需补一个“顺序反转”状态。**
- **F5 统计口径。** rMAE / rP95 / rMax 只在 `sampling==='actual_samples'` 时作为精确值显示；抽样后极值被过表达，均值与分位会偏，应改用 `max_points=5000` 重取，仍抽样则标“近似”。命名一律用“校正后残差”，不称“预测误差”或“拟合精度”，并与预测对照区（成熟预测）分开。**设计里“拟合情况”统计带的文字要改。**
- **F6 实测线用独立序列。** 画实测 TJ 用 `temperature.tj` 原始序列；联合序列里的 TJ 只用来算残差（N3）。
- **F7 阶段与原因展示。** `phase_at_sample=degraded` 需有可见标记；`reason_code` 映射为统一文案（N7）。**设计需补一个 degraded 图例。**
- **F8 资源。** 请求窗口以可见范围为准；不在 2 s 周期里请求整小时；N305 上线前不得认为资源通过。
- **F9 时间轴与暂停。** `t` 是相对本 run 起点的毫秒，与其它序列同轴；暂停只影响显示，恢复时用最新快照与真实有效性；数据组变化立即清空并使在途请求失效。
