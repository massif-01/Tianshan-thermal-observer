## 4. 推荐结构与先后

优先现有aiohttp提供同源静态资源+只读JSON+SSE；前端TypeScript/Vite/ECharts，节点SVG。本地构建后打包静态文件，N305运行无需Node/CDN。已存在等价项目栈则复用，不平行再建设一套。

按下列顺序实际实施：
1. 基线/DTO/source registry，完成直接字段、独立有效期及脱敏。
2. follow发布消费链；observe复用唯一collector/observer的持续只读模式及拥有权，不生成第二轮询器。
3. 原子快照、SSE有界队列/重连/过期；有限历史缓存，不无限写日志。
4. 固定模型预测发布、到期标签匹配、建议provider接口/必要曲线映射；规则按文档，无新阈值搜索。
5. 三大趋势及C/D/E、A/B和字段抽屉；中文状态文案和低动态模式。
6. 安装候选、systemd服务、独立prefix及回退；保护原TTO和CPU专项环境。
7. 针对真实风险的测试、浏览器核查和交付。

不必先交一份新方案再等批准；本次即授权上述实现和本地测试。需要新增无法从已有数据/配置定义的控制策略，才是超出当前任务，不能顺手补成“AI建议”。

## 5. 常驻服务与不影响实验

Web service长期运行是本次新功能，旧研究里“不建常驻服务”不再用来拒绝Web部署候选。**但常驻UI不等于授权常驻推理或重新接管设备。**

follow只读已有注册活动流；observe是明确安装配置后的单一只读观察者，不构造Requester、不查询推理模型列表、不触发CPU SSH旁录。以实际共享锁/拥有权验证单实例，多开网页不多采集。Web退出不停止外部试验；只停止自己创建的observe进程。

源未配置/被其他入口占用时，59009页面仍启动并明确状态，不能静默换成假数据或另扫网段。包装有限数据缓存/日志转动，不沿用高体积实验日志无限写盘。

安装器实际包含自动启用服务的代码，并提供清楚的本机/LAN选择；没有现场安装授权时只在容器/临时prefix/临时unit验证。不能交一个永远raise“只允许预览”的正式serve入口。

## 6. 保留安全与真实含义

业务API无设备/风扇/训练/负载写操作；仅登录会话可POST/DELETE。不得返回secret、header、完整binding、任务prompt/回复或私有路径。LAN必须显式配置访问保护，不能默认匿名对外；不自动更改系统防火墙。

异常、断连、失效、到期、身份切换均真实显示；不把只读建议接到天山OS写API，不对研究模型的deployed/permission字段作偷偷放权。图形动效和绘图插值不能伪造新测量。
