执行顺序
一、先处理 R1 和 R6 的执行边界，再处理 R2/R3 的有效性，最后处理 R4/R5 的时间与过程归属。可以在同一有限收尾版本完成，不拆成新的研究方向。

R1｜隔离 Web 展示异常，原 field 处理保持自己的失败规则。
- 已复现：同一 native accepted TJ 包，仅 memory=null，无 Web hook 的 Pipeline 正常；有 hook 时 adapter 的 .get 抛 AttributeError，被包装成 ValueError，原 collector writer 设置 stop。
- 对合同允许缺失/null 的附加字段作明确的缺失/invalid 映射；不要缺失补 0。
- 新增显示编码/发布必须有独立异常边界。显示失败应撤销自己的有效资格、记录有界且脱敏的错误/gap；不得影响已经正确完成的 quality/observer/原证据/latest 提交。
- 原处理链的真实异常仍保留原有停止行为。禁止用大范围 except: pass 把原安全或数据错误吞掉。
- 只验证 memory=null 的无/有 hook 对照和显示故障隔离即可。探针中的 fan.data=null 在有无 Web 时都失败，是旧行为，排除本轮。

R2｜沿用原生 GPU 质量结果，补齐同源年龄映射。
- 原生 quality.gpu 已计算 NVML base age + telemetry outer age。Web 不得仅用 base age 和 contract_valid 重建更宽松资格。
- 使用原质量结果的 value、reason、age_lower_bound_ms 和 valid_until；同一个 sample 的截止只能缩短，新 invalid 必须撤销。
- 验证 base=2s、outer=4s、TTL=5s 时仍为无效；base=2s、outer=2.5s 时只剩 0.5s，0.6s 后必须过期。
- 顺手给两 rail、CPU、RAM 等同源指标传入实际源龄，避免“几秒前”从 0 重新计算。其源 TTL 不变。
- GPU 利用率不是本版 G2 输入，不改热模型。

R3｜前端同步撤销所有“当前”显示。
- SSE 断流时，指标、模型数值/phase/节点/动效、当前未来参考、当前建议及数据健康文案同步更新。
- 没有新 SSE 快照时，前端仍按后端提供的剩余资格到期；必要时补派生状态的截止字段，不由前端猜 TTL 或重算模型。
- D 的“现在发出的未来参考”不能依赖另一次 HTTP 请求成功才刷新。历史已成熟配对可保留，和当前未来值分开。
- 补真实浏览器中断流、连接未关闭但快照停更后超期两个场景。保留暂停只冻结画面及明确暂停语义。

R4｜事件不能串到另一个 run/epoch。
- 为事件保留所属 run/source_epoch（如需 service 身份也一并明确），API/前端按所属时间轴筛选。
- V1 若只保留当前过程，切换时清理旧过程事件也可以；同步处理事件去重和已选详情。
- Web 全局事件不要凭相同 elapsed_ms 塞进设备过程轴。不要新增历史播放器。
- 验证旧过程 20s 的任务事件，在新过程进行到 30s 时不会画到新过程 20s；同 run 的源 epoch 切换也核对。

R5｜用源事件时间完成首标签结算。
- target=24s，允许首标签源时刻在 [24,26]；源时刻 25s 的首个合格 TJ 因发布延迟于 Web 26.2s 到达，当前代码已在 Web 26.1s 永久记 missing，导致漏配对。
- 缺标签的最终结算应依据已消费的有序源流进度，或等价的可证明规则。页面时钟可以提示等待，但不能抢在合法源事件之前永久封口。
- 保持 +2s 源标签窗、同 run/epoch/model/spec、首条有效样本、丢帧不可比等规则；不要放宽窗口、补最近邻、跨 gap 配对或改写已发布预测值。
- 此问题是合格配对被漏掉，不是已出现错误预测或虚假的 matched。修后同时核对 records 与 summary 分母。

R6｜新增 Web observe 需要恢复与准确终态。
- 真实 collect/observe/server 的短退避反例保留原 10 次尝试：开机暂不可达或累计 10 次连接后断线，来源恢复也不会再连；Web 进程仍运行，状态有时仍写“正在观察”。
- 分开 Web 关闭信号和本轮 collector 停止信号；无论哪个先结束，都在 await 完本轮后读取结果、准确撤销来源状态。
- 仅针对可恢复的临时网络结束，在 Web observe 拥有者层做可取消、有退避的恢复。先收完自己旧 collector，再重新取得原共享锁，创建唯一新 run/epoch。
- 用户 STOP、配置/授权失败、拥有权冲突与临时断网分开；不能自动抢占、kill 他人或在 STOP 后复活。
- 原有限 collect/field 默认行为、每轮连接预算、采样周期、TTL、模型与设备权限不变。follow 仍不拥有外部 producer。
- 验证来源稍晚恢复及累计断线恢复；同时确认停止无复活、锁冲突无第二采集器。测试等待可缩短，报告写清不是现场时长实验。
