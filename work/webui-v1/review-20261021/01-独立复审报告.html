结论

保留软件主体；完成 6 项有限修正后，再进入 N305 安装与现场监看验证。

本轮独立核验确认这是一份包含真实运行链、冻结模型、前端资源和离线安装器的候选。主要产品结构已经落实，C／D／E 没有被缩减成静态占位。需要修正的是展示旁路的异常隔离、资格撤销、时间与过程归属，以及持续来源恢复。应优先处理 R1，它会影响原采集链。

本报告没有修改候选代码，没有连接设备，没有启动真实推理、训练或现场服务，也没有推送/创建 PR。问题均来自本轮新增路径，有可核对的反例。原有历史缺陷和单纯美学偏好未纳入本轮。

R1 · 可选展示字段的异常会传回原实验链

用户影响：原本可以继续的采集/实验，因为一个附加展示字段而停止。

已确认的反例

同一条其余字段有效的记录，只将 memory 设为 null。native TJ 仍 accepted；不启用 Web hook 时回调完成，计数 29→30；启用 hook 后抛 field_projection_failed:AttributeError。原 writer 捕获 ValueError 后设置 stop。

最小修正

对允许缺失的字段明确归一为不可用，并把新增编码/发布从原质量、模型与证据提交的失败边界中隔离。显示故障应撤销显示资格并留下有界错误，原处理链继续按原规则运行。

判断边界：已直接复现到 field 回调异常；采集停止由真实 writer 的捕获分支得到。没有让真实设备或实验中断。fan.data=null 在有无 Web 时都失败，作为旧行为排除。

源码位置：adapter.py 117–120；vendor/tto_field/runtime.py 114–126；vendor/tto/collector.py 216–233
本包证据：optional-source-fields-root-py310.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

R2 · GPU 利用率漏算外层源龄，旧数据重新被视为有效

用户影响：GPU 当前指标及数据健康状态可能继续显示原生质量层已经撤销的旧数值。

已确认的反例

NVML 自身年龄 2s、外层源龄 4s、期限 5s：原生结果为 gpu_effective_stale/value=null；Web 却显示 value=0、valid，并给近 3s 剩余资格。另一个只剩 0.5s 的样本，0.6s 后 Web 仍显示 valid、剩余 2.4s。

最小修正

直接复用 quality.gpu 的有效值、原因、年龄和截止；保留同 sample 期限只能缩短、明确 invalid 立即撤销。两 rail、CPU、RAM 同时传入已存在的源龄，修正年龄显示从 0 重算。

判断边界：GPU 利用率不进入本版 G2 方程。该发现不能解释成热模型错误或风扇被错误控制。

源码位置：adapter.py 125–137；vendor/tto/profiles.py 148–151；platform_quality.py 101–114
本包证据：gpu-age-root-py310.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

R3 · 断流和本地到期未同步撤销全部当前显示

用户影响：指标已经撤值，D 的“现在发出的未来参考”仍可显示旧数字；快照停更时 C 也可继续表示有效与流动。

已确认的反例

执行交付 TypeScript 的真实函数：触发 SSE.onerror 后内部 predictions 已空、C 的 Tf 为 null、顶栏写“当前值已撤下”，但 D 仍显示三个 44.3℃。保留原快照的全部期限，推进本地时钟到 10s 后，TJ 已撤值，C 仍为 tracking/Tf=44.30004、8 条关系仍流动，D 仍保留数字。

最小修正

统一“当前显示”的撤销入口；断流/到期同步更新指标、模型数值与节点/动效、当前未来参考、建议及健康文案。必要时由后端提供派生状态的剩余有效期。历史已成熟配对可以保留。

判断边界：探针使用 Node 24 的 TypeScript 擦除及 DOM/ECharts I/O 替身，不是独立真实浏览器验收。复现没有改动原候选，也没有改原快照的 TTL。

源码位置：frontend/src/main.ts 123–124、172、183
本包证据：frontend-probe-results.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

R4 · 没有过程身份的旧事件会画入新过程时间轴

用户影响：用户可能把上一轮任务或告警当作本轮温度/PWM 变化的原因，破坏事件带的解释价值。

已确认的反例

用实际 State 在 old-run-A 的 20s 写入任务事件，再切到已运行 30s 的 new-run-B。事件没有 run_id/source_epoch，仍留在结果中；再交给实际前端 renderEventTimeline，旧事件被画到新过程的 20s。

最小修正

事件带上所属过程身份并在正确轴上筛选；V1 只保留当前过程时，也可明确清理旧事件。同步处理去重、已选详情与 Web 全局事件的归属。

判断边界：不要求新增历史播放器。该问题与曲线缓存清理是否已正确是两回事：曲线已重置，事件仍可串入。

源码位置：state.py 71–78、93–97；server.py 108–113；frontend/src/main.ts 147–151、169
本包证据：events-probe-results.json / frontend-probe-results.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

R5 · 预测首标签可能被 Web 当前时钟提前判成永久缺失

用户影响：合格配对被遗漏、缺标签数偏高，参与误差统计的样本受本地发布延迟影响。

已确认的反例

真实计算出的预测 origin=9s、horizon=15s，target=24s。首个合格 TJ 的源时刻为 25s，属于 [24,26] 窗口；包延迟 1.2s，于 Web 26.2s 到达。Web 定时器已在 26.1s 永久记为 missing_label，之后不再匹配。该序列无断线、无 gap、同 epoch，包仍有有效期。

最小修正

以已消费的有序源流进度或等价可证明规则完成缺标签结算。Web 时钟可以提示等待，但不能提前永久封口。保持 +2s 源窗口、首个有效样本及跨 gap 不可比的规则。

判断边界：这是保守漏统计，不是生成了错误预测或虚假的 matched 误差。不延长标签窗口，不重训模型。

源码位置：state.py 115–120、232–233；接口合同 §7
本包证据：label-deadline-root-py310.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

R6 · 持续 observe 用完重连预算后不会恢复，终态也可能不准确

用户影响：开机时来源启动较慢，或长期运行中累计断线后，网页还在但监看停止；来源恢复也不再连接，部分序列仍显示“正在观察”。

已确认的反例

使用真实 collect/observe/server，保留原 10 次尝试预算，仅用惰性设备传输/锁并缩短测试退避。开机不可达、以及 10 次成功连接后各自断开两种场景中，来源恢复后 connect_calls 都停在 10，source_run 活跃任务为 0，Web healthz 仍为 200。后一场景 source_connected 还为 true。

最小修正

在新增 Web observe 层分开服务停止与单轮采集停止信号；始终读取已完成任务的终态。对可恢复网络结束做可取消的退避恢复，收完自己的旧实例后重取原共享锁、建立唯一新 run。

判断边界：没有执行 systemd 或现场联网。Web 不退出所以不会因该原因触发 Restart=on-failure，是代码推论。后端字段 TTL 仍会撤值；不能说旧数值永远有效。原有限实验的退出规则无需改变。

源码位置：vendor/tto/collector.py 241–293；source.py 124–139；server.py 196–206；tools/install.py 的 Restart=on-failure
本包证据：observe_recovery_result.json；对应探针在 probes/，源码摘录在 evidence/source-excerpts.txt。

修正顺序与放行条件

  1. 先处理 R1/R6：显示故障与原执行链隔离；持续观察能准确结束并在临时网络恢复后继续，停止和拥有权边界保持清楚。
  2. 再处理 R2/R3：后端不延长原资格；前端所有当前展示一起撤销。
  3. 处理 R4/R5：事件属于正确过程；首标签结算沿用源时间轴。
  4. 最终候选有限复验：原测试、这 6 项反例对应的必要断言、最终 wheel 离线安装/身份/短启动，以及 R3/R4 的实际浏览器场景。测试夹具的 UID 假设可局部修正，无需改变生产权限逻辑。
  5. 交回新候选：版本、身份、patch、报告和操作卡同步更新，保留旧负结果及构建轮次。未触及或未暴露资源风险时，不要求再做多轮长时间本机测试。

上述有限复审通过后，下一阶段才是经用户安排的 N305 安装与只读监看：实际服务启动/开机恢复、已有采集时 follow、无其他拥有者时 observe、一次有针对性的断源恢复与资源检查。该阶段不自动包含真实推理负载、CPU 补测、重新训练或天山 OS 控制修改。

本轮明确没有要求补齐的数字

没有可靠测速证据时 RPM 保持“未确认”；没有核实曲线时 PWM 建议保持不可用；没有当前需求 provider/参考时平稳需求保持“本轮未计算”；没有 runner 时任务/服务端状态保持未知；不增加结构测温。它们符合原 PRD 的缺项分支，不能为让页面显得完整而编造数值。

执行顺序
一、先处理 R1 和 R6 的执行边界，再处理 R2/R3 的有效性，最后处理 R4/R5 的时间与过程归属。可以在同一有限收尾版本完成，不拆成新的研究方向。

R1｜隔离 Web 展示异常，原 field 处理保持自己的失败规则。
- 已复现：同一 native accepted TJ 包，仅 memory=null，无 Web hook 的 Pipeline 正常；有 hook 时 adapter 的 .get 抛 AttributeError，被包装成 ValueError，原 collector writer 设置 stop。
- 对合同允许缺失/null 的附加字段作明确的缺失/invalid 映射；不要缺失补 0。
- 新增显示编码/发布必须有独立异常边界。显示失败应撤销自己的有效资格、记录有界且脱敏的错误/gap；不得影响已经正确完成的 quality/observer/原证据/latest 提交。
- 原处理链的真实异常仍保留原有停止行为。禁止用大范围 except: pass 把原安全或数据错误吞掉。
- 只验证 memory=null 的无/有 hook 对照和显示故障隔离即可。探针中的 fan.data=null 在有无 Web 时都失败，是旧行为，排除本轮。

R2｜沿用原生 GPU 质量结果，补齐同源年龄映射。
- 原生 quality.gpu 已计算 NVML base age + telemetry outer age。Web 不得仅用 base age 和 contract_valid 重建更宽松资格。
- 使用原质量结果的 value、reason、age_lower_bound_ms 和 valid_until；同一个 sample 的截止只能缩短，新 invalid 必须撤销。
- 验证 base=2s、outer=4s、TTL=5s 时仍为无效；base=2s、outer=2.5s 时只剩 0.5s，0.6s 后必须过期。
- 顺手给两 rail、CPU、RAM 等同源指标传入实际源龄，避免“几秒前”从 0 重新计算。其源 TTL 不变。
- GPU 利用率不是本版 G2 输入，不改热模型。

R3｜前端同步撤销所有“当前”显示。
- SSE 断流时，指标、模型数值/phase/节点/动效、当前未来参考、当前建议及数据健康文案同步更新。
- 没有新 SSE 快照时，前端仍按后端提供的剩余资格到期；必要时补派生状态的截止字段，不由前端猜 TTL 或重算模型。
- D 的“现在发出的未来参考”不能依赖另一次 HTTP 请求成功才刷新。历史已成熟配对可保留，和当前未来值分开。
- 补真实浏览器中断流、连接未关闭但快照停更后超期两个场景。保留暂停只冻结画面及明确暂停语义。

R4｜事件不能串到另一个 run/epoch。
- 为事件保留所属 run/source_epoch（如需 service 身份也一并明确），API/前端按所属时间轴筛选。
- V1 若只保留当前过程，切换时清理旧过程事件也可以；同步处理事件去重和已选详情。
- Web 全局事件不要凭相同 elapsed_ms 塞进设备过程轴。不要新增历史播放器。
- 验证旧过程 20s 的任务事件，在新过程进行到 30s 时不会画到新过程 20s；同 run 的源 epoch 切换也核对。

R5｜用源事件时间完成首标签结算。
- target=24s，允许首标签源时刻在 [24,26]；源时刻 25s 的首个合格 TJ 因发布延迟于 Web 26.2s 到达，当前代码已在 Web 26.1s 永久记 missing，导致漏配对。
- 缺标签的最终结算应依据已消费的有序源流进度，或等价的可证明规则。页面时钟可以提示等待，但不能抢在合法源事件之前永久封口。
- 保持 +2s 源标签窗、同 run/epoch/model/spec、首条有效样本、丢帧不可比等规则；不要放宽窗口、补最近邻、跨 gap 配对或改写已发布预测值。
- 此问题是合格配对被漏掉，不是已出现错误预测或虚假的 matched。修后同时核对 records 与 summary 分母。

R6｜新增 Web observe 需要恢复与准确终态。
- 真实 collect/observe/server 的短退避反例保留原 10 次尝试：开机暂不可达或累计 10 次连接后断线，来源恢复也不会再连；Web 进程仍运行，状态有时仍写“正在观察”。
- 分开 Web 关闭信号和本轮 collector 停止信号；无论哪个先结束，都在 await 完本轮后读取结果、准确撤销来源状态。
- 仅针对可恢复的临时网络结束，在 Web observe 拥有者层做可取消、有退避的恢复。先收完自己旧 collector，再重新取得原共享锁，创建唯一新 run/epoch。
- 用户 STOP、配置/授权失败、拥有权冲突与临时断网分开；不能自动抢占、kill 他人或在 STOP 后复活。
- 原有限 collect/field 默认行为、每轮连接预算、采样周期、TTL、模型与设备权限不变。follow 仍不拥有外部 producer。
- 验证来源稍晚恢复及累计断线恢复；同时确认停止无复活、锁冲突无第二采集器。测试等待可缩短，报告写清不是现场时长实验。
